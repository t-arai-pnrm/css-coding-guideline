付録D レビューのチェックリスト

この付録は、CSSをレビューするときの確認項目をまとめたチェックリストです。項目は、「19-2 レビューの進め方」で定めた確認の順番に並べています。上にあるものほど、プロジェクト全体への影響が大きい項目です。レビューの前に目を通し、関係する項目だけを拾って使ってください。

各項目には、関係するルールのIDを添えています。指摘するときは、IDを引用すると、理由と詳しい説明をすぐに示せます。項目に当てはまらない記述でも、意図が読み取れないものは誤りと決めつけずに Q で質問します。反対に、プロジェクトで合意していない規約を求める指摘は IMO にとどめます。

インデントやプロパティの並び順は、この一覧に入れていません。整形はStylelintで自動化しているので、レビューで指摘するのは、自動化が機能していないときだけです。Stylelintで検出できるルールは、各ページのガイドラインの「自動チェック」の欄で分かります。このチェックリストでは、Stylelintが通ったことを前提に、人が確かめる項目を中心に挙げています。

コードを読む確認とは別に、ブラウザで条件を再現して表示と操作を確かめる手順は「19-3 表示と操作を確かめる」に、崩れの原因を開発者ツールで調べる手順は「19-4 表示の崩れを開発者ツールで調べる」にまとめています。

レビューの前に

  • Stylelintを実行し、エラーが残っていないか（run-stylelint-before-done）
  • エラーや警告を消すためだけに、ルールを無効にしていないか（no-disabling-to-silence）
  • ルールを無効にする場合は、1行と1つのルールに絞り、理由を書いているか（disable-one-line-with-reason）
  • 警告を放置していないか（resolve-warnings）
  • AIが生成したCSSを、lintとレビューの両方で確かめたか（verify-ai-output）

指摘の書き方

  • 指摘に、理由と解決策をセットで書いているか（review-reason-and-solution）
  • MUST、IMO、Q のラベルで深刻度を分けているか（review-severity-labels）
  • 合意のない好みの指摘を、IMO にとどめているか（review-preferences-as-imo）
  • 意図が読み取れない記述を、Q で質問しているか（review-ask-unclear-intent）
  • 本書のルールに関わる指摘で、ルールのIDを添えているか（cite-rule-ids）

MUST は、仕様やコーディング規約に反するもの、バグが起きているもの、将来深刻な問題になりそうなもの、使いやすさやアクセシビリティを損なうものに付けます。レビューを通したコードには、レビュアーも責任を負います。承認するときは、自分が書いたコードと同じ基準で見ます。

1. 仕様とプロジェクトの規約

プロジェクトでコーディングガイドラインが定められている場合は、それを守れているかを最優先で確かめます。本書の規約を採用しているプロジェクトなら、次の項目が対象です。

命名とスコープ

  • コンポーネントのルートに scoped クラスを付け、スタイルを @scope (.scoped.<名前>) to (.scoped) の中に書いているか（scoped-class-on-root（9-3、巻2）、scope-with-donut（4-4、巻1））
  • 子要素は ._、ユーティリティは .- で始め、コンポジションとパターンは接頭辞なしにしているか（child-class-underscore（9-1、巻2）、utility-class-hyphen（9-1、巻2）、composition-class-plain（9-1、巻2））
  • 名前が、見た目ではなく役割を表しているか。コンポジションは配置の名前、パターンは役割の名前にしているか（name-by-role（9-1、巻2））
  • container や button のような語を、別の意味の名前に使っていないか（no-redefining-web-terms（9-1、巻2））
  • wrapper や module のように、責務を表さない名前を使っていないか（no-vague-names（9-1、巻2））
  • @keyframes、グリッドのエリア、アンカー、コンテナの名前を -- で始めているか（dashed-ident-names（9-1、巻2）、container-name-dashed-ident（13-3、巻2））

カスケードとセレクタ

  • IDセレクタでスタイルを指定していないか（no-id-selector（4-2、巻1））
  • .a.a や祖先のクラスを足すような、詳細度を上げるためだけのセレクタがないか（no-specificity-hacks（4-2、巻1））
  • :hover や [aria-expanded="true"] のような状態のセレクタを、:where() で包んでいないか。まとめるときは :is() を使っているか（is-for-state-selectors（5-2、巻1））
  • 詳細度や読み込み順の競争に勝つための !important がないか（no-important-for-specificity（4-1、巻1））
  • レイヤーを使うプロジェクトで、@layer の外にスタイルを書いていないか（no-unlayered-styles（4-3、巻1））
  • ページ固有のセクションを pages に、使い回すコンポーネントを components に書いているか（layer-by-role（4-3、巻1））
  • CMSのように外部のCSSと共存する環境で、@layer を使っていないか（no-layers-with-unlayered-css（4-3、巻1））
  • :has() の直前に起点を書き、引数を > や + で絞っているか（no-unanchored-has（5-3、巻1）、has-narrow-anchor（5-3、巻1））
  • 対応が分かれる擬似クラスを、:is() か :where() の中でほかのセレクタと並べているか（forgiving-list-for-partial-support（5-1、巻1））

ネストと記法

  • セレクタのネストが2層までで、ネストしたセレクタが & で始まっているか（nesting-depth-one（9-4、巻2）、nested-selector-ampersand（9-4、巻2））
  • 要素自身の擬似クラス・擬似要素・属性の状態を、[popover]:popover-open のように主語へ連結せず、&:popover-open とネストしているか（nest-own-states（9-4、巻2））
  • &__title のように、& に文字をつなげていないか（no-nesting-concatenation（9-4、巻2））
  • @media、@container、@supports を、各セレクタの中に書いているか（conditions-inside-rules（9-4、巻2））
  • 直下の子へのネストに、親のレイアウトで意味が決まる宣言だけを書いているか（nest-child-placement-only（9-5、巻2））
  • 詳細度の違うセレクタリストの中で、セレクタをネストしていないか（no-nesting-under-selector-list（9-5、巻2））
  • 寸法、余白、位置を論理プロパティで書いているか（logical-properties（9-8、巻2））
  • display を2値構文で、変形を translate などの個別のプロパティで書いているか（display-two-value-syntax（9-7、巻2）、individual-transform-properties（9-7、巻2））
  • 色の関数をスペース区切りで書き、rgba() を使っていないか（color-space-separated（9-7、巻2）、no-rgba-hsla（9-7、巻2））
  • 必要のないベンダープレフィックスがないか（no-vendor-prefix（9-7、巻2））

2. デザイントークン

  • トークンとして定義されている値を、数値や色で直接書いていないか（use-defined-tokens（10-4、巻2））
  • z-indexを数値ではなくトークンで指定しているか（z-index-tokens-only（10-2、巻2））
  • トランジションの再生時間とイージングに、トークンを使っているか（transition-longhand-with-tokens）
  • 新しいトークンが --<分類>--<名前> の形になっているか（token-naming-category-first（10-4、巻2））
  • 1回しか使わない値や、特定のコンポーネント専用の値をトークンにしていないか（no-single-use-token（10-4、巻2））
  • 派生させた色のために、トークンやRGBの値を別に用意していないか（derive-colors-from-base）

余白のトークンは、レスポンシブの環境では % や cqi が絡み、二者択一で片付かないことが多いので、使っていなくてもあまり細かく指摘しません。

3. 対象のブラウザ

  • 新しい機能が、対象のSafari（現行から2つ前のメジャーバージョンの最終版）で使えるか（browser-support-target（1-2、巻1）、check-safari-support-first（1-2、巻1））
  • 一部のブラウザしか対応していない機能を、未対応の環境でも内容を読めて操作できる範囲で使っているか（progressive-enhancement-if-harmless（1-2、巻1））
  • アンカーポジショニングのような未対応の環境があるレイアウトの機能を、レイアウトの要にしていないか（no-unsupported-layout-features（1-2、巻1））
  • 新しい機能に合わせて既存の宣言も変える場合に、@supports で分岐しているか（supports-for-dependent-declarations（1-2、巻1））
  • 対象のすべてが対応した機能のフォールバックが、残っていないか（remove-unneeded-fallbacks（1-2、巻1））
  • JavaScriptで表示を切り替える前提のスタイルを、@media (scripting: enabled) の中に書いているか（scripting-for-js-dependent-styles（1-2、巻1））
  • ブロックレイアウトの要素に justify-self を指定していないか（no-justify-self-in-block-layout（1-2、巻1））
  • 単位のついた値での割り算を、Firefoxの安定版で宣言が無効になっても内容を読める場面で使っているか（typed-arithmetic-to-unitless（6-4、巻1））
  • Chromeだけでなく、Safari（iOSを含む）とFirefoxでも表示を確かめたか（no-chrome-only-check（1-2、巻1））

4. 不要な記述と副作用のある上書き

  • どの宣言も、なぜ必要かを説明できるか（explainable-declarations（2-3、巻1））
  • 何にでも width: 100% や height: 100% を指定していないか（no-redundant-width-100（2-3、巻1）、stretch-over-height-100（7-4、巻1））
  • 幅いっぱいに広げる指定が要る要素に、100% ではなく -webkit-fill-available と stretch をこの順に書いているか（stretch-over-width-100（7-4、巻1））
  • 初期値、デフォルトスタイル、リセットやベーススタイルで決まっている値を、指定し直していないか（no-redundant-defaults（2-3、巻1））
  • 中央寄せに margin: 0 auto ではなく margin-inline: auto を使っているか（margin-inline-auto-centering（7-3、巻1））
  • 一部だけを変えるのに、background のような影響範囲の広いショートハンドを使っていないか（longhand-for-partial-change（2-3、巻1））
  • kiso.cssで0になっているマージンを、margin: 0 や margin-block: 8px 0 で打ち消していないか。片側だけ付けるならロングハンドで書いているか（no-redundant-defaults（2-3、巻1）、longhand-for-partial-change（2-3、巻1））
  • 値を戻すときに、戻したい先に合うキーワード（revert など）を選んでいるか（explicit-rollback-keyword（4-1、巻1））
  • 継承されるプロパティを、子要素ごとに指定し直していないか（inherit-from-root（4-1、巻1））

5. グローバルのCSS

リセットやベーススタイルの変更は、すべてのページに影響します。変更があったときは、とくに丁寧に確かめます。

  • ベーススタイルを base レイヤーに素のセレクタで書いているか。レイヤーを使えない環境では、セレクタを :where() で包み、詳細度を0にしているか（where-for-base-selectors（4-2、巻1）、no-heavy-specificity-in-global（8-3、巻2））
  • 要素全体に display や position のようなレイアウトのプロパティを指定していないか（no-layout-properties-in-base（8-3、巻2））
  • * { margin: 0; padding: 0; } や input { appearance: none; } のような、機能を一律に消すリセットがないか（reset-no-destructive-reset（8-1、巻2））
  • outline: none でフォーカスリングを消していないか（no-outline-none（8-3、巻2））
  • フォーカスリングを box-shadow だけで描いていないか（focus-ring-not-box-shadow-only（8-2、巻2））
  • リストのマーカーを list-style: none ではなく list-style-type: "" で消しているか（list-style-type-empty-string（8-3、巻2））
  • ベースの line-height が1.5以上で、line-height: 1 がないか（base-line-height-min、no-line-height-one）
  • scroll-behavior: smooth を無条件に指定していないか（no-global-smooth-scroll（8-2、巻2））
  • ダークモードに対応しないのに color-scheme: light dark を指定していないか（no-color-scheme-without-dark-mode（8-3、巻2））

6. 内容の変化への耐性

テキストが2倍の長さになったら、画像がなかったら、要素の数が変わったら、と考えながら見ます。

  • 長い見出し、画像のない記事、要素の数が違う一覧で、表示を確かめたか（design-for-content-changes（11-3、巻2））
  • 幅を固定値で決めず、max-inline-size で上限を決めているか（max-inline-size-over-fixed-width（13-1、巻2））
  • 高さを block-size で固定せず、min-block-size や aspect-ratio で決めているか（min-block-size-over-fixed-height（11-3、巻2））
  • 縦の margin を、* + * で選んだ後ろの要素の margin-block-start に付けているか（block-margin-with-sibling-combinator（11-2、巻2））
  • minmax() や min-inline-size の固定の最小値を、min(100%, …) で包んでいるか（minmax-min-capped-at-100-percent（11-3、巻2））
  • 列を minmax(0, 1fr) ではなく 1fr で分けているか（fr-without-minmax-zero（11-3、巻2））
  • 要素の数が変わるFlexboxに flex-wrap: wrap を指定しているか（flex-wrap-for-variable-items（11-3、巻2））
  • 列数を子要素の数ではなく、auto-fit やコンテナサイズクエリで切り替えているか（quantity-query-for-count-conditions（5-5、巻1））
  • 理由のない white-space: nowrap がないか（no-nowrap-without-reason（11-3、巻2））
  • はみ出しを切り取るのに、hidden ではなく clip を使っているか（overflow-clip-over-hidden（11-4、巻2））
  • 横スクロールを隠す前に、はみ出している要素を特定して直したか（find-overflow-source-first（11-4、巻2））
  • 画像の上の文字に、画像が表示されなくても読める背景色があるか（text-on-image-fallback-background）
  • ブラウザの文字サイズの設定を大きくして、表示を確かめたか（verify-with-text-scaling（6-1、巻1））

7. コンポーネントの境界

  • 見た目が似ているだけのものを、1つのコンポーネントにまとめていないか（component-split-by-role（10-1、巻2）、rule-of-three（2-3、巻1））
  • コンポーネントごとにCSSのファイルを分け、複数のコンポーネントのCSSを1つのファイルに混ぜていないか（one-component-per-file（10-2、巻2））
  • コンポーネントのルートに、margin や grid-area のような外部関連型のレイアウトを指定していないか（no-external-layout-on-root（10-2、巻2））
  • 子のコンポーネントの配置と外側の余白を、親の gap やOuterで決めているか（parent-owns-child-placement（10-2、巻2））
  • ほかのコンポーネントのルートや内部の要素を、セレクタで選んで上書きしていないか（no-other-component-internals（10-2、巻2））
  • パターンに、重ねるコンポーネントが指定するプロパティを書いていないか。コンポーネントの側で変える値を公開プロパティで受け取っているか（pattern-leaves-component-properties（10-3、巻2））
  • コンポーネントの中の要素をタイプセレクタで選び、子クラスは同じ種類の要素を役割で区別するときと、div と span に役割を示すときだけ付けているか。a:hover のような擬似クラス付きのタイプセレクタで、子クラスのスタイルを打ち消していないか（type-selector-in-scope（10-2、巻2））
  • 外から変えてよい値を --<コンポーネント>--<プロパティ> の公開プロパティにし、内部で使う値を --_ で始めているか（public-property-naming（10-5、巻2）、internal-property-prefix（10-5、巻2））
  • 公開プロパティを自分で宣言せず、内部プロパティで受けてフォールバックにデフォルト値を書いているか（receive-public-property-with-fallback（10-5、巻2））
  • ルートには絶対的なz-indexだけを、内部には相対的なz-indexだけを指定しているか（z-index-absolute-root-relative-inside（10-2、巻2））
  • 内部で相対的なz-indexを使うコンポーネントのルートに、isolation: isolate があるか（isolation-for-relative-z-index（10-2、巻2））

8. レスポンシブ

  • 「静的 → イントリンシック → コンテナサイズクエリ → メディアクエリ」の順に検討し、不要なクエリを書いていないか（responsive-escalation-order（13-1、巻2））
  • タグやアイコンのような固定サイズの要素を、レスポンシブにしていないか（no-responsive-for-static-elements（13-1、巻2））
  • コンテナに名前を付け、条件を inline-size で書いているか（container-name-required（13-3、巻2）、container-query-inline-size（13-3、巻2））
  • cqi を、名前付きのコンテナがあると言い切れる要素でだけ使っているか（cqi-needs-named-container（13-4、巻2））
  • クエリの条件を範囲構文で書き、ブレイクポイントをremの式にしているか（query-range-syntax（13-5、巻2）、breakpoint-in-rem（13-2、巻2））
  • ブレイクポイントを、デバイスの幅ではなくレイアウトが崩れる幅から決めているか（breakpoint-from-content（13-2、巻2））
  • sp や pc のようなデバイスの名前を使っていないか（no-device-names（13-2、巻2））
  • メディアクエリの条件と、コンテナクエリのサイズの条件の中で var() を使っていないか（no-var-in-query（13-2、巻2））
  • vw や vh を使っていないか（no-vw-vh（6-2、巻1））

9. コメント

  • コードの途中のコメントが、「なぜ」だけを書いているか（comments-why-only（9-9、巻2））
  • 変更の経緯や、コメントアウトしたコードが残っていないか（no-history-comments（9-9、巻2））
  • ファイルの先頭に、責務と使い方の説明ブロックがあるか（file-header-doc-block（9-9、巻2））
  • 公開プロパティを @prop で説明しているか（prop-tag-for-public-properties（9-9、巻2））

あわせて確かめる項目

次の項目は、確認の順番の9つには含まれていません。しかし、使いやすさやアクセシビリティを損なうものは MUST の対象です。関係するスタイルがあれば、あわせて確かめます。

  • ホバーを &:any-link:hover や &:enabled:hover のように操作できる状態に限り、@media (any-hover) の中に書いているか（hover-operable-in-any-hover）。:focus-visible にも同じ見た目を指定しているか（hover-with-focus-visible）
  • 状態を .is-active のようなクラスではなく、擬似クラスやARIA属性で表しているか（state-by-pseudo-class-or-aria）
  • 動きに目的があり、高い頻度で触るUIに装飾的な動きを足していないか（motion-needs-purpose）
  • 装飾的な動きのうちフェード以外を @media (prefers-reduced-motion: no-preference) の中で指定しているか（motion-only-with-no-preference）
  • 機能的な動きの大きな変動を、動きを減らす設定でフェードに置き換えているか。DevToolsで prefers-reduced-motion: reduce をエミュレートして確かめたか（simplify-large-motion-when-reduced）
  • 機能的な動きの再生時間が300ms以下（大きなUIでも500ms以下）か。イージングは標準のキーワードではなくトークンで、現れる動きと出ていく動きは ease-out 系、画面の上にあるものの移動は ease-in-out 系か。ease-in 系を使っていないか（functional-motion-under-300ms、no-ease-in-for-ui）
  • 拡大して現れる動きを scale: 0 から始めず、transform-origin をトリガーのある側に向けているか（scale-in-from-near-one）
  • キーボードのフォーカスの移動に動きを付けていないか（no-motion-on-focus-visible）
  • キーボードショートカットで開閉するUIに、出現と退場の動きを付けていないか（no-motion-on-keyboard-shortcut）
  • 途中で取り消される動きをトランジションで書き、続けて押されるUIの動きを短くするか省いているか（interruptible-with-transition）
  • レイアウトの変わるプロパティを動かしていないか。will-change をCSSに書いたままの状態にしていないか（animate-composite-properties、will-change-temporarily）
  • content-visibility: auto を最初の画面より下のブロックにだけ指定しているか。contain-intrinsic-block-size: auto <長さ> を組で書いているか（content-visibility-with-intrinsic-size）
  • @keyframes の名前が -- で始まり、中間のフレームを持つものをコンポーネントのCSSに置いているか。一度だけ再生する演出で、@keyframes の外に opacity: 0 などを重ねて書いていないか（keyframes-local-naming、scroll-linked-method）
  • transition: all を使っていないか（no-transition-all）
  • 開閉するUIを、<dialog>、popover 属性、<details> のようなHTMLの機能で作っているか（native-disclosure-elements）
  • リンクや入力エラーのような情報を、色の違いだけで伝えていないか（no-color-only-information、grayscale-check）
  • 文字と背景のコントラスト比が、WCAG 2.1のAAを満たしているか（text-contrast-aa）
  • 枠線を border: none ではなく border-color: transparent で消しているか（transparent-border-over-none）
  • grid-template-areas や *-reverse で並べ替えたルールに、reading-flow を指定しているか（reading-flow-when-reordered（11-12、巻2））
  • 必須の印や単位のように読み手が知る必要のある文字を、content で入れていないか（no-meaningful-generated-content（5-8、巻1））
  • ::placeholder の文字と背景のコントラスト比が4.5:1以上か（placeholder-color-contrast（5-6、巻1））
  • 入力欄の文字サイズが1rem以上で、ズームを止める指定がないか（input-font-size-min-1rem、no-maximum-scale）
  • <img> に width と height の属性があり、ファーストビューの画像を遅延読み込みにしていないか（img-width-height-attributes、no-lazy-loading-first-view）

AIが生成したコードを見るとき

AIが生成したCSSでは、Stylelintで検出できない誤りが残りやすくなります。付録A「ルール一覧（巻3）」のうち、AIが誤りやすい印の付いたルールを重点的に確かめます※1。

  • 名前のないコンテナや、コンテナにした要素そのものを条件にしたクエリがないか（container-name-required（13-3、巻2））
  • ブレイクポイントが 768px のような慣習の値ではなく、レイアウトが成り立つ条件から決めた値になっているか（breakpoint-from-content（13-2、巻2）、threshold-as-formula（13-2、巻2））
  • 閾値の式が「列の最小幅×列数」で終わらず、列数から決まる隙間（gap）の数や、padding と border まで含んでいるか（threshold-includes-gap-and-padding（13-2、巻2））
  • 何にでも付いた width: 100% や、中央寄せの margin: 0 auto がないか（no-redundant-width-100（2-3、巻1）、margin-inline-auto-centering（7-3、巻1））
  • 上書きが効かない原因を調べずに足した !important がないか（no-important-for-specificity（4-1、巻1））
  • ._list や ._link のように、要素の種類を言い換えただけの子クラスをすべての要素に付けていないか（type-selector-in-scope（10-2、巻2））
  • 宣言を1つずつ言い換えたコメントが付いていないか（comments-why-only（9-9、巻2））
  • AIの出力を直した内容を、プロジェクトの規約の文書に書き足したか（record-ai-corrections）

レイアウト

用語 意味 詳しい説明
レイアウトの方式 子の大きさと位置を決める規則のまとまりです。通常フロー、Flexbox、Grid、位置指定などがあり、親の display の内側の値と、要素自身の position で決まります。同じプロパティでも、方式によって働き方が変わります。レイアウトモードとも言います。 1-3（巻1）、7-1（巻1）
通常フロー FlexboxやGridを指定していない要素が従う、既定のレイアウトの方式です。ブロックレベルのボックスはブロック方向に積まれ、インラインレベルのボックスは行の中をインライン方向に流れます。 7-2（巻1）
ブロック整形コンテキスト 通常フローのブロックを並べる、閉じた範囲です。中の float を内側に収め、外とのマージンの相殺を止めます。本書では display: flow-root で作ります。 7-2（巻1）、7-6（巻1）

ガター ページのコンテンツの左右に置く、余白のための列です。画面幅いっぱいに広げたい要素は、この列まで広げます。 11-2（巻2）
次兄弟結合子 h2 + p の + のように、直前の兄弟要素を条件にして要素を選ぶ結合子です。本書では、要素の間のブロック方向の margin を、& > * + * のようにこの結合子で選んだ後ろの要素の margin-block-start に付けます。 11-2（巻2）
ディフェンシブCSS テキストが長くなったら、画像がなかったら、要素の数が変わったらと考え、想定外の内容が入っても崩れないように書くCSSです。 11-3（巻2）

スタッキングコンテキスト 重なり順を決める単位です。z-indexは、同じスタッキングコンテキストの中の要素どうしでしか比べられません。 11-6（巻2）
トップレイヤー <dialog> のモーダルや popover 属性の要素が表示される層です。本来は、z-indexと関係なく最前面に描かれます。 10-2（巻2）、17-5
アンカーポジショニング ある要素（アンカー）の位置を基準に、別の要素を配置する仕組みです。本書の対象のブラウザではまだレイアウトの要にしません（2026年9月確認）。 7-11（巻1）

表にない困りごと

表にない症状は、まず開発者ツールで、問題の要素にどの宣言が当たり、どの宣言が負けているかを確かめます。負けている宣言が分かれば、その宣言のプロパティから付録A「ルール一覧（巻3）」を引けます。崩れが特定の幅や内容でだけ起きるなら、「19-3 表示と操作を確かめる」の手順で、幅と内容を変えながら再現する条件を絞ります。
