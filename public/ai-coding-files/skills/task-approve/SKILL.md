---
name: task-approve
description: タスクの plan.md を承認し、status を approved にする。利用者が呼ぶ。
argument-hint: <タスクのスラッグの一部>
disable-model-invocation: true
---

`tasks/` の直下（`tasks/archive/` を除く）から、名前に「$ARGUMENTS」を含むタスクを探し、plan.md を承認する。複数見つかったら、一覧を示して選んでもらう。

1. plan.md の status が draft でなければ、今の status を伝えて止まる。
2. 「懸念・確認事項」の問いを判定する。実装に必要な値や振る舞いが回答によって決まり、plan に反映されている問いは、解決済みとする。「未定」という回答だけでは解決済みにしない。人が選んだ暫定案が値の対応表に記録されている問いは、未解決として止めず、その案で進めることを承認する対象にする。
   - 未解決の問いがあれば、一覧にして止まる。回答やチャットの修正依頼がまだ plan に反映されていない場合も、`/task-start` で反映してから承認するよう案内する。
   - 人が選んだ暫定案が値の対応表に種類「仮」として記録されている問いは、案と対応する問いを一覧にして、その案で進めることを承認するか尋ねる。承認すると答えるまで、status を変えない。
3. plan.md の frontmatter を `status: approved` と `approved: <今日の日付>` にし、決定ログに「<今日の日付>：承認」と追記する。暫定案を承認した場合は、対応する問いと、その案で進めることを認めた記録も残す。
4. 実装は `/task-start <slug>` で始めるよう案内する。このスキルでは実装に進まない。
