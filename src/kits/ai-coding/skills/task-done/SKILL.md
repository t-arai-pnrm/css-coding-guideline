---
name: task-done
description: 完了したタスクの報告を確かめてアーカイブし、教訓とプロジェクトの規約を見直す。利用者が呼ぶ。
argument-hint: <タスクのスラッグの一部>
disable-model-invocation: true
---

`tasks/` の直下（`tasks/archive/` を除く）から、名前に「$ARGUMENTS」を含むタスクを探す。複数見つかったら、一覧を示して選んでもらう。

1. plan.md の「完了の報告」を読む。
   - 報告がない、または「不合格」の項目があれば、`/task-start` で続けるよう案内して止まる。
   - 「未確認」の項目は一覧にして、人が確かめたかを尋ねる。確かめていない項目は、アーカイブの前に確かめてもらう。
2. 決定ログとこのセッションのやりとりから、AI が誤った点と、人が直した点を拾う。`tasks/lessons.md` の先頭に、ファイルの書式で追記する。原因は、コンテキスト不足、権限不足、性能不足のどれかに分ける。
3. 規約を見直す。どちらも、人の確認を得てから書き換える。
   - 教訓ごとに、同じ誤りを防ぐために書き足す先を提案する（`CLAUDE.md`、Stylelint の設定、テスト、brief や plan のひな形）。
   - `CLAUDE.md` に、モデルが守れるようになって要らなくなった指示や、本書のルールと重なる指示があれば、消す案を出す。
4. plan.md の status を done にし、`tasks/<slug>/` を `tasks/archive/<slug>/` に移す。
