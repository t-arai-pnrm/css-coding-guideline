「$ARGUMENTS」のタスクを作る。

## 手順

1. タスクを表すスラッグを、英小文字とハイフンで決める（例：`article-card`）。`tasks/` と `tasks/archive/` に同じ名前があれば、別の名前を提案して確かめる。
2. 次の項目を、1回に1〜3問ずつ尋ねる。答えにないことを推測で埋めない。決まっていない項目は「未定」と書く。
   1. 目的、対象の部品やページ、やること、やらないこと
   2. Figma の URL（node-id を含む）、置き場所と、そこでの幅
   3. デザインから読み取れないこと
      - 共通のルールから外している箇所
      - カンプのない幅での振る舞い（カンプとカンプの間の幅、カンプより狭い幅と広い幅）
      - 内容が変わったときの見せ方（長い見出し、画像がない、項目が0件・1件・多数）
      - 状態と動き（ホバー、フォーカス、押下、無効、開閉、動きを減らす設定）
   4. 完了条件。コマンドや数値で確かめられるもの（AI が判定する）と、見た目の印象のように人が判定するものに分ける
   5. 参考ファイル（`refs/` に置くもの）と、それぞれの用途
   6. 確かめる幅とブラウザ（プロジェクトの既定と違うときだけ）
3. 答えを [templates/brief.md](templates/brief.md) の形にまとめ、ファイルに書く前にチャットで全文を示す。直す点がなくなるまで、チャットの中で直す。
4. 確認が取れたら、`tasks/<slug>/brief.md` を1回で書き出し、`tasks/<slug>/refs/` を作る。書き出した後の brief は人のファイルで、AI は編集しない。直す点が出たら、人が直接編集する。
5. 参考ファイルを `refs/` に置き、準備ができたら `/task-start <slug>` を実行するよう案内して終える。plan.md は作らない。
