AIにCSSを書かせる前に、2種類の規約を読ませます。1つは本書のルールで、スキルかMCPサーバーで読ませます。もう1つはプロジェクトの判断基準で、`CLAUDE.md` のような、AIが作業のたびに読む指示のファイルに書きます。

指示のファイルには、本書のルールを写しません。本書のルールはIDで参照し、書くのは、選択肢があるときにこのプロジェクトがどちらを選ぶかと、本書と違う独自の規約だけです。既存のプロジェクトでは、書き足す前に、AIにCSSの構成を説明させ、自分の理解とのずれを直します。

## 書く前にルールを読ませる理由

AIが学習した知識は、学習した時点で止まっています。「`@scope` はまだ使えない」のように、その後に対応が進んだ機能を未対応とみなすことがあります（「[20-7 AIが誤りやすいパターン](/ai-coding/pitfalls/)」）。また、`scoped` のルートのクラスや `--_density` のフラグのような本書の規約は、学習したコードにほとんど含まれていません。

{/* 要確認: 出典なし */}一方で、作業の中で読ませた情報は、学習した知識よりも優先して使われることが多くあります。そのため、AIには書く前に関係するルールを読ませます（`ai-read-rules-first`）。読ませなければ、AIは学習した中で多数派の書き方で埋めます。

## 本書のスキルとMCPサーバー

{/* 要確認: 著者の判断。配布物の提供を始めたら、次の文を消す */}
この節で説明するスキル、MCPサーバー、プラグインは、提供に向けて対応中のため、まだ利用できません（2026年10月時点）。

本書は、AIのコーディングエージェントに参照させるドキュメントを兼ねています。そのために、ルールはすべて1か所のデータ（YAMLのファイル）で管理しています。各ページの「ガイドライン」、付録A「[ルール一覧](/appendix/rules/)」、AI向けのスキルとMCPサーバーは、どれも同じデータから作られます。人が読むルールとAIに渡すルールは食い違いません。

AIが古い書き方や誤った書き方をしがちなルールには、印を付けています。ページのガイドラインでは「AIが生成するコードで誤りやすいルールです」という注意が表示されます。スキルでは、こうしたルールを1件1行の一覧にまとめ、CSSを書く前に必ず読ませています。

本文の書き方にも、AIが読むことを前提にした約束があります。各ページは単体で意味が通るように書き、ほかのページに触れるときはリンクと一言の要約を添えます。ブラウザの対応状況のように時間で変わる記述には、確認した年月を書きます。コードを省略するときは `/* ... */` と書き、推奨のコード例はすべてStylelintで検証しています。

配布しているのは、スキル、MCPサーバー、`llms.txt` の3つです。Claude Codeでは、プラグインを1つ入れると、スキルとMCPサーバーの両方が使えます。Cursor、Codex、GitHub Copilotのようなほかのツールにも、スキルとMCPサーバーを設定できます。ツールごとの設定方法は、付録J「[AIツールで使う](/appendix/ai-tools/)」にまとめています。

どの形で読ませても、AIにさせることは同じです。書く前に関係するルールを引き、書いた後に検査し、判断の根拠をルールのIDで示させます。スキルは、手順と章の索引を最初に読み込み、ルールは必要な章のファイルだけを開きます。MCPサーバーがあれば、AIはルールを語句や章で検索し、書いたCSSを本書のStylelintの設定で検査できます。

ただし、MCPサーバーの検査で見つかるのは、Stylelintで確かめられるルールの違反だけです。検査を通ったことは、ルールを守っていることの証明にはなりません。lintを通っても残る誤りの例は「[20-8 生成したコードを確かめ、教訓を残す](/ai-coding/verify-output/)」で示します。AIへの指示でも、「`no-vw-vh` に従って」のようにルールのIDで伝えると、どのルールのことかが正確に伝わります。

## `CLAUDE.md` に書くこと

プロジェクトの事情は、本書のスキルとは別の文書に書きます。Claude Codeは、プロジェクトの `CLAUDE.md` を作業のたびに読み、`CLAUDE.md` がなければ `AGENTS.md` を読みます（2026年10月確認）。Codex、Cursor、GitHub Copilotは `AGENTS.md` を読みます。複数のツールを使うチームでは、内容を `AGENTS.md` へまとめます。`CLAUDE.md` も置く場合は、`@AGENTS.md` で読み込み、同じ内容を2か所で持たないようにします。

書くのは、選択肢があるときの判断基準です。{/* 要確認: 出典なし */}「あなたはCSSの専門家です」のような役割の指定を書いても、どの書き方を選ぶかは決まりません。たとえば、ブレイクポイントをいくつ置くか、トークンにない値をその場に書くかトークンを足すか、どの幅で確かめるかは、プロジェクトごとに答えが違います。これらを書いておかなければ、AIはその場で選び、選んだ理由も残りません。

本書のルールで足りることは、IDで参照し、本文を写しません。写すと、本書の版が上がってルールが変わったときに、`CLAUDE.md` の文面だけが古いまま残ります。本書と違う規約を採るときは、どのルールより優先するかが分かるように、ルールのIDと理由を添えます。CSSに関わる部分の例を、次に示します。

私のテンプレートでは、`CLAUDE.md` にコマンド、ディレクトリの構成、検証の手順を書き、CSSの規約は単位、不要な記述、コンポーネントの設計のように、話題ごとのファイルに分けています。CMSの案件では、ネストやモーションの規約を書き足し、「下位の手段を選ぶときは、上位の手段で満たせない理由を説明する」のように、AIに判断の理由を求める書き方もしています。

指示のファイルは、書き足すだけでなく、要らなくなった指示を消すことも必要です。モデルの版が上がると、以前は書かなければ守れなかった指示を、書かなくても守れるようになることもあります。古い指示が残ると、読ませる量が増えるうえに、新しい規約と食い違う指示が混ざります。見直す機会は、タスクを終えるときに設けます（「[20-8 生成したコードを確かめ、教訓を残す](/ai-coding/verify-output/)」）。

## 既存のプロジェクトで最初にすること

すでにCSSがあるプロジェクトでAIに書かせ始めるときは、最初の作業として、AIにCSSの構成を説明させます。説明させる項目は、レイヤーの順番、トークンの置き場所と名前の付け方、コンポーネントの命名とスコープの書き方、ブレイクポイントとコンテナサイズクエリの使い方です。

```md title="AIへの依頼の例"
このリポジトリのCSSの構成を説明してください。レイヤーの順番、トークンの置き場所と名前の付け方、コンポーネントの命名とスコープの書き方、ブレイクポイントとコンテナサイズクエリの使い方を、根拠になるファイルのパスを添えて説明し、本書のルールと違う点を挙げてください。コードは変更しないでください。
```

説明を読んで、自分の理解と違う点があれば、どちらが正しいかをコードで確かめます。AIの説明が誤っていれば、誤解の元になった箇所を `CLAUDE.md` に書きます。自分の理解が誤っていれば、そのまま学べます。本書と違う規約が見つかったら、本書に合わせるか、プロジェクトの規約として残すかを決め、残すものを `CLAUDE.md` に書きます。

この作業を飛ばすと、AIは新しいコンポーネントを、既存の規約を確かめないまま書きます。デザインに合わせることだけを追って、既存のコンポーネントの書き方と違うスコープの書き方を持ち込む、といった手戻りが起きます。本書の規約を既存のサイトにどの範囲から入れるかは、「[19-6 既存のサイトに段階的に導入する](/operations/adoption/)」で説明しています。

## lintと、許可とフック

規約のうち機械的に判断できるものは、Stylelintで検査します。AIには、CSSを変えたらlintを実行させ、エラーを消すためにルールを無効にすることを禁じます（`no-disabling-to-silence`）。本書の設定と、プロジェクトへの入れ方は「[19-1 Stylelintでルールを守る](/operations/stylelint/)」で説明しています。

Claude Codeの許可の設定（`.claude/settings.json` の `permissions`）では、読むだけのツールを許可しておくと、作業のたびに確認を求められる回数が減ります。たとえば、FigmaのMCPサーバーのデザインを読むツールや、本書のMCPサーバーのツールは、ファイルを書き換えないので許可してかまいません。

取り返しのつかない操作には、フックで確認を挟みます。フックは、ツールを使う前後に、決めたコマンドを実行する仕組みです。私の案件では、AIが作業の途中で、ローカル環境の管理者のパスワードを無断で変えたことがありました。それ以来、パスワードを変えるコマンドを実行する前に、必ず人の確認を求めるフックを入れています。人が書いたファイルをAIの書き込みから守るフックは、「[20-4 タスクの単位で進める](/ai-coding/tasks/)」で示します。
