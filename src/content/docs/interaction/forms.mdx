フォーム部品は、ブラウザが用意している部品をできるだけそのまま使います。チェックボックスやラジオボタンの色を変えるだけなら、`accent-color` で済ませます。見た目を作り直す必要があるときは、`input` を隠さずに、`input` 自体に `appearance: none` を指定して描きます。

スイッチは `<input type="checkbox" switch>` で作り、入力エラーの見た目は `:invalid` ではなく `:user-invalid` に指定します。入力欄の文字サイズは1rem以上にし、ズームを止める指定は書きません。`<select>` の見た目は、対応した環境でだけ `appearance: base-select` で変え、未対応の環境では標準の `<select>` のまま表示します。

## kiso.cssが整えるフォームの初期値

フォーム部品のスタイルを書く前に、リセットCSSが何を整えているかを確認しておきます。本書が推奨するkiso.cssは、フォーム部品に1pxの実線の枠線を付け、枠線の色、文字色、フォントを親から継承させています。スタイルを当てていない状態でも入力欄の範囲が分かり、コンポーネントでは色や余白を足すだけで済みます。枠線を消したいときは、強制カラーモードを考えて `border: none` ではなく `border-color: transparent` にします。

ほかにも、入力欄には `text-autospace: no-autospace` を指定して、入力中に和文と英数字の間へアキが入るのを防いでいます。ボタンには `touch-action: manipulation` を指定して、iOSで連続してタップしたときの拡大を防ぎ、押せる部品のカーソルを `pointer` にしています。`<textarea>` は、縦方向にだけリサイズできます。詳しくは「[8-1 壊さないリセット](/reset/kiso/)」で説明しています。

CSSではありませんが、入力欄には `autocomplete` 属性で入力する内容の種類（`name`、`email`、`postal-code` など）を正しく指定します。ブラウザの自動入力が働き、入力の手間と誤りを減らせます。ログインのフォームでは、多くのブラウザがパスワードマネージャーのために `autocomplete="off"` を無視します（MDN、2026年9月確認）。

## `accent-color` で色を変える

チェックボックスの色をデザインに合わせたいとき、`input` を透明にして、隣の要素で四角とチェックを描き直す方法がよく使われてきました。しかし、色を変えるだけなら、描き直す必要はありません。`accent-color` を指定すれば、チェックボックス、ラジオボタン、スライダー（`type="range"`）、プログレスバーの色が変わります。

```css title="🙆‍♂ Recommended: フォーム全体のアクセントカラーを指定する"
@scope (.scoped.contact-form) to (.scoped) {
  :scope {
    accent-color: var(--background--accent);
  }
}
```

`accent-color` は継承されるので、フォームのルートに1回書けば、中のすべての部品に適用されます。部品の操作性やアクセシビリティは、ブラウザのものがそのまま残ります。

<Baseline id="accent-color" />

web-featuresのデータでは、SafariはSafari 26.2からの対応になっています。MDNの互換性データによると、それより前のSafariも `accent-color` に対応していますが、チェックマークの色を背景に合わせて調整しません（2026年9月確認）。本書の対象のSafariでも色は変わるので、チェックマークとのコントラストが十分に取れる色を選べば使えます。

なお、リセットCSSで、すべての `input` へ一律に `appearance: none` を指定するのは禁止です。チェックボックスやラジオボタンの見た目が消え、画面から見えなくなるからです（「[8-1 壊さないリセット](/reset/kiso/)」）。

## `input` 自体に描く作り直し方

デザインの都合で、形まで作り直す必要がある場合もあります。そのときも、`input` を隠して別の要素で描く方法は使いません。

```css title="🙅‍♂ Not Recommended: input を隠し、隣の要素でチェックボックスを描く"
/* 🙅‍♂ Not Recommended */
._checkbox {
  display: none;
}

._checkbox + ._icon {
  display: inline flow-root;
  inline-size: 1lh;
  block-size: 1lh;
  border: 1px solid;
}

._checkbox:checked + ._icon {
  background-color: var(--background--accent);
}
```

`display: none` や `visibility: hidden` で隠した `input` は、キーボードでフォーカスできません。Tabキーで操作するユーザーは、チェックボックスを操作できなくなります。透明にして残す方法でも、フォーカスリングを隣の要素に描き直す手間がかかり、隣接セレクタや `:has()` で状態をつなぐ必要もあります。

見た目を作り直すときは、`input` 自体に `appearance: none` を指定して、ブラウザの見た目だけを消します。そのうえで、`input` の枠と背景、`::before` で描いたチェックマークで見た目を作ります。

```css title="🙆‍♂ Recommended: input 自体に appearance: none を指定して描く"
@scope (.scoped.check-field) to (.scoped) {
  input {
    display: inline grid;
    place-content: center;
    inline-size: 1lh;
    block-size: 1lh;
    border-color: var(--foreground--muted);
    border-radius: 4px;
    appearance: none;

    &:checked {
      border-color: var(--background--accent);
      background-color: var(--background--accent);
    }

    /* チェックマークは、選択したときだけ作る */
    &:checked::before {
      content: "";
      inline-size: 0.3lh;
      block-size: 0.55lh;
      border-block-end: 2px solid var(--foreground--on-accent);
      border-inline-end: 2px solid var(--foreground--on-accent);
      rotate: 45deg;
    }
  }
}
```

`input` そのものなので、キーボードで操作でき、ベーススタイルのフォーカスリングもそのまま表示されます。状態は `:checked` で選べるので、ほかの要素とつなぐ必要もありません。大きさは `inline-size` と `block-size` の両方で指定します。`input` の大きさを `aspect-ratio` で決めると、Safariでは縦横の比率を保てずに、部品を潰してしまうことがあるからです。強制カラーモードで背景色が消えたときの見え方は、「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/)」で扱います。

チェックマークの `::before` は、選択したときだけ作ります。未選択のときも作っておき、枠線を `transparent` にして隠すと、強制カラーモードで枠線の色がシステムカラーに置き換わり、未選択でもチェックマークが見えてしまいます。状態の違いを、色を透明にするかどうかだけで表さないようにします。

## `appearance: base-select` で `<select>` を変える

`<select>` は、長いあいだ見た目をほとんど変えられない部品でした。開いたときの選択肢の一覧はブラウザやOSの部品で描かれ、角丸や影を付けることも、選択肢に画像を入れることもできません。そのため、デザインに合わせたドロップダウンを、`<div>` とJavaScriptで作り直すことがよくありました。作り直した部品では、キーボードでの選択や読み上げを自分で実装することになり、その分だけ抜けが起きやすくなります。{/* 要確認: 出典なし */}

`appearance: base-select` を `<select>` と、選択肢の一覧を表す `::picker(select)` の両方に指定すると、一覧まで含めてCSSで見た目を変えられるようになります（MDN）。部品は `<select>` のままなので、キーボードでの選択、フォームの送信、読み上げはブラウザが引き受けます。一覧はトップレイヤーに表示され、`<select>` を暗黙のアンカーにして配置されます（「[11-8 アンカーポジショニング](/layout-practice/anchor-positioning/)」）。

<Baseline id="customizable-select" name="カスタマイズ可能な <select>" />

2026年10月の時点で対応しているのは、Chrome系のブラウザ（135以降）とSafari 27で、Firefoxは対応していません。本書では、Baselineでない機能はプログレッシブ・エンハンスメントとして使います。対応していない環境では、ブラウザの標準の `<select>` のまま表示されれば十分です。HTMLは、選んだ項目を表示するボタンを、`<select>` の最初の子に置きます。

```html title="選んだ項目の中身を、ボタンの中に写す"
<select name="sort">
  <button>
    <selectedcontent></selectedcontent>
  </button>
  <option value="new">新しい順</option>
  <option value="popular">人気の順</option>
</select>
```

`<selectedcontent>` には、選んでいる `<option>` の中身が写されます。`<option>` に画像や `<span>` を入れておけば、選んだ後のボタンにも同じものが表示されます。対応していないブラウザのHTMLの解析では、`<select>` の中にある `<option>` 以外の開始タグは捨てられます（HTML Standardの以前の解析規則）。`<button>` と `<selectedcontent>` は無視され、`<option>` の中の文字だけが残るので、従来の `<select>` として動きます。

```css title="🙆‍♂ Recommended: 対応した環境でだけ、<select> と選択肢の一覧の見た目を変える"
@scope (.scoped.sort-select) to (.scoped) {
  select {
    @supports (appearance: base-select) {
      padding-block: 8px;
      padding-inline: 12px;
      border-color: var(--foreground--muted);
      border-radius: 8px;
      appearance: base-select;

      &::picker(select) {
        margin-block-start: 4px;
        border-color: var(--border--base);
        border-radius: 8px;
        appearance: base-select;
      }

      &::picker-icon {
        @media (prefers-reduced-motion: no-preference) {
          transition-duration: var(--duration--fast);
          transition-property: rotate;
          transition-timing-function: var(--ease--out-quint);
        }
      }

      &:open::picker-icon {
        rotate: 180deg;
      }
    }
  }

  option {
    @supports (appearance: base-select) {
      &:checked {
        font-weight: 700;
      }

      &::checkmark {
        color: var(--foreground--accent);
      }
    }
  }
}
```

`::picker-icon` はボタンの中の矢印、`option::checkmark` は選んでいる選択肢の前に付く印です。`:open` は、一覧が開いている間だけ `<select>` に当てはまる擬似クラスです。この例では、開いている間は矢印を180度回します。`:open` 自体は2026年5月からBaselineで、Firefoxでも使えます。ここでは `base-select` の見た目と組み合わせるので、同じ `@supports` の中に書いています。

<Baseline id="open-pseudo" name=":open" />

`@supports (appearance: base-select)` で囲むのは、`base-select` を前提にした余白や枠線を、ブラウザの標準の `<select>` に当てないためです。対応していない環境は `appearance: base-select` の宣言を無視しますが、同じルールの `padding` や `border-radius` は標準の部品に当たり、矢印や文字の位置とかみ合わない見た目になりえます。{/* 要検証: ブラウザ。未対応のブラウザでの崩れ方は未検証 */}囲んでおけば、未対応の環境はブロックごと読み飛ばし、`<select>` は標準の見た目のまま残ります。

## `switch` 属性によるスイッチ

オンとオフを切り替えるスイッチは、`<input type="checkbox" switch>` で作ります。`switch` 属性に対応したブラウザでは、スクリーンリーダーが「スイッチ」として、状態を「オン」「オフ」で読み上げます。JavaScriptは要らず、スペースキーでも切り替えられます。

<Baseline id="switch-control" name="switch 属性" />

2026年9月の時点で、`switch` 属性に対応しているのはSafariだけです。ほかのブラウザでは、ふつうのチェックボックスとして扱われます。操作は損なわれないので、チェックボックスとして読み上げられることを許容できるなら、プログレッシブ・エンハンスメントとして使えます。すべての環境で「スイッチ」として読み上げる必要がある場合は、`<input type="checkbox" switch role="switch">` のように `role="switch"` を加えます。`role="switch"` を付けたチェックボックスは、スクリーンリーダーにオンとオフの状態を伝えます。`<button>` と `aria-pressed` の組み合わせは、押した状態を表す「トグルボタン」になり、オンとオフの意味にはならないので、スイッチの代わりには使いません。

見た目は、`appearance: none` を指定した `input` 自体に描きます。`::after` をつまみに、`::before` をつまみの手前の余白にして、オンのときに `::before` を伸ばしてつまみを押し出します。

```css title="🙆‍♂ Recommended: つまみの手前の余白を伸ばして、つまみを動かす"
@scope (.scoped.setting-switch) to (.scoped) {
  input {
    display: inline flex;
    inline-size: calc(1lh * 2);
    block-size: 1lh;
    padding: 2px;
    border-color: transparent;
    border-radius: calc(infinity * 1px);
    background-color: var(--border--strong);
    appearance: none;

    &::before {
      content: "";

      @media (prefers-reduced-motion: no-preference) {
        transition-duration: var(--duration--fast);
        transition-property: flex-grow;
        transition-timing-function: var(--ease--out-quint);
      }
    }

    &::after {
      content: "";
      flex-shrink: 0;
      block-size: 100%;
      aspect-ratio: 1;
      border-radius: inherit;
      background-color: var(--foreground--on-accent);

      /* 強制カラーモードでは、背景色で描いたつまみが消えるので、システムカラーで描く */
      @media (forced-colors: active) {
        background-color: CanvasText;
      }
    }

    &:checked {
      background-color: var(--background--accent);
    }

    &:checked::before {
      flex-grow: 1;
    }
  }
}
```

高さは `1lh` にして、隣のラベルの行の高さにそろえています。kiso.cssは入力欄のフォントを継承させているので、`1lh` はラベルと同じ行の高さになり、幅はその2倍です。

つまみもスイッチの地も背景色で描いているので、何もしなければ、強制カラーモードでは背景色がページの背景色に置き換わり、つまみが見えなくなります。そこで、強制カラーモードのときだけ、つまみの背景色をシステムカラーの `CanvasText` にしています。作者が指定したシステムカラーは置き換えられないので、つまみは文字と同じ色で描かれ、その位置でオンとオフを見分けられます。{/* 要検証: ブラウザ。強制カラーモードでのつまみの表示をブラウザで確認していない */}

枠線を消さずに `border-color: transparent` で残しているのも、強制カラーモードのためです。透明にした枠線はシステムカラーで描かれるので、スイッチの範囲が分かります。背景色で描いた図形をシステムカラーで補う考え方は「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/)」で説明しています。

`flex-grow` はレイアウトが変わるプロパティですが、小さな部品なので負荷は問題になりません。`translate` でつまみを動かすより、スイッチの幅を変えたときや、右から左へ書く言語でも調整が要らないという利点があります。

## `:user-invalid` による入力エラーの表示

入力エラーの見た目を `:invalid` に指定すると、ページを開いた時点でエラーが表示されてしまいます。`required` を付けた空の入力欄は、何も入力していなくても `:invalid` に当てはまるからです。私も以前は、この問題を避けるためにJavaScriptで検証し、data属性で状態を表していました。

`:user-invalid` は、ユーザーが値を変えて入力欄を離れた後や、送信しようとした後にだけ当てはまる擬似クラスです。入力する前にエラーが表示されることはありません。

```css title="🙆‍♂ Recommended: 入力した後にだけ、エラーの見た目にする"
@scope (.scoped.contact-form) to (.scoped) {
  ._email-input {
    border-color: var(--foreground--muted);

    &:user-invalid {
      border-color: var(--foreground--danger);
    }
  }

  p {
    &:is(._field:has(:user-invalid) *) {
      color: var(--foreground--danger);
      font-weight: 700;
    }
  }
}
```

<Baseline id="user-pseudos" compatKey="css.selectors.user-invalid" name=":user-invalid" />

エラーは、色だけで伝えないようにします。上の例では、入力例を示すヒントの文字を太くしています。また、`:user-invalid` が変えるのは見た目だけで、スクリーンリーダーには伝わりません。エラーの内容を読み上げさせるには、`aria-invalid` や、エラーの文章を関連付ける `aria-describedby` を、JavaScriptで設定します。

次のデモでは、メールアドレスの欄に不正な値を入れて欄を離れるか、何も入力せずに「送信する」を押すと、エラーの表示を確かめられます。ラジオボタンは `accent-color` で色だけを変え、同意のチェックボックスとスイッチは `input` 自体に描いています。開発者ツールで強制カラーモードを再現すると、未選択のチェックボックスにチェックマークが出ないことも確かめられます。

## 入力欄の大きさと文字サイズ

`<textarea>` には、次のスタイルを定義します。`field-sizing: content` で入力した量に合わせて入力欄を伸び縮みさせ、最小と最大の高さは `lh` 単位で行数として決めます。

```css title="🙆‍♂ Recommended: 行数で高さを決め、対応した環境では内容に合わせて伸び縮みさせる"
._textarea {
  --_rows: 3lh;
  --_max-rows: 8lh;
  --_border-color: var(--foreground--muted);
  --_foreground: var(--foreground--base);
  --_background: var(--background--base);

  /* ① box-sizing を初期値（content-box）に戻す */
  box-sizing: unset;

  /* ② 横幅をいっぱいにする。content-box なので 100% は使わない */
  inline-size: -webkit-fill-available;
  inline-size: stretch;

  /* ③ 最小の高さを --_rows 行分にする（行数は rows 属性ではなくここで決める） */
  min-block-size: var(--_rows);
  padding: 1em;
  border-color: var(--_border-color);
  background-color: var(--_background);
  color: var(--_foreground);

  /* ④ iOS の拡大を防ぐため 16px を下限にし、それ以上なら 1rem に追従する */
  font-size: max(16px, 1rem);

  @supports (field-sizing: content) {
    /* ⑤ 最大の高さを --_max-rows 行分に制限する */
    max-block-size: var(--_max-rows);

    /* ⑥ ユーザーによるサイズの変更を無効にする */
    resize: none;

    /* ⑦ 内容に合わせて高さが変わるようにする */
    field-sizing: content;
  }
}
```

①で `box-sizing` を `content-box` に戻すのは、高さを行数だけで書くためです。kiso.cssはすべての要素を `border-box` にしています。そのままでは `min-block-size` に `padding` と `border` が含まれるので、3行分の高さを `calc(3lh + 2em + 2px)` のような足し算で求めることになります。`content-box` なら `min-block-size` は内容の領域の高さなので、`3lh` がそのまま3行分になります。`box-sizing` は継承しないプロパティなので、`unset` は初期値の `content-box` になります。

②で `100%` を使わないのは、`content-box` では `100%` に `padding` と `border` が足され、入力欄が親からはみ出すからです。`stretch` を指定すると、`margin` を含めた箱が親の幅にちょうど収まります。`stretch` に対応していないブラウザのために、先に `-webkit-fill-available` を書いています。2026年10月の時点で `stretch` に対応していないFirefoxも、`-webkit-fill-available` で同じように広がります（「[2-3 保守しやすさを最優先にする](/layout/sizing/#rule-stretch-over-width-100)」）。

③の `min-block-size` で、行数は `rows` 属性ではなく `--_rows` で決まります。`field-sizing: content` に対応した環境では、`rows` 属性はもともと高さに使われません（「[6-5 if()とattr()で条件と属性を値にする](/values/if-and-attr/)」）。

⑤から⑦は、`field-sizing` に対応した環境でだけ指定します。自動で伸び縮みするなら、ユーザーが手でサイズを変える機能（`resize`）は要りません。`resize` の初期値は `none` なので、`unset` でブラウザの既定の `resize` を打ち消せます。最大の高さも、自動で伸びる上限としてここでだけ指定します。未対応の環境では入力欄の右下のつまみで高さを変えられるので、最大の高さを付けると、手で広げられる範囲まで狭まるからです。`@supports` を使う理由とデモは、「[1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」にあります。

<Baseline id="field-sizing" />

④のように、入力欄の文字サイズは、1rem（16px相当）以上にします。iOSのSafariは、文字サイズが16px未満の入力欄にフォーカスすると、ページを拡大します。拡大されたページは、ユーザーが自分で縮小するまでそのままです。`1rem` だけでなく `max()` で16pxを下限にしているのは、ブラウザの設定で基準の文字サイズを16px未満にしている環境でも、拡大が起きないようにするためです。kiso.cssは入力欄の文字サイズを親から継承させているので、ほかの入力欄でも、フォームの周りで文字サイズを小さくしていないかを確かめます。

この拡大を防ぐために、`<meta name="viewport">` に `maximum-scale=1` や `user-scalable=no` を指定する方法が知られています。しかし、この指定はページ全体の拡大を止めてしまい、拡大して読む必要のあるユーザーが、読めなくなります。デザインでどうしても小さな文字にしたい場合は、フォーカスしている間だけ1remにする方法もありますが、まずは1remで成り立つデザインにできないかを相談します。

## フォーム部品で確かめる状態

フォーム部品を作り直したら、通常の表示で整っていることに加えて、キーボード、強制カラーモード、拡大した状態でも操作できるかを確かめます。このページで説明した振る舞いから、確かめる状態を次の表にまとめました。

| 状態 | 確かめること | 期待する結果 |
| --- | --- | --- |
| キーボードだけの操作 | Tabキーで移動し、スペースキーで切り替える | 作り直したチェックボックスとスイッチにもフォーカスが止まり、フォーカスリングが表示され、状態が切り替わる |
| ページを開いた直後と入力した後 | 何も入力せずに表示し、次に不正な値を入れて欄を離れる | 開いた直後はエラーの見た目にならず、離れた後に枠線の色とヒントの太字でエラーが示される |
| 強制カラーモード | チェックボックスとスイッチをオンとオフにする | 未選択のチェックボックスにチェックマークが出ず、スイッチの範囲が枠線で分かり、つまみの位置でオンとオフを見分けられる |
| `appearance: base-select` の対応と未対応 | Chrome系のブラウザまたはSafari 27と、Firefoxで `<select>` を開き、キーボードで選ぶ | 対応した環境ではスタイルを当てた一覧が、未対応の環境では標準の一覧が開き、どちらも矢印キーで選べる |
| `switch` 属性の対応と未対応 | Safariとほかのブラウザで、スクリーンリーダーで読み上げる | Safariでは「スイッチ」として、ほかのブラウザではチェックボックスとして読み上げられ、どちらでも切り替えられる |
| 文字を200%に拡大した状態 | ラベルとチェックボックス、スイッチを見比べる | `1lh` で大きさを決めた部品が、ラベルの行の高さに合わせて大きくなる |
| iOSのSafari | 入力欄にフォーカスする | ページが拡大されない |
| 動きを減らす設定 | スイッチを切り替える | つまみが動かず、すぐにオンやオフの位置に変わる |

強制カラーモードと動きを減らす設定は、Chromeの開発者ツールの「Rendering」パネルで再現できます。それぞれ「Emulate CSS media feature forced-colors」と「Emulate CSS media feature prefers-reduced-motion」を切り替えます。強制カラーモードでつまみが見えないときは、つまみの背景色をシステムカラーで補っているかを確かめます。
