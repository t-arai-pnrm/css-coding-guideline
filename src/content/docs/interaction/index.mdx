この章では、ユーザーの操作に反応する部分のCSSを扱います。ホバーやフォーカスの状態の表し方、ダイアログやアコーディオンのような開閉するUI、フォーム部品、カルーセルです。インタラクションはできるだけブラウザの機能に任せ、CSSでは見た目を足すことに徹します。

操作に関わるUIは、見た目が同じでも使いやすさが変わります。キーボードで操作できるか、スクリーンリーダーで状態が読み上げられるか、ページ内検索で中身が見つかるかといった違いがあるからです。以前は、こうした振る舞いの多くをJavaScriptで作り直す必要がありました。現在は、`<dialog>` の `command` 属性や `popover` 属性、`<details>` の `name` 属性のように、HTMLとCSSだけで実現できることが増えています。

私自身、少し前まではモーダルの開閉や背景のクリックの判定をJavaScriptで書いていました。入力エラーの表示も、`:invalid` ではページを開いた時点でエラーが出てしまうので、JavaScriptで管理していました。どちらも、いまはブラウザの機能で置き換えられます。

この章は次の7つの節で構成しています。17-1から17-4は、どの部品にも関わる操作の基本で、17-5から17-7は、部品ごとの作り方です。

- [17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)：`any-hover` によるホバーの書き方、`:focus-visible` との対応、キーボード操作とトランジション、透明度ではなく色で表す変化
- [17-2 押せる範囲とタッチ操作](/interaction/hit-area-and-touch/)：操作する要素の最小の大きさ、余白を付ける要素、項目の間に隙間を作らない並べ方、`user-select` と `touch-action` を指定する範囲
- [17-3 状態を属性で表す](/interaction/state-attributes/)：擬似クラス、HTML要素の属性、ARIA属性、`data-*` 属性の順で選ぶ状態のセレクタ、`:focus-within` と `:has(:focus-visible)` の使い分け
- [17-4 カード全体をリンクにする](/interaction/card-link/)：見出しのリンクの `::after` を広げる方法と、フォーカスリングの出し方
- [17-5 開閉するUI](/interaction/disclosure/)：`<dialog>`、`popover` 属性、`<details>`、`hidden="until-found"` の使い分け、ドロワーの背面に付ける `inert` 属性
- [17-6 フォーム部品](/interaction/forms/)：`accent-color`、`input` 自体に描くチェックボックス、`switch` 属性、`:user-invalid`、入力欄の文字サイズ
- [17-7 CSSでカルーセルを作る](/interaction/carousel/)：スクロールスナップを土台にした `::scroll-button()` と `::scroll-marker`、隠れているスライドを外す `interactivity: inert`、自動再生をしない判断

トランジションとアニメーション、開閉するUIの出現と退場の動き、View Transitionsによる画面の切り替えは、第18章「[モーション](/motion/)」で扱います。フォーカスリングの定義、スムーススクロール、モーダル表示中の背面の固定は、ベーススタイルに書くものとして「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」で扱います。強制カラーモードでの部品の見え方は「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/)」で扱います。この章のコード例では、説明に関係しない `@layer` の記述を省略しています。デモのCSSには省略せずに書いています。

## 初めて読むとき

初めて読むときは、「[17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)」「[17-3 状態を属性で表す](/interaction/state-attributes/)」を読みます。17-4のカード全体のリンクは、第21章の「[21-6 カード全体を押せるようにする](/exercise/clickable-card/)」の前に読んでください。17-2の押せる範囲と、17-5以降の部品ごとの作り方は、その部品を作るときに読んでください。

## 最初に押さえるルール

次のルールを先に押さえ、ほかのルールは、該当する場面で付録A「[ルール一覧](/appendix/rules/)」から引けば足ります。

- [`hover-with-focus-visible`](/interaction/states-and-focus/#rule-hover-with-focus-visible)：ホバーで変える見た目は、`:focus-visible` にも同じように指定します。
- [`hover-operable-in-any-hover`](/interaction/states-and-focus/#rule-hover-operable-in-any-hover)：ホバーのスタイルは、`&:any-link:hover` や `&:enabled:hover` のように操作できる状態に限定し、`@media (any-hover)` の中に書きます。
- [`hide-panels-after-init`](/interaction/disclosure/#rule-hide-panels-after-init)：開閉するパネルは初期のHTMLでは隠さず、開閉の処理の初期化が成功してからJavaScriptで隠します。
- [`no-maximum-scale`](/interaction/forms/#rule-no-maximum-scale)：入力欄での拡大を防ぐために、`maximum-scale` や `user-scalable=no` でズームを止めません。

## この章で判断できるようになること

この章を読むと、ホバーで変える見た目をどの状態に限定し、キーボードで操作したときにどう表すかを決められるようになります。開閉するUIでは、`<dialog>`、`popover` 属性、`<details>`、`hidden="until-found"` のどれを使うかを、背面を操作できなくするか、ページ内検索で中身を見つけられるようにするかといった要件から選べます。フォーム部品やカルーセルについても、JavaScriptで作り直していた振る舞いのうち、ブラウザの機能に置き換えられるものを見分けられます。

## 次の章へ

ここまでで、操作に応じて状態を切り替え、その状態を伝えられるようになりました。切り替わる瞬間に動きを付けると変化は分かりやすくなりますが、繰り返し触るUIでは待ち時間が増え、動きを減らす設定をしているユーザーには不調の原因にもなるので、動かすかどうかは別に判断します。第18章「[モーション](/motion/)」では、動かすかどうかの判断から、出現と退場、View Transitionsまでを説明します。
