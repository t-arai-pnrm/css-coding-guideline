アニメーションを足す前に、その動きが必要かどうかを確かめます。動かすと決めたら、トランジションとアニメーションは `@media (prefers-reduced-motion: no-preference)` の中で指定します。トランジションは `transition: all` を使わず、動かすプロパティを絞ってロングハンドで書き、再生時間とイージングにはトークンを使います。

`@keyframes` はユーティリティのように設計し、1つにつき1つのプロパティだけを変えます。自明な `from` と `to` は省略し、動きの起点はカスタムプロパティで受け取ります。

## 動かす前に目的を確かめる

アニメーションは目的ではなく、手段です。状態の変化を伝える、操作の結果を返すといった目的があってはじめて、その動きに意味があります。私は、動きを足す前に次の表で判断しています。

| 目的 | 判断 | 例 |
| --- | --- | --- |
| 状態の変化の因果関係を示す | 必要 | アコーディオンの開閉、タブの切り替え |
| 新しく現れたものに注意を向ける | 必要 | トースト通知、入力エラー |
| 操作に反応を返す | 必要 | ボタンを押したときの縮小、チェックの表示 |
| 空間のつながりを保つ | 条件付き | ページ遷移のView Transitions |
| ブランドの個性を表す | 頻度の低いUIだけ | LPのヒーロー、初回の案内 |
| 見た目を華やかにするだけ | 高頻度のUIには不要 | 管理画面のカードが1枚ずつ現れる |

何度も触るUIでは、短い動きでも毎回ユーザーを待たせることになります。ユーザーが求めているのは、「すぐ反応した」と感じられる速さです。

動かすと決めたら、機能的な動きの再生時間は原則として300ms以下にし、ダイアログのような大きなUIでも500ms以下にします。イージングは、現れる動きには減速する `ease-out` 系、画面から出ていく動きには加速する `ease-in` 系、画面上にあるものの移動には `ease-in-out` 系を選びます。出ていく動きは、速度が上がりきった状態で見えなくなるので、ゆっくり終わる必要がないからです。CSSのキーワードではなく、`--ease--quint-out` や `--ease--quint-in` のようなトークンを使います。ポップオーバーは `scale: 0` からではなく、`0.95` 前後から拡大させ、`transform-origin` をトリガーの側に向けます。トークンの定義は「[7-4 デザイントークン](/components/design-tokens/)」で説明しています。

## 動きを減らす設定への対応

OSには、画面の動きを減らす設定があります。前庭障害のあるユーザーにとって、画面の大きな動きはめまいや吐き気の原因になるからです。CSSでは、この設定を `prefers-reduced-motion` メディア特性で調べられます。

本書では、トランジションとアニメーションを `@media (prefers-reduced-motion: no-preference)` の中で指定します。動きを「減らす設定のときに止める」のではなく、「設定がないときにだけ付ける」書き方です。

```css title="🙆‍♂ Recommended: 動きを減らす設定がないときだけ、トランジションを指定する"
._link {
  @media (prefers-reduced-motion: no-preference) {
    transition-duration: var(--duration--fast);
    transition-property: color;
    transition-timing-function: var(--ease--quint-out);
  }
}
```

以前の私は、動きを減らす設定のときに、全称セレクタと `!important` ですべての動きを止めていました。再生時間を0ではなく `1ms` にするのは、JavaScriptの `transitionend` イベントを発火させるための工夫です。

```css title="🙅‍♂ Not Recommended: 全称セレクタと !important で、すべての動きを止める"
/* 🙅‍♂ Not Recommended */
@media (prefers-reduced-motion: reduce) {
  *,
  ::before,
  ::after {
    transition-duration: 1ms !important;
    animation-duration: 1ms !important;
    animation-iteration-count: 1 !important;
  }
}
```

この書き方は、読み込み中を示すスピナーのように、止めてはいけない動きやサードパーティのスクリプトの動きまで、一律に止めてしまいます。動きを1つずつ条件の中に書けば、何を止めて何を残すかを動きごとに判断できます。

判断の目安は、次の4段階です。画面の3分の1以上を占める要素の移動、回転、大きな拡大や縮小、揺れる動きは「大きな変動」にあたるので、機能的な動きでも無効化するか簡素化します。

| 対応 | 内容 | 対象の例 |
| --- | --- | --- |
| 無効化 | `no-preference` の中でだけ指定する | パララックス、自動で回るカルーセル |
| 簡素化 | 移動をやめ、フェードだけにする | ページ遷移、大きなUIの出現 |
| 短縮 | 再生時間を大幅に短くする | ツールチップのフェードイン |
| 維持 | 変えない | スピナー、プログレスバー |

「維持」にあたる動きは、動きそのものが「処理中」のような情報を伝えているので、条件の外に書きます。「簡素化」と「短縮」では、位置や大きさの変化だけを条件の中へ書きます（後の `@starting-style` の例を参照）。

この設定を有効にした状態は、開発者ツールで再現できます。ChromeのDevToolsでは、Renderingパネルの `prefers-reduced-motion` のエミュレーションで `reduce` を選びます。OSの設定を切り替えずに、動きが止まったか、簡素化されたか、残すべきフェードが残っているかを確かめられます。

## トランジションの書き方

`transition: all` は、手軽ですが使いません。関係のないプロパティまでアニメーションするからです。たとえば、ブレイクポイントをまたいで余白が変わったときや、ダークモードに切り替えたときにも、要素がゆっくりと変化します。動かす必要のないプロパティまで補間するので、描画の負荷も増えます。

```css title="🙅‍♂ Not Recommended: すべてのプロパティを対象にする"
/* 🙅‍♂ Not Recommended */
._card {
  transition: all 0.3s;
}
```

トランジションは、`transition-duration`、`transition-property`、`transition-timing-function` のロングハンドで書きます。動かすプロパティが一目で分かり、再生時間とイージングにはトークンを渡せます。複数のプロパティを動かすときは、`transition-timing-function: var(--ease--quint-out), var(--ease--quint-in-out)` のように、プロパティごとにイージングを選び分けます。

動かすプロパティは、`opacity` と、`translate`、`scale`、`rotate` を優先します。これらは描画をやり直さずに合成だけで動かせるので、滑らかに動きます。`background-color` や `box-shadow` は描画のやり直しが必要ですが、ホバーの変化なら問題ありません。ただし、大きくぼかした影をループするアニメーションで動かし続けるのは避けます。ぼかしを含む影は描画に時間がかかり、動いている間は描画のやり直しが続くからです。こうした場面では、影を擬似要素に描いてその `opacity` を動かすなど、`opacity` と変形だけで表せないかを考えます。`inline-size` や `inset` のようにレイアウトが変わるプロパティは、アコーディオンの高さのように、ほかに方法のない場合に限ります。変形に個別のプロパティを使う理由は「[6-4 モダンな記法にそろえる](/notation/modern-syntax/)」で説明しています。

`will-change` は、必要のない合成レイヤーを作ってメモリを無駄に使うので、常に指定することはしません。

状態に入るときと外れるときで、再生時間を変えることもできます。トランジションは、変化したあとの状態に指定された再生時間とイージングで動きます。そのため、基本のルールに長い再生時間を、入る側の状態のルールに短い再生時間を書けば、入るときは素早く、戻るときはゆっくり動きます。反応の速さと、戻るときの自然さの両方を取れます。どちらの値もトークンから選びます。

```css title="🙆‍♂ Recommended: 押したときは素早く、戻るときはゆっくり変える"
@scope (.scoped.like-button) to (.scoped) {
  :scope {
    --_background: var(--color--accent--600);
    --_background--pressed: var(--color--accent--700);

    background-color: var(--_background);

    @media (prefers-reduced-motion: no-preference) {
      transition-duration: var(--duration--slow);
      transition-property: background-color;
      transition-timing-function: var(--ease--quint-out);
    }

    &[aria-pressed="true"] {
      --_background: var(--_background--pressed);

      @media (prefers-reduced-motion: no-preference) {
        transition-duration: var(--duration--fast);
      }
    }
  }
}
```

入る側の `transition-duration` も、動きを減らす設定の条件の中に書きます。`transition-property` の初期値は `all` なので、条件の外に再生時間だけを書くと、動きを減らす設定のときにもすべてのプロパティが動いてしまいます。

## `@keyframes` の置き場所と命名

`@keyframes` の名前はグローバルなので、置き場所と命名に決まりを作ります。サイト全体で使い回す `@keyframes` は、`base` レイヤーの1つのファイルにまとめます。そのうえで、1つの `@keyframes` には1つのプロパティの変化だけを書き、ユーティリティクラスのように組み合わせて使います。

```css title="🙆‍♂ Recommended: 1つのプロパティだけを変え、起点をカスタムプロパティで受け取る"
@keyframes --opacity-from {
  from {
    opacity: var(--opacity-from--value, 0);
  }
}

@keyframes --translate-from {
  from {
    translate: var(--translate-from--x-value, 0) var(--translate-from--y-value, 0);
  }
}

@keyframes --scale-from {
  from {
    scale: var(--scale-from--x-value, 1) var(--scale-from--y-value, 1);
  }
}
```

使う側では、`animation-name` にカンマ区切りで並べます。再生時間とイージングも、`@keyframes` ごとに選べます。起点は、`--<keyframes の名前>--<値の名前>` のカスタムプロパティで渡します。名前の先頭に `@keyframes` の名前が入っているので、内部プロパティの `--_` は付けません。

```css title="🙆‍♂ Recommended: 必要な動きを組み合わせ、起点だけを指定する"
@scope (.scoped.toast) to (.scoped) {
  :scope {
    --translate-from--y-value: 100%;

    @media (prefers-reduced-motion: no-preference) {
      animation-name: --opacity-from, --translate-from;
      animation-duration: var(--duration--base), var(--duration--slow);
      animation-timing-function: var(--ease--quint-out);
      animation-fill-mode: both;
    }
  }
}
```

`@keyframes` の `to` を書いていないのは、要素がもともと持っている値に向かって動かすためです。`from` か `to` を省略すると、その時点の要素の値が補われます。`opacity: 0.8` の要素に `--opacity-from` を使えば、0から0.8まで変化します。`to { opacity: 1; }` と書き込むと、終わった瞬間に0.8へ戻って、ちらついて見えます。同じ理由で、退場の動きでは `from` を省略します。

```css title="🙅‍♂ Not Recommended: 複数のプロパティを持ち、終わりの値を書き込んだ @keyframes"
/* 🙅‍♂ Not Recommended */
@keyframes fadeInUp {
  from {
    opacity: 0;
    translate: 0 20px;
  }

  to {
    opacity: 1;
    translate: 0 0;
  }
}
```

この `@keyframes` では、不透明度と移動のイージングを別々に選べず、フェードだけが欲しい場面では再利用できません。名前も `--` で始まっていないので、CSSのキーワードと見分けにくくなっています（「[6-1 命名規則](/notation/naming/)」）。

中間のフレームを持つ動きや、複数のプロパティを同時に動かす動きは、特定のUIに結びついています。こうした `@keyframes` はグローバルに置かず、コンポーネントのCSSに `--<コンポーネント>--<動きの名前>` の名前で定義します。たとえば、読み込み中の枠を点滅させる動きなら、`@keyframes --skeleton--pulse { 50% { opacity: 0.4; } }` のように書きます。迷ったらコンポーネントに置き、3か所で使われたらグローバルに移します。

なお、途中で中断される動きには、`@keyframes` よりトランジションが向いています。トランジションは、ホバーをすぐに外したときなどに、途中の状態から逆向きに戻るからです。

アニメーションは、略記の `animation` ではなく、ここまでの例のようにロングハンドで書きます。略記は、`animation-timeline` と `animation-range` もリセットするので、略記をあとに書くと、先に指定したスクロール駆動の設定が消えます。ロングハンドなら、指定していないプロパティに影響しません。

`animation-fill-mode` は、遅延の間と、終わったあとの見た目を決めます。指定しない（`none`）と、遅延の間は開始前の見た目のままで、終わった瞬間にもとの値へ戻ります。`backwards` は遅延の間に最初のキーフレームの値を当て、`forwards` は終わったあとも最後のキーフレームの値を保ち、`both` はその両方を行います。遅延を付けるときや、開始値を待機中にも見せたいときは、`both` を指定します。

## `@starting-style` で出現と退場を動かす

`display: none` の要素は、表示された瞬間に最終的な見た目で現れるので、これまではトランジションで動かせず、JavaScriptで1フレーム待ってからクラスを付けるような工夫が必要でした。現在は、`@starting-style` で表示されたときの開始地点を指定すれば、CSSだけで出現を動かせます。

```css title="🙆‍♂ Recommended: 開いた瞬間の見た目を @starting-style で指定する"
@scope (.scoped.notice) to (.scoped) {
  :scope {
    --_scale-from: 1;

    transform-origin: 50% 100%;
    transition-duration: var(--duration--base);
    transition-property: opacity, scale, display, overlay;
    transition-timing-function: var(--ease--quint-in);
    transition-behavior: allow-discrete;

    @media (prefers-reduced-motion: no-preference) {
      --_scale-from: 0.96;
    }
  }

  :scope:popover-open {
    transition-timing-function: var(--ease--quint-out);

    @starting-style {
      opacity: 0;
      scale: var(--_scale-from);
    }
  }

  :scope:not(:popover-open) {
    opacity: 0;
    scale: var(--_scale-from);
  }
}
```

イージングは、開くときと閉じるときで分けています。トランジションは変化したあとの状態のルールの値で動きます。閉じた状態の基本のルールには `--ease--quint-in`（加速しながら消える）を、`:popover-open` のルールには `--ease--quint-out`（減速しながら現れる）を書きます。

`transition-behavior: allow-discrete` は、`display` のように途中の値がないプロパティも、トランジションの対象にする指定です。閉じるときは、`opacity` と `scale` が終わるまで `display: none` への切り替えが待たされるので、退場も動きます。`overlay` は、閉じる途中の要素をトップレイヤーに残しておくための指定です。`@starting-style` は、開いた状態のセレクタの中に書きます。

この例では、拡大の起点だけを `no-preference` の中で変えています。動きを減らす設定のときは拡大しないので、短いフェードだけが残ります。ポップオーバーのような出現は、一瞬で切り替わるとかえって何が起きたのか分かりにくいので、位置と大きさを変えないフェードは残しています。次のデモで、ボタンを押して動きを確かめられます。

Firefoxは、2026年9月の時点で `display` のトランジションに対応していません。開くときは動きますが、閉じるときは一瞬で消えます。閉じる機能は損なわれないので、プログレッシブ・エンハンスメントとして扱えます。`overlay` に対応しているのはChrome系のブラウザだけなので、閉じる途中でほかの要素の下に潜り込まないように、`z-index: var(--z--top)` も指定しておきます（「[7-2 コンポーネントの境界を守る](/components/boundaries/)」）。

`@starting-style` の中の宣言は、特別に優先されるわけではなく、通常のカスケードでほかの規則と競い合います。同じ要素の同じプロパティに、詳細度の高い規則やインラインスタイルが値を指定していると、そちらが勝って開始値にならず、トランジションが起きません。MDNによれば、元の規則と `@starting-style` の詳細度は同じなので、上の例のように `@starting-style` を元の規則の中に書けば、ソース順で負けることもありません。`!important` や詳細度を上げるセレクタで解決することはしません（「[2-2 セレクタで詳細度を設計する](/cascade/selectors/)」）。

出現だけを動かせば足りるなら、`@keyframes` の `from` を使うほうが壊れにくくなります。アニメーションの値は、通常の宣言よりカスケードで優先されるからです。退場も動かしたいとき、つまり `display` を扱うときに、`@starting-style` を使います。

## スクロールに合わせて動かす

スクロールに合わせた動きは、目的によって作り方を選びます。スクロールの位置とともに値が連続して変わる動き（パララックスや読んだ量の表示）には、CSSのスクロール駆動アニメーションを使います。要素が画面に入ったら1回だけ動かす演出は、`IntersectionObserver` で属性を付け、CSSのアニメーションを再生して作ります。`scroll` イベントのたびに要素の位置を計算する方法は、メインスレッドを占有して動きがかくつくので使いません。

<Baseline id="scroll-driven-animations" />

スクロール駆動アニメーションは、2026年9月の時点でFirefoxが対応していません。対応していない環境では `animation-timeline` が無視され、普通のアニメーションとして一瞬で終わった状態になってしまいます。そこで、`@supports` で対応している環境に限り、さらに動きを減らす設定の条件でも囲みます。

```css title="🙆‍♂ Recommended: スクロール駆動アニメーションを、対応した環境でだけ動かす"
@keyframes --hero--parallax {
  from {
    translate: 0 -80px;
  }

  to {
    translate: 0 80px;
  }
}

@scope (.scoped.hero) to (.scoped) {
  ._background {
    @supports (animation-timeline: view()) {
      @media (prefers-reduced-motion: no-preference) {
        animation-name: --hero--parallax;
        animation-timing-function: linear;
        animation-fill-mode: both;
        animation-timeline: view();
        animation-range: cover;
      }
    }
  }
}
```

`animation-range` を指定しない（`normal`）と、範囲はタイムラインの全体になり、`view()` では、要素が画面に入り始めてから出終わるまでの全体（`cover`）に広がります。見せたいタイミングとずれやすいので、範囲は明示します。`entry` は画面に入る間、`exit` は出ていく間、`contain` は要素の全体が画面に収まっている間だけを範囲にします。範囲の前後の見た目は `animation-fill-mode` で決まるので、例では `both` を指定しています。

画面に入ったら1回だけ動かす演出では、`animation-play-state: paused` と `animation-fill-mode: both` を組み合わせます。一時停止していても、`both` によって `from` の状態が描画されるので、要素は動き始める前の位置で待機します。待機させるのは、JavaScriptがルートに `data-motion-mode="motion"` を付けたときだけです。要素が画面に入り、JavaScriptが `data-revealed` を付けたら、再生に切り替えます。

```css title="🙆‍♂ Recommended: 一時停止したアニメーションを、画面に入ったら再生する"
@scope (.scoped.feature-list) to (.scoped) {
  li {
    --translate-from--y-value: 24px;

    &:is(:scope[data-motion-mode="motion"] *) {
      @media (prefers-reduced-motion: no-preference) and (scripting: enabled) {
        animation-name: --opacity-from, --translate-from;
        animation-duration: var(--duration--slow);
        animation-timing-function: var(--ease--quint-out);
        animation-fill-mode: both;
        animation-play-state: paused;
      }
    }

    &[data-revealed]:is(:scope[data-motion-mode="motion"] *) {
      animation-play-state: running;
    }
  }
}
```

動き始める前の状態のために `opacity: 0` を別に書く必要はなく、`@keyframes` が開始地点のただひとつの情報源になります。動く前の要素を隠すのに、`visibility: hidden` や `display: none` を使わないのも大切です。スクリーンリーダーで読めなくなったり、ページ内検索で見つからなくなったりします。

待機の条件が `scripting: enabled` だけだと、スクリプトの読み込みや初期化に失敗した環境で、要素が透明のまま止まります。`data-motion-mode` は `IntersectionObserver` で監視を始めた後に付けるので、処理が途中で止まれば属性は付かず、内容はそのまま読めます（「[1-3 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」）。再生のセレクタにも同じ条件を書くのは、待機の宣言より詳細度を高くして、確実に上書きするためです。属性の付け方は、後の「JavaScriptの演出と `data-motion-mode`」で説明します。

画面に入ったら1回だけ動かす演出も、CSSだけで書ける仕様が出てきています。`timeline-trigger` で「ビュー進行タイムラインのどの範囲に入ったか」を引き金として定義し、`animation-trigger` で、その引き金が引かれたときにアニメーションを再生します。スクロール駆動アニメーションと違い、再生はスクロール量に連動しないので、スクロールを戻しても逆再生されません。ただし、2026年10月の時点で対応しているのはChrome系のブラウザ（Chrome 146以降）だけです。対応していない環境では `animation-trigger` が無視され、アニメーションは読み込んだ直後に画面の外で再生を終えてしまいます。そのため本書では、`IntersectionObserver` で属性を付ける方法を基本とし、すべてのブラウザが対応したら置き換えを検討します。

## ばねとバウンスを `linear()` で作る

`cubic-bezier()` でも、制御点のy座標を1より大きくすれば、終わりの値を1回行き過ぎてから戻る動きは表せます。しかし、1本の3次ベジェ曲線では、何度か揺れながら収まるばねの動きは表せません。`linear()` は、進み具合を点の列で与え、点の間を直線でつなぐイージング関数です。値は0から1の範囲を超えてよいので、点を多く並べれば、終わりの値の前後で何度か揺れるばねや、跳ね返るバウンスの曲線を近似できます。

点の列は手で書けないので、ジェネレーターで作ります（[MDNが紹介しているジェネレーター](https://linear-easing-generator.netlify.app/)があります）。値が長く、揺れが収まるまでの時間はイージングの作り方で決まるので、コンポーネントに直接書かず、再生時間とセットでトークンにします。

```css title="🙆‍♂ Recommended: ばねのイージングを、再生時間とセットでトークンにする"
:root {
  --duration--spring: 700ms;
  --ease--spring: linear(
    0, 0.094, 0.315, 0.581, 0.829, 1.022, 1.144, 1.199, 1.2, 1.166, 1.114,
    1.06, 1.014, 0.981, 0.963, 0.958, 0.962, 0.971, 0.982, 0.993, 1.001, 1.006,
    1.008, 1.008, 1.007, 1.005, 1.003, 1.001, 0.999, 0.998, 0.998, 0.998, 1
  );
}
```

使う側では、`--duration--spring` と `--ease--spring` を指定するだけです。次のデモでは、同じ距離を動くつまみを、`cubic-bezier()` のイージングとばねで比べられます。

ばねは、揺れが収まるまでの時間が要るので、上の例のように機能的な動きの上限（300ms）を超えます。頻繁に触るUIには使わず、数回しか触らない操作や、ブランドの個性を出したい場面に限ります。行き過ぎる動きは大きな変動にもなりやすいので、動きを減らす設定のときは条件の外に書かず、`no-preference` の中でだけ指定します。

## JavaScriptの演出と `data-motion-mode`

JavaScriptのアニメーションライブラリを使う前に、CSSで作れないかを確かめます。トランジション、アニメーション、View Transitions、スクロール駆動アニメーションで作れる動きには、ライブラリを足す必要がありません。`transform` や `opacity` の動きは合成だけで動かせるので、メインスレッドが忙しいときにも影響を受けにくいことが多く、ライブラリの読み込みと保守の負担もありません。ライブラリを使うのは、複数の要素にまたがる複雑な連動のように、CSSだけでは作れない動きに限ります。

スクロールに合わせて段落を入れ替えるような凝った演出は、そうした動きの例で、JavaScriptのアニメーションライブラリで作ることがあります。このとき、演出のためのスタイル（要素を重ねる、最初は隠しておくなど）を常に当てておくと、JavaScriptが動かない環境で内容が読めなくなります。

私は、JavaScriptがコンポーネントのルートに `data-motion-mode` を付け、演出のためのスタイルを `data-motion-mode="motion"` のときだけ当てるようにしています。JavaScriptは、動きを減らす設定がないときに `motion` を、設定があるときに `reduced` を付けます。基本のスタイルは、JavaScriptがないときと動きを減らす設定のときの、最終的な状態として書きます。演出のためのスタイルは、「[1-3 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」のルールに合わせて、`@media (scripting: enabled)` の中にも書きます。

```css title="🙆‍♂ Recommended: 演出のためのスタイルを、motion のときだけ当てる"
@scope (.scoped.story-section) to (.scoped) {
  ._steps {
    display: block grid;
    gap: 48px;

    &:is(:scope[data-motion-mode="motion"] *) {
      @media (scripting: enabled) {
        grid-template-areas: "--step";
        gap: initial;
      }
    }
  }

  ._step {
    &:is(:scope[data-motion-mode="motion"] *) {
      @media (scripting: enabled) {
        grid-area: --step;
        opacity: 0;
      }
    }
  }
}
```

```js title="data-motion-mode を付ける JavaScript の例"
const root = document.querySelector('.story-section');
const reduced = window.matchMedia('(prefers-reduced-motion: reduce)');
// 演出の準備（ライブラリの読み込みや監視の登録）が終わってから付ける
root.dataset.motionMode = reduced.matches ? 'reduced' : 'motion';
```

`scripting: enabled` の条件は、JavaScriptが有効なことしか表しません。スクリプトの読み込みに失敗したり、途中でエラーが起きたりした場合でも、条件は当てはまります。属性はJavaScriptが実際に動いたときにしか付かないので、演出の準備が整ったことを確実に表せます。動きを減らす設定のときは、要素をすぐに表示し、パララックスやスクロールに合わせた動きを止めます。どちらの状態でも、伝える情報と操作の結果は同じにします。
