アニメーションを足す前に、その動きが必要かどうかを確かめます。動かすと決めたら、トランジションとアニメーションは `@media (prefers-reduced-motion: no-preference)` の中で指定します。トランジションは `transition: all` を使わず、動かすプロパティを絞ってロングハンドで書き、再生時間とイージングにはトークンを使います。

`@keyframes` はユーティリティのように設計し、1つにつき1つのプロパティだけを変えます。自明な `from` と `to` は省略し、動きの起点はカスタムプロパティで受け取ります。この節では、これらの書き方に加えて、`@starting-style` による出現、スクロールに合わせた動き、View Transitions、JavaScriptで動かす演出の切り替え方を説明します。

## 動かす前に目的を確かめる

アニメーションは目的ではなく、手段です。状態の変化を伝える、操作の結果を返すといった目的があって初めて、動きに意味が生まれます。私は、動きを足す前に次の表で判断しています。

| 目的 | 判断 | 例 |
| --- | --- | --- |
| 状態の変化の因果関係を示す | 必要 | アコーディオンの開閉、タブの切り替え |
| 新しく現れたものに注意を向ける | 必要 | トースト通知、入力エラー |
| 操作に反応を返す | 必要 | ボタンを押したときの縮小、チェックの表示 |
| 空間のつながりを保つ | 条件付き | ページ遷移のView Transitions |
| ブランドの個性を表す | 頻度の低いUIだけ | LPのヒーロー、初回の案内 |
| 見た目を華やかにするだけ | 高頻度のUIには不要 | 管理画面のカードが1枚ずつ現れる |

何度も触るUIでは、短い動きでも毎回ユーザーを待たせることになります。ユーザーが求めているのは、「すぐ反応した」と感じられる速さです。

動かすと決めたら、機能的な動きの再生時間は原則として300ms以下にし、ダイアログのような大きなUIでも500ms以下にします。イージングは、出現と退場には `ease-out` 系、画面上にあるものの移動には `ease-in-out` 系を選び、CSSのキーワードではなく `--ease--quint-out` のようなトークンを使います。ポップオーバーは `scale: 0` からではなく、`0.95` 前後から拡大させ、`transform-origin` をトリガーの側に向けます。トークンの定義は「[6-3 デザイントークン](/components/design-tokens/)」で説明しています。

## 動きを減らす設定のときは動かさない

OSには、画面の動きを減らす設定があります。前庭障害のあるユーザーにとって、画面の大きな動きはめまいや吐き気の原因になるからです。CSSでは、この設定を `prefers-reduced-motion` メディア特性で調べられます。

本書では、トランジションとアニメーションを `@media (prefers-reduced-motion: no-preference)` の中で指定します。動きを「減らす設定のときに止める」のではなく、「設定がないときにだけ付ける」書き方です。

```css title="🙆‍♂ Recommended: 動きを減らす設定がないときだけ、トランジションを指定する"
._link {
  @media (prefers-reduced-motion: no-preference) {
    transition-duration: var(--duration--fast);
    transition-property: color;
    transition-timing-function: var(--ease--quint-out);
  }
}
```

以前の私は、動きを減らす設定のときに、全称セレクタと `!important` ですべての動きを止めていました。再生時間を0ではなく `1ms` にするのは、JavaScriptの `transitionend` イベントを発火させるための工夫です。

```css title="🙅‍♂ Not Recommended: 全称セレクタと !important で、すべての動きを止める"
/* 🙅‍♂ Not Recommended */
@media (prefers-reduced-motion: reduce) {
  *,
  ::before,
  ::after {
    transition-duration: 1ms !important;
    animation-duration: 1ms !important;
    animation-iteration-count: 1 !important;
  }
}
```

この書き方は、読み込み中を示すスピナーのように、止めてはいけない動きやサードパーティのスクリプトの動きまで、一律に止めてしまいます。動きを1つずつ条件の中に書けば、何を止めて何を残すかを動きごとに判断できます。

判断の目安は、次の4段階です。画面の3分の1以上を占める要素の移動、回転、大きな拡大や縮小、揺れる動きは「大きな変動」にあたるので、機能的な動きでも無効化するか簡素化します。

| 対応 | 内容 | 対象の例 |
| --- | --- | --- |
| 無効化 | `no-preference` の中でだけ指定する | パララックス、自動で回るカルーセル |
| 簡素化 | 移動をやめ、フェードだけにする | ページ遷移、大きなUIの出現 |
| 短縮 | 再生時間を大幅に短くする | ツールチップのフェードイン |
| 維持 | 変えない | スピナー、プログレスバー |

「維持」にあたる動きは、動きそのものが「処理中」のような情報を伝えているので、条件の外に書きます。「簡素化」と「短縮」では、位置や大きさの変化だけを条件の中へ書きます（後の `@starting-style` の例を参照）。

## トランジションは対象を絞ってロングハンドで書く

`transition: all` は、手軽ですが使いません。関係のないプロパティまでアニメーションするからです。たとえば、ブレイクポイントをまたいで余白が変わったときや、ダークモードに切り替えたときにも、要素がゆっくりと変化します。動かす必要のないプロパティまで補間するので、描画の負荷も増えます。

```css title="🙅‍♂ Not Recommended: すべてのプロパティを対象にする"
/* 🙅‍♂ Not Recommended */
._card {
  transition: all 0.3s;
}
```

トランジションは、`transition-duration`、`transition-property`、`transition-timing-function` のロングハンドで書きます。動かすプロパティが一目で分かり、再生時間とイージングにはトークンを渡せます。複数のプロパティを動かすときは、`transition-timing-function: var(--ease--quint-out), var(--ease--quint-in-out)` のように、プロパティごとにイージングを選び分けます。

動かすプロパティは、`opacity` と、`translate`、`scale`、`rotate` を優先します。これらは描画をやり直さずに合成だけで動かせるので、滑らかに動きます。`background-color` や `box-shadow` は描画のやり直しが必要ですが、ホバーの変化なら問題ありません。`inline-size` や `inset` のようにレイアウトが変わるプロパティは、アコーディオンの高さのように、ほかに方法のない場合に限ります。変形に個別のプロパティを使う理由は「[5-3 モダンな記法にそろえる](/notation/modern-syntax/)」で説明しています。

`will-change` は、必要のない合成レイヤーを作ってメモリを無駄に使うので、常に指定することはしません。

## `@keyframes` はユーティリティのように設計する

`@keyframes` の名前はグローバルなので、置き場所と命名に決まりを作ります。サイト全体で使い回す `@keyframes` は、`base` レイヤーの1つのファイルにまとめます。そのうえで、1つの `@keyframes` には1つのプロパティの変化だけを書き、ユーティリティクラスのように組み合わせて使います。

```css title="🙆‍♂ Recommended: 1つのプロパティだけを変え、起点をカスタムプロパティで受け取る"
@keyframes --opacity-from {
  from {
    opacity: var(--opacity-from--value, 0);
  }
}

@keyframes --translate-from {
  from {
    translate: var(--translate-from--x-value, 0) var(--translate-from--y-value, 0);
  }
}

@keyframes --scale-from {
  from {
    scale: var(--scale-from--x-value, 1) var(--scale-from--y-value, 1);
  }
}
```

使う側では、`animation-name` にカンマ区切りで並べます。再生時間とイージングも、`@keyframes` ごとに選べます。起点は、`--<keyframes の名前>--<値の名前>` のカスタムプロパティで渡します。名前の先頭に `@keyframes` の名前が入っているので、内部プロパティの `--_` は付けません。

```css title="🙆‍♂ Recommended: 必要な動きを組み合わせ、起点だけを指定する"
@scope (.scoped.toast) to (.scoped) {
  :scope {
    --translate-from--y-value: 100%;

    @media (prefers-reduced-motion: no-preference) {
      animation-name: --opacity-from, --translate-from;
      animation-duration: var(--duration--base), var(--duration--slow);
      animation-timing-function: var(--ease--quint-out);
      animation-fill-mode: both;
    }
  }
}
```

`@keyframes` の `to` を書いていないのは、要素がもともと持っている値に向かって動かすためです。`from` か `to` を省略すると、その時点の要素の値が補われます。`opacity: 0.8` の要素に `--opacity-from` を使えば、0から0.8まで変化します。`to { opacity: 1; }` と書き込むと、終わった瞬間に0.8へ戻って、ちらついて見えます。同じ理由で、退場の動きでは `from` を省略します。

```css title="🙅‍♂ Not Recommended: 複数のプロパティを持ち、終わりの値を書き込んだ @keyframes"
/* 🙅‍♂ Not Recommended */
@keyframes fadeInUp {
  from {
    opacity: 0;
    translate: 0 20px;
  }

  to {
    opacity: 1;
    translate: 0 0;
  }
}
```

この `@keyframes` では、不透明度と移動のイージングを別々に選べず、フェードだけが欲しい場面では再利用できません。名前も `--` で始まっていないので、CSSのキーワードと見分けにくくなっています（「[5-1 命名規則](/notation/naming/)」）。

中間のフレームを持つ動きや、複数のプロパティを同時に動かす動きは、特定のUIに結びついています。こうした `@keyframes` はグローバルに置かず、コンポーネントのCSSに `--<コンポーネント>--<動きの名前>` の名前で定義します。たとえば、読み込み中の枠を点滅させる動きなら、`@keyframes --skeleton--pulse { 50% { opacity: 0.4; } }` のように書きます。迷ったらコンポーネントに置き、3か所で使われたらグローバルに移します。

なお、途中で中断される動きには、`@keyframes` よりトランジションが向いています。トランジションは、ホバーをすぐに外したときなどに、途中の状態から逆向きに戻ってくれるからです。

## `@starting-style` で出現と退場を動かす

`display: none` の要素は、表示された瞬間に最終的な見た目で現れるので、これまではトランジションで動かせず、JavaScriptで1フレーム待ってからクラスを付けるような工夫が必要でした。現在は、`@starting-style` で表示されたときの開始地点を指定すれば、CSSだけで出現を動かせます。

```css title="🙆‍♂ Recommended: 開いた瞬間の見た目を @starting-style で指定する"
@scope (.scoped.notice) to (.scoped) {
  :scope {
    --_scale-from: 1;

    transform-origin: 50% 100%;
    transition-duration: var(--duration--base);
    transition-property: opacity, scale, display, overlay;
    transition-timing-function: var(--ease--quint-out);
    transition-behavior: allow-discrete;

    @media (prefers-reduced-motion: no-preference) {
      --_scale-from: 0.96;
    }
  }

  :scope:popover-open {
    @starting-style {
      opacity: 0;
      scale: var(--_scale-from);
    }
  }

  :scope:not(:popover-open) {
    opacity: 0;
    scale: var(--_scale-from);
  }
}
```

`transition-behavior: allow-discrete` は、`display` のように途中の値がないプロパティも、トランジションの対象にする指定です。閉じるときは、`opacity` と `scale` が終わるまで `display: none` への切り替えが待たされるので、退場も動きます。`overlay` は、閉じる途中の要素をトップレイヤーに残しておくための指定です。`@starting-style` は、開いた状態のセレクタの中に書きます。

この例では、拡大の起点だけを `no-preference` の中で変えています。動きを減らす設定のときは拡大しないので、短いフェードだけが残ります。ポップオーバーのような出現は、一瞬で切り替わるとかえって何が起きたのか分かりにくいので、位置と大きさを変えないフェードは残しています。次のデモで、ボタンを押して確かめてください。

Firefoxは、2026年9月の時点で `display` のトランジションに対応していません。開くときは動きますが、閉じるときは一瞬で消えます。閉じる機能は損なわれないので、プログレッシブ・エンハンスメントとして扱えます。`overlay` に対応しているのはChrome系のブラウザだけなので、閉じる途中でほかの要素の下に潜り込まないように、`z-index: var(--z--top)` も指定しておきます（「[6-1 コンポーネントの境界を守る](/components/boundaries/)」）。

## スクロールに合わせて動かす

スクロールに合わせた動きは、目的によって作り方を選びます。スクロールの位置とともに値が連続して変わる動き（パララックスや読んだ量の表示）には、CSSのスクロール駆動アニメーションを使います。要素が画面に入ったら1回だけ動かす演出は、`IntersectionObserver` で属性を付け、CSSのアニメーションを再生して作ります。`scroll` イベントのたびに要素の位置を計算する方法は、メインスレッドを占有して動きがかくつくので使いません。

<Baseline id="scroll-driven-animations" />

スクロール駆動アニメーションは、2026年9月の時点でFirefoxが対応していません。対応していない環境では `animation-timeline` が無視され、普通のアニメーションとして一瞬で終わった状態になってしまいます。そこで、`@supports` で対応している環境に限り、さらに動きを減らす設定の条件でも囲みます。

```css title="🙆‍♂ Recommended: スクロール駆動アニメーションを、対応した環境でだけ動かす"
@keyframes --hero--parallax {
  from {
    translate: 0 -80px;
  }

  to {
    translate: 0 80px;
  }
}

@scope (.scoped.hero) to (.scoped) {
  ._background {
    @supports (animation-timeline: view()) {
      @media (prefers-reduced-motion: no-preference) {
        animation-name: --hero--parallax;
        animation-timing-function: linear;
        animation-fill-mode: both;
        animation-timeline: view();
      }
    }
  }
}
```

画面に入ったら1回だけ動かす演出では、`animation-play-state: paused` と `animation-fill-mode: both` を組み合わせます。一時停止していても、`both` によって `from` の状態が描画されるので、要素は動き始める前の位置で待機します。JavaScriptが `data-revealed` を付けたら、再生に切り替えるだけです。

```css title="🙆‍♂ Recommended: 一時停止したアニメーションを、画面に入ったら再生する"
@scope (.scoped.feature-list) to (.scoped) {
  ._item {
    --translate-from--y-value: 24px;

    @media (prefers-reduced-motion: no-preference) and (scripting: enabled) {
      animation-name: --opacity-from, --translate-from;
      animation-duration: var(--duration--slow);
      animation-timing-function: var(--ease--quint-out);
      animation-fill-mode: both;
      animation-play-state: paused;
    }

    &[data-revealed] {
      animation-play-state: running;
    }
  }
}
```

動き始める前の状態のために `opacity: 0` を別に書く必要はなく、`@keyframes` が開始地点のただひとつの情報源になります。JavaScriptのない環境には `scripting: enabled` の条件で何も当たらないので、内容はそのまま読めます（「[1-3 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」）。動く前の要素を隠すのに、`visibility: hidden` や `display: none` を使わないのも大切です。スクリーンリーダーで読めなくなったり、ページ内検索で見つからなくなったりします。

## View Transitionsで切り替えをつなぐ

View Transitionsは、画面の状態が切り替わる前後のスナップショットを撮り、その間をアニメーションでつなぐ仕組みです。同じページの中の切り替えはJavaScriptの `document.startViewTransition()` で、ページ間の遷移はCSSの `@view-transition` で有効にします。

```css title="🙆‍♂ Recommended: ページ間の遷移を有効にし、独自の動きは条件の中で指定する"
@view-transition {
  navigation: auto;
}

@keyframes --theme-toggle--reveal {
  from {
    clip-path: inset(0 0 100% 0);
  }

  to {
    clip-path: inset(0);
  }
}

:active-view-transition-type(theme-toggle) {
  &::view-transition-old(root) {
    animation: none;
  }

  &::view-transition-new(root) {
    @media (prefers-reduced-motion: no-preference) {
      animation-name: --theme-toggle--reveal;
      animation-duration: var(--duration--slow);
      animation-timing-function: var(--ease--quint-in-out);
      animation-fill-mode: both;
    }

    @media (prefers-reduced-motion: reduce) {
      animation: none;
    }
  }
}
```

ページ間の遷移のデフォルトはクロスフェードで、位置や大きさは変わりません。そのため、`@view-transition` そのものは条件で囲まず、独自の動きだけを `no-preference` の中に書いています。この例は、テーマを切り替えるときだけ、新しい画面を上から塗り替えるように表示するものです。`clip-path` は `none` との間では補間できないので、ここでは `to` も書いています。

ページ間のView Transitionsは、Firefoxが対応していません。対応していない環境では、アニメーションせずにページが切り替わるだけなので、プログレッシブ・エンハンスメントとして使えます。

## JavaScriptの演出は `data-motion-mode` で切り替える

スクロールに合わせて段落を入れ替えるような凝った演出は、JavaScriptのアニメーションライブラリで作ることがあります。このとき、演出のためのスタイル（要素を重ねる、最初は隠しておくなど）を常に当てておくと、JavaScriptが動かない環境で内容が読めなくなります。

私は、JavaScriptがコンポーネントのルートに `data-motion-mode` を付け、演出のためのスタイルを `data-motion-mode="motion"` のときだけ当てるようにしています。JavaScriptは、動きを減らす設定がないときに `motion` を、設定があるときに `reduced` を付けます。基本のスタイルは、JavaScriptがないときと動きを減らす設定のときの、最終的な状態として書きます。

```css title="🙆‍♂ Recommended: 演出のためのスタイルを、motion のときだけ当てる"
@scope (.scoped.story-section) to (.scoped) {
  ._steps {
    display: block grid;
    gap: 48px;

    &:is(:scope[data-motion-mode="motion"] *) {
      grid-template-areas: "--step";
      gap: 0;
    }
  }

  ._step {
    &:is(:scope[data-motion-mode="motion"] *) {
      grid-area: --step;
      opacity: 0;
    }
  }
}
```

```js title="data-motion-mode を付ける JavaScript の例"
const root = document.querySelector('.story-section');
const reduced = window.matchMedia('(prefers-reduced-motion: reduce)');
root.dataset.motionMode = reduced.matches ? 'reduced' : 'motion';
```

`scripting: enabled` の条件は、JavaScriptが有効なことしか表しません。スクリプトの読み込みに失敗したり、途中でエラーが起きたりした場合でも、条件は当てはまります。属性はJavaScriptが実際に動いたときにしか付かないので、演出の準備が整ったことを確実に表せます。動きを減らす設定のときは、要素をすぐに表示し、パララックスやスクロールに合わせた動きを止めます。どちらの状態でも、伝える情報と操作の結果は同じにします。
