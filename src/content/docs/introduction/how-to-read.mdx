本書の各ページは、同じ構成と同じ約束事で書いています。このページでは、ルールの読み方、コード例のラベル、デモの操作、ブラウザの対応状況の表示を順に説明します。最初に一度目を通しておくと、どの章から読んでも迷わずに済みます。

## 節のページの構成

各節のページは、次の順番で書いています。冒頭の数段落で、その節の結論を先に示します。その後に、よくある書き方の何が問題なのかを説明し、本書の解決策を、コード例やデモと一緒に紹介します。最後に、補足や注意点を添えます。

ページの最後にある「ガイドライン」は、その節で守るべきルールの一覧です。本文を読む時間がないときは、ここだけを確認してもかまいません。ルールの背景を知りたくなったら、本文に戻って理由を確かめてください。

## ルールの強度とID

ルールには、「必須」「推奨」「非推奨」「禁止」の4段階の強度を付けています。「必須」と「禁止」は、例外なく守るルールです。「推奨」と「非推奨」は、基本的には従いますが、理由があれば外れてかまいません。外れるときは、その理由をコメントに残すのが本書の約束です。

各ルールには、`no-vw-vh` のような英語のIDを付けています。IDは章の構成が変わっても変えないので、レビューのコメントやAIへの指示で「`no-vw-vh` に違反しています」のように引用できます。すべてのルールは、付録A「[ルール一覧](/appendix/rules/)」にまとめています。

ルールによっては、「自動チェック」の欄にStylelintのルール名を書いています。本書のStylelintの設定を使えば、そのルールへの違反は機械的に見つけられます。設定の中身は「[12-1 Stylelintでルールを守る](/operations/stylelint/)」で説明します。

## コード例のラベル

コード例のタイトルには、2種類のラベルを付けています。`🙆‍♂ Recommended` は本書が勧める書き方で、`🙅‍♂ Not Recommended` は避けるべき書き方です。避けるべき書き方には、コードの先頭行にも同じラベルをコメントで入れています。コードだけを切り出して読んだときにも、悪い例だと分かるようにするためです。

```css title="🙅‍♂ Not Recommended: 物理プロパティで書く"
/* 🙅‍♂ Not Recommended */
._card {
  margin-top: 16px;
}
```

```css title="🙆‍♂ Recommended: 論理プロパティで書く"
._card {
  margin-block-start: 16px;
}
```

`🙆‍♂ Recommended` のCSSは、本書のStylelintの設定ですべて検証しています。ラベルのないコード例は、計算式だけを示す場合など、完全なCSSになっていないものです。

本文のコード例では、説明に関係しない記述を省略しています。とくにカスケードレイヤー（`@layer`）の記述は、ほとんどのコード例で省略しています。コードの一部を省略するときは、`/* ... */` と書いています。クラス名が `._title` のように `_` で始まっている場合は、`@scope` の中に書く子要素のクラスです。命名の規則は「[5-1 命名規則](/notation/naming/)」で説明します。

## デモの使い方

多くの節には、コードをその場で表示するデモがあります。デモは、ページとは切り離された枠（iframe）の中で表示しているので、デモのCSSがページに影響することはありません。枠の幅がそのままデモの画面幅になるので、メディアクエリも実際の画面と同じように動きます。

デモの上にあるボタンやスライダーで、表示の幅を変えられます。本文の幅より広い値を選ぶと、デモを横にスクロールして確認できます。デモの下のタブでは、表示に使っているCSSとHTMLを確認できます。

デモには、特に断りがない限り、本書が勧めるリセットCSS（kiso.css）と、カスケードレイヤーの順序の宣言を読み込んでいます。ブラウザのデフォルトスタイルそのものを見せたいデモでは、これらを読み込んでいません。

## ブラウザの対応状況の表示

新しい機能を紹介する箇所には、ブラウザの対応状況を示す枠を置いています。表示は、Web標準の対応データ（web-features）の「Baseline」という指標にもとづいています。「広く利用可能」はすべての主要なブラウザで長く使えている機能、「新しく利用可能」は最近すべての主要なブラウザで使えるようになった機能、「一部のブラウザのみ」はまだ一部のブラウザでしか使えない機能です。

枠には、データのバージョンと確認した年月を書いています。本書が対象にしているブラウザ（Safariは現行から2つ前のメジャーバージョンの最終版以降、ほかの主要なブラウザは最新版）と、機能ごとの使い方の判断は、「[1-3 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」で説明します。

## AIで使う

本書のルールは、AIのコーディングエージェントにも読ませられる形で配布しています。Claude Codeを使っている場合は、本書のリポジトリにあるスキル（`skills/css-coding-guideline/`）を読み込ませると、CSSを書くときやレビューするときに、本書のルールを守るようになります。スキルに含まれるルール集では、AIが誤りやすいルールを先頭に並べています。

ほかのAIツールでは、ルール集（`rules.md`）を、プロジェクトの `AGENTS.md` や `CLAUDE.md` から参照させてください。AIへの指示でルールのIDを使うと、どのルールに従ってほしいのかを正確に伝えられます。詳しい使い方は「[12-2 レビューとAIとの協働](/operations/review-and-ai/)」で説明します。
