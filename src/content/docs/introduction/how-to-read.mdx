本書の節のページは、共通の基本の構成と約束事で書いています。このページでは、ページの構成、初めて読むときの順番、ルールの読み方、コード例のラベル、デモの操作、ブラウザの対応状況の表示、AIでの使い方を順に説明します。先に一度読んでおくと、どの章から読み始めても表記に迷いません。

## 節のページの構成

節のページは、冒頭の数段落でその節の結論を先に示し、最後に「ガイドライン」と「参考リンク」を置くという基本の構成を持っています。その間の進め方は、節の題材に合わせて選んでいます。コード例とデモは、説明する見出しの直下に置いています。

仕組みを理解する節は、実際に起きる表示から始め、どう表示されるかを予測したうえで仕組みを説明し、デモで確かめます。手法を選ぶ節は、満たしたい要件を挙げ、選択肢を比べてから、どれを選ぶかの判断を示します。実装する節は、完成形を先に見せ、組み立ての手順と表示の検証を経て、注意点を添えます。本書独自の規約を導入する節は、目的、約束の中身、例外、チームでの運用の順に書き、採用したときに増える手間も示します。このほか、よくある書き方の問題点から本書の解決策へ進む節もあります。

ページの最後にある「ガイドライン」は、その節で守るべきルールの一覧です。時間がないときは、ここだけを確認してもかまいません。ルールの理由を知りたいときは、本文に戻ってください。ただし、第I部でCSSや設計の考え方を述べる節にはルールを置いていないので、「ガイドライン」もありません。

第21章の演習の節は、別の形で進みます。各節で部品を作ったあと、途中で要件を1つ変え、直す場所を予想してから解説を読み、最後に判断を問う問題と答えで振り返ります。演習では新しいルールを置かず、「ガイドライン」の代わりに、その節で使ったルールを掲載ページへのリンク付きで並べています。

## ルールの強度と性質、ID

ルールには、「必須」「推奨」「非推奨」「禁止」の4段階の強度を付けています。「必須」と「禁止」は、各ルールの補足に書いた適用範囲と例外を除き、必ず守るルールです。補足の例外に当たるコードは違反ではないので、レビューやAIのチェックで指摘しません。「推奨」と「非推奨」は、基本的には従いますが、理由があれば外れてかまいません。外れるときは、その理由をコメントに残します。

強度とは別に、ルールの根拠がどこにあるかを「性質」として示しています。「仕様上の制約」は、CSS・HTML・ブラウザの振る舞いやWCAGから導かれるルールで、守らないと表示や操作が崩れます。「実装上の判断」は、状況とトレードオフで決まるルールです。適用する条件は、補足や本文に書いています。「本書の規約」は、命名やレイヤーの順番のように、一貫性のために本書が選んだ約束です。自分の案件に持ち帰るときは、仕様上の制約はそのまま使い、実装上の判断は条件が合うかを確かめ、本書の規約はチームの規約と見比べて選んでください。

各ルールには、`no-vw-vh` のような英語のIDを付けています。IDは章の構成が変わっても変えないので、レビューのコメントやAIへの指示で「`no-vw-vh` に違反しています」のように引用できます。すべてのルールは、付録A「[ルール一覧](/appendix/rules/)」にまとめています。

ルールによっては、「自動チェック」の欄にStylelintのルール名を書いています。本書のStylelintの設定を使えば、そのルールへの違反は機械的に見つけられます。設定の中身は「[19-1 Stylelintでルールを守る](/operations/stylelint/)」で説明します。

## コード例のラベル

コード例のタイトルには、2種類のラベルを付けています。`🙆‍♂ Recommended` は本書が勧める書き方で、`🙅‍♂ Not Recommended` は避けるべき書き方です。避けるべき書き方には、コードの先頭行にも同じラベルをコメントで入れています。コードだけを切り出して読んだときにも、避けるべき例だと分かるようにするためです。

`🙅‍♂ Not Recommended` には、表示や操作が崩れる書き方と、正しく動くものの本書の規約と異なる書き方の2種類があります。どちらに当たるかは、ラベルの後ろの説明と本文に書いています。次の物理プロパティの例は後者で、横書きのページでは正しく表示されます。本書では、書字方向が変わっても同じ意味になるように論理プロパティにそろえているので、避ける例にしています。

```css title="🙅‍♂ Not Recommended: 物理プロパティで書く"
/* 🙅‍♂ Not Recommended */
._card {
  padding-top: 16px;
}
```

```css title="🙆‍♂ Recommended: 論理プロパティで書く"
._card {
  padding-block-start: 16px;
}
```

`🙆‍♂ Recommended` のCSSは、本書のStylelintの設定ですべて検証しています。ただし、Stylelintが確かめるのは記法と規約の一部で、表示や操作が正しいかまでは確かめません。表示と操作は、「[19-3 表示と操作を確かめる](/operations/verification/)」の手順に沿ってブラウザで確かめます。ラベルのないコード例は、勧めるかどうかを示すためではなく、仕組みや計算式を示すための例です。完全なCSSのものも、一部だけを抜き出したものもあります。

本文のコード例では、説明に関係しない記述を省略しています。とくにカスケードレイヤー（`@layer`）の記述は、ほとんどのコード例で省略しています。省略した箇所は `/* ... */` と書いています。クラス名が `._main-link` のように `_` で始まっている場合は、`@scope` の中に書く子要素のクラスです。命名の規則は「[9-1 命名規則](/notation/naming/)」で説明します。

省略した記述をそろえた全体の形は、「[最小の構成で始める](/introduction/quick-start/)」に1枚のカードを例にして示しています。その構成で定義しているトークンは、そのカードに必要な最小限のものだけです。本文のコード例を手元で試すときは、その構成のコンポーネントのファイルに貼り付け、コード例が参照するトークンを足してください。色や余白、イージングと再生時間のトークンは「[10-4 デザイントークン](/components/design-tokens/)」で定義しています。

## デモの使い方

多くの節には、コードをその場で表示するデモがあります。デモは、ページとは切り離された枠（iframe）の中で表示しているので、デモのCSSがページに影響することはありません。枠の幅がそのままデモの画面幅になるので、メディアクエリも実際の画面と同じように動きます。

本文は、デモを操作しなくても結論が分かるように書いています。表示が幅で変わるデモについては、「幅を320pxにすると」「768pxのときは」のように、どの幅で何が変わるかを本文に書いています。操作で状態が変わるデモについては、何をすると、どこがどう変わるかを書いています。

Webでは、デモの上にあるボタンやスライダーで表示の幅を変えられます。本文の幅より広い値を選ぶと、デモを横にスクロールして確認できます。デモの下のタブでは、表示に使っているCSSとHTMLの全体を確認できます。

紙の書籍では、一部のデモを静止図で示し、ほかのデモは番号と補足サイトへの参照だけを載せます。静止図には撮った幅（320pxなど）を添えているので、本文の「幅を320pxにすると」は、その幅の図と対応します。紙面にない幅や、押す・動かすといった操作による変化は、[補足サイト](/book-support/index.html)からたどれるWeb版のデモで確かめてください。デモのCSSとHTMLの全体は、補足サイトのサンプル一式にも入っています。

デモには、特に断りがない限り、本書が勧めるリセットCSS（kiso.css）とカスケードレイヤーの順序の宣言を読み込んでいます。ブラウザのデフォルトスタイルそのものを見せるデモでは、これらを読み込んでいません。

## ブラウザの対応状況の表示

新しい機能を紹介する箇所には、ブラウザの対応状況を示す枠を置いています。表示は、Web標準の対応データ（web-features）の「Baseline」という指標にもとづいています。「広く利用可能」はすべての主要なブラウザで長く使えている機能、「新しく利用可能」は最近すべての主要なブラウザで使えるようになった機能、「一部のブラウザのみ」はまだ一部のブラウザでしか使えない機能です。

枠には、データのバージョンと確認した年月を書いています。本書が対象にしているブラウザ（Safariは現行から2つ前のメジャーバージョンの最終版以降、ほかの主要なブラウザは最新版）と、機能ごとの使い方の判断は、「[1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」で説明します。

## AIで使う

本書のルールは、AIのコーディングエージェントにも読ませられる形で提供する予定です。{/* 要確認: 著者の判断。配布物の提供を始めたら、次の文を消し、前の文を「配布しています」に戻す */}スキル、MCPサーバー、プラグインは、提供に向けて対応中のため、まだ利用できません（2026年10月時点）。提供を始めた後は、スキルとMCPサーバーを入れれば、CSSを書くときやレビューするときに、本書のルールを規約として指示できます。提供の状況と、ツールごとの設定方法は、付録J「[AIツールで使う](/appendix/ai-tools/)」にまとめています。

ただし、スキルを読み込ませても、生成されたCSSがルールに沿うとは限りません。出力は、Stylelintとレビューで確かめる必要があります。AIへの指示でルールのIDを使うと、どのルールに従ってほしいのかを正確に伝えられます。生成されたコードの確かめ方は「[20-8 生成したコードを確かめ、教訓を残す](/ai-coding/verify-output/)」で説明します。
