単位は、「ユーザーの設定や画面の大きさが変わったとき、その値にどう振る舞ってほしいか」で選びます。計算して決まる値は、結果ではなく式で書きます。

同じ16pxの大きさでも、`16px`、`1rem`、`1em`、`4svi` では、ユーザーが文字サイズの設定を変えたときや、画面の幅が変わったときの振る舞いがまったく違います。そのため、単位を選ぶことは、見た目の数値を決めることではなく、変化への応じ方を決めることになります。

私自身、以前は「pxとremはどちらでもよく、迷ったらremを使えばいい」と考えていました。スマートフォン向けの表示では、デザインカンプの比率を保つために `vw` を使っていた時期もあります。しかし、ズームと文字サイズの設定の違いや、モバイルのブラウザのUIとビューポートの関係を知るにつれて、単位ごとに理由を持って選ぶように変わりました。ジェネレーターで作った `clamp()` の値がマジックナンバーになりやすいことから、計算の式を残すことも大事にしています。

この章のルールのうち、`vw` や `vh` の使用と、単位の付いた `line-height` は、本書のStylelintの設定で検出できます。一方で、pxとremのどちらを選ぶかや、`clamp()` の推奨値の根拠は、ツールでは判断できません。コードを書く人が、値ごとに理由を持って選ぶ必要があります。

この章は次の4つの節で構成しています。

- [4-1 pxとremを使い分ける](/values/px-and-rem/)：文字サイズの設定に追従させるかどうかで単位を選ぶ基準と、remへの変換の式、単位のない `line-height`
- [4-2 ビューポート単位とコンテナ単位](/values/viewport-and-container-units/)：`vw` と `vh` を使わない理由と、`svi`・`svb`・`dvb`・`lvb` の選び方、`cqi` との使い分け
- [4-3 計算関数で根拠を式に残す](/values/math-functions/)：`calc()`、`min()`、`max()`、`clamp()` で値の根拠を残す書き方と、流体的な値の組み立て方
- [4-4 if()とattr()で条件と属性を値にする](/values/if-and-attr/)：型付きの `attr()` でHTMLの属性値を読む書き方と、`if()` を使う場面、未対応の環境へのフォールバック

ブレイクポイントの単位とコンテナクエリの書き方は第12章「[レスポンシブデザイン](/responsive/)」で、トークンの命名は第8章「[コンポーネントとカスタムプロパティ](/components/)」で扱います。見出しや本文の文字サイズと行の高さの具体的な値は、[第13章「タイポグラフィと和文組版」](/typography/)で説明します。この章のコード例では、説明に関係しない `@layer` の記述を省略しています。

## 最初に押さえるルール

{/* 要確認: 著者の優先順位で選び直す（レビューの提案にもとづく下書き） */}

次のルールを先に押さえ、ほかのルールは、該当する場面で付録A「[ルール一覧](/appendix/rules/)」から引けば足ります。

- [`font-size-in-rem`](/values/px-and-rem/#rule-font-size-in-rem)：`font-size` はremで指定し、pxを使いません（要素の文字サイズに比例させるならem）。
- [`no-root-font-size-change`](/values/px-and-rem/#rule-no-root-font-size-change)：`html { font-size: 62.5% }` などで、remの計算を簡単にする目的でルートの文字サイズを変えません。
- [`unitless-line-height`](/values/px-and-rem/#rule-unitless-line-height)：`line-height` は単位のない数値で指定します。
- [`no-vw-vh`](/values/viewport-and-container-units/#rule-no-vw-vh)：`vw`、`vh`、`vi`、`vb`、`vmin`、`vmax` は使いません。
- [`clamp-rem-bounds`](/values/math-functions/#rule-clamp-rem-bounds)：文字サイズを `clamp()` で書くときは、最小値と最大値をremにし、推奨値をremと相対単位の和にします。
