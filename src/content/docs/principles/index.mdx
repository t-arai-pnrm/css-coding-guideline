この章では、本書のすべてのルールの土台になる、CSSの捉え方を扱います。CSSは、プロパティと値を書けば思いどおりに動く言語ではありません。最終的な表示を決めるのはユーザーの環境とブラウザで、同じプロパティもレイアウトの方式によって働き方が変わります。JavaScriptと同じ感覚で表示をすべて制御しようとするほど、CSSは思いどおりにならない言語だと感じられます。

そこで本書では、2つの考え方を前提にしています。1つ目は、CSSをブラウザへの命令ではなく「提案」として書くことです。2つ目は、対象のブラウザをはっきり決め、そのブラウザが未対応の新しい機能は、プログレッシブ・エンハンスメントとして使うことです。

以降の章に出てくるルールの多くは、この2つのどちらかと、第2章で扱う保守しやすさから導かれています。たとえば「幅を固定しない」はブラウザに計算を任せるためで、「未対応の機能をレイアウトの要にしない」はどの環境でも内容を読めるようにするためです。個々のルールの扱いに迷ったときは、この章の考え方に戻って判断します。

私自身、以前は「デザインカンプを忠実に再現するのは実装者として当たり前」と考えていました。しかし、ユーザーの画面の幅や文字サイズの設定は無数にあり、カンプと同じ見た目を、すべての環境で保証するのは不可能です。今は、限られた環境で見た目を一致させるよりも、どの環境でも破綻しない状態を用意するほうが大切だと考えています。

この章は次の7つの節で構成しています。1-1と1-2は本書のルールの前提になるCSSの捉え方と方針、1-3はレイアウトの捉え方、1-4〜1-7はCSSを学ぶうえで大切なことです。

- [1-1 CSSはブラウザへの「提案」である](/principles/browser-suggestion/)：固定値ではなく制約で考え、計算はブラウザに任せる理由と、ピクセルパーフェクトではなく合格点を目指す考え方
- [1-2 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)：Safariを基準にした対象範囲、プログレッシブ・エンハンスメントとして使える機能の見分け方、`@supports` と `scripting` メディア特性の使い方
- [1-3 CSSはレイアウトのアルゴリズムの集まりである](/principles/layout-algorithms/)：同じプロパティでもレイアウトの方式によって働き方が変わる理由と、指定が効かないときに方式から確かめる考え方
- [1-4 基礎を固める](/principles/fundamentals/)：Tailwind CSSやAIを使っても基礎が要る理由と、一次情報を読み、手を動かして学ぶこと
- [1-5 解決策を丸暗記しない](/principles/no-memorizing/)：画像の下にできる隙間を例に、問題の原因と解決策が効く理由を確かめること
- [1-6 Tipsとの付き合い方](/principles/tips/)：SNSで見かけたTipsを、仕様とブラウザの対応状況で確かめてから使うこと
- [1-7 選択肢を多く持つ](/principles/options/)：中央寄せやカードの並べ方を例に、文脈から方法を選ぶこと

この章と同じ第I部には、CSSを書くときの判断と保守しやすさを扱う第2章「[CSS設計の考え方](/design-mindset/)」と、デザインカンプに向き合う姿勢を扱う第3章「[デザインを再現する](/design-reproduction/)」を置いています。

固定値を避けてブラウザに任せる具体的な方法は、[第13章「レスポンシブデザイン」](/responsive/)で扱います。レイアウトの方式ごとの規則は[第7章「レイアウトの仕組み」](/layout/)で、レビューとAIとの協働は「[19-2 レビューとAIとの協働](/operations/review-and-ai/)」で扱います。

## 最初に押さえるルール

{/* 要確認: 著者の優先順位で選び直す（レビューの提案にもとづく下書き） */}

次のルールを先に押さえ、ほかのルールは、該当する場面で付録A「[ルール一覧](/appendix/rules/)」から引けば足ります。

- [`scripting-for-js-dependent-styles`](/principles/browser-support/#rule-scripting-for-js-dependent-styles)：JavaScriptで表示を切り替える前提の隠す指定は、`@media (scripting: enabled)` と、初期化が成功したら付く属性を条件にして書きます。
- [`progressive-enhancement-if-harmless`](/principles/browser-support/#rule-progressive-enhancement-if-harmless)：対象のブラウザの一部しか対応していない機能は、未対応の環境でも内容を読めて操作できる場合に限って使います。
- [`no-unsupported-layout-features`](/principles/browser-support/#rule-no-unsupported-layout-features)：対象のブラウザの一部が対応していないレイアウトの機能を、レイアウトの要にしません。
- [`no-chrome-only-check`](/principles/browser-support/#rule-no-chrome-only-check)：表示はChromeだけでなく、Safari（iOSを含む）とFirefoxでも確かめます。
