この章では、本書のすべてのルールの土台になる考え方を扱います。1つ目は、CSSをブラウザへの命令ではなく「提案」として書くことです。2つ目は、コードの短さや共通化よりも、保守しやすさを優先することです。3つ目は、対象のブラウザをはっきり決め、そのブラウザが未対応の新しい機能は、プログレッシブ・エンハンスメントとして使うことです。

以降の章に出てくるルールの多くは、この3つのどれかから導かれています。たとえば「幅を固定しない」はブラウザに計算を任せるためで、「何にでも `width: 100%` を書かない」は余計な記述が保守の妨げになるためです。個々のルールの扱いに迷ったときは、この章の考え方に戻って判断します。

私自身、以前は「デザインカンプを忠実に再現するのは実装者として当たり前」と考えていました。しかし、ユーザーの画面の幅や文字サイズの設定は無数にあり、カンプと同じ見た目を、すべての環境で保証するのは不可能です。今は、限られた環境で見た目を一致させるよりも、どの環境でも破綻しない状態を用意するほうが大切だと考えています。

もうひとつの背景は、Webサイトの寿命です。Webサイトは公開したときが始まりで、その後の更新や改修の期間のほうがずっと長く続きます。どれだけ丁寧に組んだCSSも、運用の中で少しずつ劣化していきます。そのため本書では、書いた本人以外が触っても壊れにくいことを最も重視しています。

この章は次の3つの節で構成しています。

- [1-1 CSSはブラウザへの「提案」である](/principles/browser-suggestion/)：固定値ではなく制約で考え、計算はブラウザに任せる理由と、ピクセルパーフェクトではなく合格点を目指す考え方
- [1-2 保守しやすさを最優先にする](/principles/maintainability/)：重複を恐れず共通化は3回目から考えることと、`width: 100%`、デフォルト値の指定し直し、副作用のあるショートハンドといった不要な記述をしないこと
- [1-3 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)：Safariを基準にした対象範囲、プログレッシブ・エンハンスメントとして使える機能の見分け方、`@supports` と `scripting` メディア特性の使い方

固定値を避けてブラウザに任せる具体的な方法は、[第9章「レスポンシブデザイン」](/responsive/)で扱います。共通化の単位になるコンポーネントとコンポジションは[第7章「コンポーネントとカスタムプロパティ」](/components/)で、上書きの仕組みは[第2章「カスケードを制御する」](/cascade/)で説明します。想定外の内容に備えるディフェンシブCSSは「[8-10 変化に強いレイアウト](/layout/defensive/)」で、レビューとAIとの協働は「[14-2 レビューとAIとの協働](/operations/review-and-ai/)」で扱います。

## 最初に押さえるルール

{/* 要確認: 著者の優先順位で選び直す（レビューの提案にもとづく下書き） */}

次のルールを先に押さえ、ほかのルールは、該当する場面で付録A「[ルール一覧](/appendix/rules/)」から引けば足ります。

- [`scripting-for-js-dependent-styles`](/principles/browser-support/#rule-scripting-for-js-dependent-styles)：JavaScriptで表示を切り替える前提の隠す指定は、`@media (scripting: enabled)` と、初期化が成功したら付く属性を条件にして書きます。
- [`progressive-enhancement-if-harmless`](/principles/browser-support/#rule-progressive-enhancement-if-harmless)：対象のブラウザの一部しか対応していない機能は、未対応の環境でも内容を読めて操作できる場合に限って使います。
- [`no-unsupported-layout-features`](/principles/browser-support/#rule-no-unsupported-layout-features)：対象のブラウザの一部が対応していないレイアウトの機能を、レイアウトの要にしません。
- [`no-chrome-only-check`](/principles/browser-support/#rule-no-chrome-only-check)：表示はChromeだけでなく、Safari（iOSを含む）とFirefoxでも確かめます。
- [`no-redundant-width-100`](/principles/maintainability/#rule-no-redundant-width-100)：ブロックレベルの要素や `inset: 0` で広げた絶対配置の要素に、`width: 100%` を書きません。
