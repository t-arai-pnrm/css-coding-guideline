数量クエリ（quantity queries）は、子要素の数に応じてスタイルを切り替える手法の総称です。専用の構文があるわけではなく、子要素の位置で選ぶ擬似クラスを組み合わせて「3つ以上ある」「ちょうど1つだけ」といった条件を表します。本書では、`&:has(> :nth-child(3))` のように親を起点にした `:has()` で書きます。

ただし、数量クエリを使う場面は限ります。列数のようなレイアウトの切り替えは、まず `auto-fit` やコンテナクエリで行います。数量クエリを使うのは、「1件だけなら中央に置く」のように、子要素の数そのものが条件になるときだけです。この節では、数え方の式、従来の書き方との違い、使いどころの見分け方を順に説明します。

## 件数によって見た目を変えたい場面

お知らせや関連記事の一覧は、CMSの登録状況によって件数が変わります。3件や6件のときに整って見えるカードの一覧も、1件だけになると、カードが行いっぱいに引き伸ばされたり、左端に1枚だけ残ったりします。件数が少ないときだけ並べ方を変えたい、という要望は珍しくないでしょう。

CSSのセレクタには、子要素の数を直接表す仕組みがありません。そのため、テンプレートの側で件数を数え、`is-single` や `has-3-items` のようなクラスを親に付けて出し分けることがよくありました。JavaScriptで描画する一覧なら、項目を追加したり削除したりするたびに、クラスを付け直す処理も必要です。

この方法では、クラスと実際の件数は、ずれることがあります。項目を絞り込む機能を後から足したときに、クラスを更新する処理を書き漏らすと、見た目が件数と合わなくなります。件数という情報が、DOMの構造とクラスの2か所に分かれているからです。数量クエリを使えば、DOMの構造だけを条件にして、件数による切り替えをCSSの中で完結できます。

## `:nth-last-child()` で数える従来の書き方

数量クエリは、`:has()` が使えるようになる前から知られていました。代表的な記事は、2015年、A List Apartに掲載されたHeydon Pickeringの「Quantity Queries for CSS」です。子要素の位置で選ぶ擬似クラスだけで、「3つ以上ある」を次のように書きます。

```css title="🙅‍♂ Not Recommended: 子の側で数える"
/* 🙅‍♂ Not Recommended */
li:nth-last-child(n + 3),
li:nth-last-child(n + 3) ~ li {
  /* 3つ以上あるときの、すべての li */
  flex-basis: 30%;
}
```

`li:nth-last-child(n + 3)` は、後ろから数えて3番目以降の `li`、つまり後ろに2つ以上の兄弟が続く `li` を選びます。そうした `li` が存在するのは、全体が3つ以上あるときだけです。当てはまった `li` より後ろの兄弟は `~ li` で拾い、全体として「3つ以上あるときの、すべての `li`」を選びます。ちょうど3つのときは、`li:first-child:nth-last-child(3)` と、その後ろの兄弟を組にします。

この書き方には限界があります。選ばれるのは子要素なので、親の `grid-template-columns` や `justify-content` のように、親に書くべき指定は切り替えられません。条件を表すのにセレクタを2つ組にする必要があり、「後ろから数えてN番目以降があるなら、全体はN個以上ある」という逆算を読み手がしなければ、意味も取れません。

`:has()` を使うと、同じ条件を親から直接書けます。`&:has(> :nth-child(3))` は「3番目の子を持つ親」、つまり子が3つ以上ある親です。スタイルが当たるのは親なので、親自身のレイアウトを変えられます。子のスタイルを変えたいときも、親でカスタムプロパティの値を切り替えれば、条件の判定は1か所で済みます。

## `:has()` で子要素を数える式

数量クエリの式は、次の4つの形でほとんどの条件を表せます。どれも、親（`&`）を起点にし、`>` で直接の子に絞ります。

```css title="数量クエリの4つの形（3つを例に）"
@scope (.scoped.item-list) to (.scoped) {
  :scope {
    /* ちょうど3つ */
    &:has(> :nth-child(3):last-child) {
      /* ... */
    }

    /* 3つ以上 */
    &:has(> :nth-child(3)) {
      /* ... */
    }

    /* 3つ以下（0個は含まない） */
    &:has(> :last-child:nth-child(-n + 3)) {
      /* ... */
    }

    /* 2〜4つ */
    &:has(> :nth-child(2)):not(:has(> :nth-child(5))) {
      /* ... */
    }
  }
}
```

「ちょうど3つ」は、3番目の子が最後の子でもある、という条件です。「3つ以上」は、3番目の子が存在する、という条件で、最後の子かどうかを問いません。「3つ以下」は、最後の子が先頭から3番目以内にある、という条件です。`:nth-child(-n + 3)` は1番目から3番目までに当てはまるので、`:last-child` と組み合わせると、子の数が3以下のときだけ当てはまります。

範囲の条件は、「N個以上」と「M＋1個以上ではない」を組み合わせます。2〜4つなら、「2番目の子がある」かつ「5番目の子がない」です。`:not()` の中に `:has()` を入れる形は、「[3-2 :has() で祖先と前の兄弟を選ぶ](/pseudo/has/)」で説明した「持たない」の書き方と同じです。上の4つの式は、2026年10月にChromeで、子が0〜6個の場合について当てはまり方を確認しました。

「3つ以下」の式は、子が0個のときには当てはまりません。最後の子が存在しないからです。0個も含めたいときは、`&:not(:has(> :nth-child(4)))` のように「4番目の子がない」と書きます。また、子が1つだけの条件は、`&:has(> :nth-child(1):last-child)` と書くより、同じ意味の `&:has(> :only-child)` のほうが読みやすくなります。

数える対象を絞りたいときは、`:nth-child()` の `of S` 構文を使います。`&:has(> :nth-child(3 of :not([hidden])))` は、`hidden` 属性の付いていない子だけを数えます。`An+B` の数え方と `of S` 構文の詳細は、「[3-3 子要素の位置で選ぶ](/pseudo/child-index/)」で説明しています。

## 起点と `>` を省かない

数量クエリでも、起点のない `:has()` は書きません。`:has(> :nth-child(3))` とだけ書くと、ページのすべての要素が起点になり、DOMが変わるたびに、ブラウザの調べ直す範囲が広がります。ネストしたルールの中では、必ず `&` から書き始めます。起点のない `:has()` を禁止する理由と、それを検出するStylelintのルールは、「[3-2 :has() で祖先と前の兄弟を選ぶ](/pseudo/has/)」で説明しています。

引数の `>` も省けません。`&:has(:nth-child(3))` は、直下の3番目の子ではなく、「子孫のどこかにある、自分の親から見て3番目の要素」を探します。一覧の項目の中に、子要素を3つ以上持つものが1つでもあれば、項目が1つしかなくても当てはまります。子要素の数を数えたいのは親の直下だけなので、`>` で範囲を絞ります。

```css title="🙅‍♂ Not Recommended: > を省いて、孫の位置の要素も数える"
/* 🙅‍♂ Not Recommended */
.item-list:has(:nth-child(3)) {
  /* 項目の中に3つ目の子要素があるだけで当てはまる */
  justify-content: center;
}
```

`>` で絞ると、調べる範囲も親の直下の子に収まります。項目の中身がどれだけ大きくても、照合する要素の数は項目の数で決まります。

## 列数は幅で、件数は数量クエリで

数量クエリを覚えると、列数の切り替えにも使いたくなります。たとえば、項目が2つなら2列、3つ以上なら3列にする、という指定です。項目の数だけを見れば、すべての項目が1行に並ぶので、整って見えます。

```css title="🙅‍♂ Not Recommended: 件数で列数を決める"
/* 🙅‍♂ Not Recommended */
.pickup-list {
  display: block grid;
}

.pickup-list:has(> :nth-child(2)) {
  grid-template-columns: repeat(2, minmax(0, 1fr));
}

.pickup-list:has(> :nth-child(3)) {
  grid-template-columns: repeat(3, minmax(0, 1fr));
}
```

この指定は、一覧が使える幅を考えていません。同じ一覧をサイドバーのような狭い場所に置くと、3件あれば3列のまま、1列あたりの幅が数十pxまで縮みます。列数を決める本当の条件は、項目の数ではなく、項目を何列並べられるだけの幅があるかです。{/* 要確認: 出典なし */}項目の数を条件にすると、その数で並べられる幅がある、という前提が暗黙のうちに入り込みます。

列数は、`repeat()` の `auto-fit` と `minmax()` に任せます。`auto-fit` は列の最小幅を下回らない範囲で列を作り、項目のない列を幅0に畳むので、項目が2つなら2列に広がり、3つなら3列に並びます。幅が足りなければ列は減ります。「2件なら2列」という要望は、数量クエリを使わずに満たせます。`auto-fit` と `auto-fill` の違いは第9章「[9-1 検討する順番](/responsive/escalation/)」と第8章「[8-5 Gridの基礎](/layout/grid-basics/)」で、置かれた場所の幅で配置を組み替える方法は第9章「[9-2 コンテナクエリ](/responsive/container-queries/)」で説明しています。

一方、`auto-fit` でも解決できないのが、項目が1つだけの場合です。`auto-fit` は残った1つの項目を行いっぱいに広げ、`auto-fill` は1列分の幅のまま行の先頭に寄せます。「1件だけなら1列分の幅で中央に置く」という指定は、幅ではなく件数そのものが条件なので、数量クエリの出番です。投稿に添える画像の並べ方（1枚なら大きく、2枚なら左右に、4枚なら2行2列に）のように、件数ごとに型が決まっている場合も同じです。

## コード例とデモ

次のデモは、同じピックアップの一覧に、項目を1件、2件、3件、5件入れて並べたものです。列の数は幅から決まり、最小幅は200px相当、多くても3列までにしています。項目が1件のときだけ、数量クエリで列の幅を400px相当に固定し、中央に置いています。

```css title="🙆‍♂ Recommended: 列数は幅で決め、1件のときだけ数量クエリで中央に置く"
@scope (.scoped.pickup-list) to (.scoped) {
  :scope {
    display: block grid;
    grid-template-columns: repeat(auto-fit, minmax(min(100%, calc(200 / 16 * 1rem)), 1fr));
    gap: 16px;

    &:has(> :only-child) {
      grid-template-columns: minmax(0, calc(400 / 16 * 1rem));
      justify-content: center;
    }
  }
}
```

<Demo title="列数は幅で決まり、項目が1件のときだけ中央に置かれる一覧" html={pickupHtml} css={pickupCss} />

幅のボタンで1024pxを選ぶと、2件の一覧は2列に、3件と5件の一覧は3列に並びます。2件の一覧が2列いっぱいに広がるのは、`auto-fit` が3列目を畳んでいるからで、数量クエリは関わっていません。320pxにすると、どの一覧も1列になります。1件の一覧は、どの幅でも400px相当を超えず、中央に置かれます。

デモの `grid-template-columns` には、列の最大数を3に抑える計算を加えています。要素の幅から列の間隔を引いて3で割った値と、列の最小幅の大きいほうを列の最小幅にする方法で、第8章「[8-13-6 grid](/layout/compositions/grid/)」の `grid` と同じ考え方です。コード例では、この計算を省いています。

## 補足と注意点

数量クエリの詳細度は、`:has()` の引数の分だけ上がります。`:scope` の中で `&:has(> :only-child)` と書くと、`:scope`（0.1.0）に `:only-child`（0.1.0）が加わり、0.2.0になります。基本のスタイルを書いた `:scope`（0.1.0）より詳細度が高いので、書く順序によらず上書きできます。

数えるのは要素だけです。テキストノードやコメントは数えず、`::before` などの擬似要素も子に含みません。一方、`hidden` 属性や `display: none` で見えなくなった要素は、DOMにある限り数えられます。絞り込みによって項目を隠す一覧では、見えている項目の数を条件にしたいことが多いので、「`:has()` で子要素を数える式」で説明した `of S` 構文を使い、数える対象を絞ります。

数量クエリの条件は、子要素の並びが変わるとその場で判定し直されます。JavaScriptで項目を追加したり削除したりしても、クラスを付け直す処理は要りません。件数をサーバー側で数えて出し分けていた処理も、DOMの構造だけで判定できるなら、CSSに移せます。
