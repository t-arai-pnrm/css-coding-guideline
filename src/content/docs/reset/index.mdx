すべてのページの土台になるスタイルは、ブラウザのデフォルトスタイルを整える「リセットCSS」と、その上にプロジェクトの既定を決める「ベーススタイル」の2つです。どちらも軽く書きます。詳細度を0に近づけ、レイアウトは指定せず、ブラウザが持つ便利な振る舞いやアクセシビリティの仕組みを壊さないようにします。

土台のCSSは、サイトのすべての要素に影響します。ここに詳細度の高いセレクタやレイアウトの指定が入ると、後から書くコンポーネントのすべてで、それを打ち消す指定が必要になります。反対に、フォーカスリングやスクロールの挙動のように土台で決めておくべきことを決めないと、コンポーネントごとに対応がばらばらになります。

私自身、以前使っていたリセットCSSの強いセレクタのせいで、アイコンの色を上書きできなかったことがあります。欧文の組版を前提にしたリセットCSSでは、日本語のサイトを作るたびに同じ調整を足す必要もありました。こうした経験から、詳細度が0で和文向けの初期値を持つリセットCSSとして、kiso.cssを作って公開しています。

この章は次の3つの節からなります。

- [5-1 壊さないリセット](/reset/kiso/)：kiso.cssの設計と、詳細度を0にする、和文向けの初期値を入れる、便利なデフォルトを残すという3つの方針
- [5-2 ベーススタイルに書くもの](/reset/base-styles/)：フォーカスリング、スクロールの挙動、モーダル表示中の背面固定、`interpolate-size` など、プロジェクトで決める既定
- [5-3 グローバルに書いてはいけないもの](/reset/global-pitfalls/)：詳細度の高い指定、ほかの要素を壊すプロパティ、アクセシビリティを損なう指定

リセットCSSとベーススタイルを置く `reset` と `base` のレイヤー、`:where()` による詳細度の調整は、第2章「[カスケードを制御する](/cascade/)」で扱います。和文組版の値の選び方は[第10章「タイポグラフィと和文組版」](/typography/)で、フォーカスの状態の表し方やダイアログの実装は[第13章「インタラクション」](/interaction/)で扱います。この章のコード例では、説明に関係しない `@layer` の記述を省略しています。デモのCSSには省略せずに書いています。

## 最初に押さえるルール

{/* 要確認: 著者の優先順位で選び直す（レビューの提案にもとづく下書き） */}

次のルールを先に押さえ、ほかのルールは、該当する場面で付録A「[ルール一覧](/appendix/rules/)」から引けば足ります。

- [`no-outline-none`](/reset/global-pitfalls/#rule-no-outline-none)：`outline: none` や `outline: 0` でフォーカスリングを消しません。
- [`focus-ring-not-box-shadow-only`](/reset/base-styles/#rule-focus-ring-not-box-shadow-only)：フォーカスリングを `box-shadow` だけで描きません。
- [`reset-no-destructive-reset`](/reset/kiso/#rule-reset-no-destructive-reset)：`* { margin: 0; padding: 0; }` のように、要素の機能や便利なデフォルトを一律に消すリセットをしません。
- [`no-heavy-specificity-in-global`](/reset/global-pitfalls/#rule-no-heavy-specificity-in-global)：リセットやベーススタイルに、クラス1つで上書きできない詳細度のセレクタを書きません。
- [`no-global-smooth-scroll`](/reset/base-styles/#rule-no-global-smooth-scroll)：`html` や `:root` に、`scroll-behavior: smooth` を無条件に指定しません。
