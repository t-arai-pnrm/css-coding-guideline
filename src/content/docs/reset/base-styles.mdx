ベーススタイルには、リセットの上に、プロジェクト全体で共通にしたい既定を書きます。本書でベーススタイルに書くのは、二重のフォーカスリング、スクロールの挙動、モーダル表示中の背面固定、`interpolate-size`、フレックスアイテムとグリッドアイテムの最小幅です。ベーススタイルは `base` レイヤーに置き、セレクタは `:where()` で包んで詳細度を0にします。詳細度を上げてはいけない理由は、「[4-3 グローバルに書いてはいけないもの](/reset/global-pitfalls/)」で説明します。

どれも、コンポーネントごとに書くと抜け漏れが出やすく、しかもリセットCSSには入れにくいものです。この節では、それぞれの書き方と、ベーススタイルに置く理由を説明します。

## リセットとベーススタイルの分担

リセットCSSとベーススタイルは、どちらもサイト全体に効く土台ですが、役割が違います。リセットCSSは、どのプロジェクトでも同じように使える汎用の部品です。ベーススタイルは、そのプロジェクトで決めたこと（色、フォント、フォーカスの見せ方、動きの扱いなど）を書く場所です。

本書が推奨するリセットCSSのkiso.css（「[4-1 壊さないリセット](/reset/kiso/)」）には、あえて入れていない指定があります。モーダル表示中に背面のスクロールを止める指定は、リセットCSSの範囲かどうかの判断が分かれるので入れていません。`interpolate-size` も、既存のサイトで意図しないアニメーションを起こすおそれがあるので見送っています。どちらも、各プロジェクトのベーススタイルで入れる前提です。

ルート要素の文字色や背景色、フォント、グローバルな `@keyframes` などもベーススタイルに置きますが、これらは「[9-1 フォントを指定する](/typography/fonts/)」「[10-1 色とダークモード](/color-media/color/)」「[11-2 モーションを実装する](/interaction/motion/)」で扱います。

## フォーカスリングを二重にする

フォーカスリングは、キーボードで操作するユーザーに、いまどこにフォーカスがあるかを伝える表示です。ブラウザのデフォルトのリングは、ブラウザごとに見た目が異なり、サイトの配色によっては見えにくいことがあります。ブランドカラーのような1色でリングを描くと、同じ色の背景の上では消えてしまいます。

そこで本書では、`:focus-visible` のときに、2色を重ねたリングを表示します。要素のすぐ外側を背景色（`Canvas`）、その外側を文字色（`CanvasText`）にしておけば、背景の明るさにかかわらず、どちらか一方は背景と区別できます。

```css title="🙆‍♂ Recommended: :focus-visible に二重のフォーカスリングを定義する"
:where(:focus-visible) {
  --_b--ring-width: 3px;
  --_b--ring-offset: 3px;

  box-shadow: 0 0 0 calc(var(--_b--ring-offset) + var(--_b--ring-width)) Canvas;
  outline: var(--_b--ring-width) solid CanvasText;
  outline-offset: var(--_b--ring-offset);
}
```

外側のリングは、太さ3pxの `outline` です。`outline-offset` で要素から3px離し、その隙間を `box-shadow` で埋めています。`box-shadow` の広がりは隙間とリングの太さを足した6pxですが、外側の3pxは `outline` に隠れるので、見えるのは要素のすぐ外側の3pxだけです。接頭辞の `--_b--` は、コンポーネントの内部用のプロパティと名前がぶつからないように付けています。
{/* 要確認: 出典なし（--_b-- の接頭辞を付ける理由は筆者の推論） */}

色に使っている `Canvas` と `CanvasText` はシステムカラーで、ブラウザが決める背景色と文字色です。ダークモードや強制カラーモードでも、互いにコントラストが取れた2色の組み合わせに切り替わります。

強制カラーモードでは `box-shadow` が `none` になりますが、`outline` は残ります。リングの本体を `outline` で描いているのはこのためです。`box-shadow` だけで描いたリングは、強制カラーモードでは消えてしまいます。

## スムーススクロールは条件付きにする

ページ内リンクで移動するときのスムーススクロールは、`html` に `scroll-behavior: smooth` を1行書けば実現できます。手軽なので広く使われていますが、この書き方には副作用があります。

```css title="🙅‍♂ Not Recommended: スムーススクロールを一律に有効にする"
/* 🙅‍♂ Not Recommended */
html {
  scroll-behavior: smooth;
}
```

まず、Tabキーでフォーカスを移したときのスクロールまでなめらかになり、キーを続けて押すと動きが追いつかずにもたつきます。JavaScriptの `scrollTo()` も、デフォルトの動きがなめらかなスクロールに変わるので、サードパーティのスクリプトにも影響します。さらに、動きを減らす設定をしているユーザーにも、そのままアニメーションが適用されます。

```css title="🙆‍♂ Recommended: ページ内リンクの移動先があり、キーボード操作中でないときだけ有効にする"
:where(:root:has(:target):not(:has(:focus-visible))) {
  @media (prefers-reduced-motion: no-preference) {
    scroll-behavior: smooth;
  }
}
```

この指定は、3つの条件がそろったときだけスムーススクロールを有効にします。1つ目は、動きを減らす設定がないこと（`prefers-reduced-motion: no-preference`）です。2つ目は、ページ内リンクの移動先（URLのフラグメントが指す要素）があること（`:has(:target)`）です。3つ目は、キーボード操作などでフォーカスリングを表示している要素がないこと（`:not(:has(:focus-visible))`）です。

ページ内リンクをクリックすると、移動先が `:target` になってからスクロールが始まるので、このときはなめらかに動きます。一方、Tabキーでフォーカスを移しているときは `:focus-visible` の要素があるので、アニメーションせずに一度でスクロールします。キーボード操作のもたつきは起きません。
{/* 要確認: 出典なし（:target と :focus-visible の条件が働く仕組みの説明は筆者の推論。ブラウザでの動作は未検証） */}

以前の私は、同じ理由から、CSSではなくJavaScriptの `scrollIntoView()` でスムーススクロールを実装していました。現在はこの条件付きの指定で、JavaScriptを使わずに済ませています。ただし、特定のリンクだけスムーススクロールを無効にするような細かい制御には、今でもJavaScriptが必要です。

## 移動先が固定ヘッダーに隠れないようにする

固定ヘッダーがあるページでは、ページ内リンクで移動した先の見出しが、ヘッダーの下に隠れてしまいます。これを防ぐのが `scroll-margin-block-start` です。スクロールで要素を表示するとき、ブロック方向の始点側に、指定した分の余白を空けます。

```css title="🙆‍♂ Recommended: 移動先とフォーカスした要素の上に余白を空ける"
:where([id], :focus) {
  scroll-margin-block-start: 4rlh;
}
```

対象は、ページ内リンクの移動先になりうる、`id` 属性を持つ要素と、フォーカスした要素です。`:focus` も含めるのは、Tabキーでフォーカスを移したときのスクロールでも、フォーカスした要素をヘッダーの下に隠さないためです。

値の `4rlh` は、ルート要素の行の高さの4倍です。ユーザーが文字サイズを大きくすれば、余白も一緒に大きくなります。ヘッダーの高さを測るJavaScriptを使わなくても、多くの場合はこの目安で足りるという印象です。ヘッダーが特に高いプロジェクトでは、この値を調整します。

## モーダルを開いている間は背面を固定する

モーダルのダイアログを開いている間は、背面のページがスクロールしないようにするのが一般的です。以前は、`body` を `position: fixed` にしたり、`dialog` の `open` 属性で判定したりする方法が使われていました。

```css title="🙅‍♂ Not Recommended: open 属性を持つ dialog で、body を固定する"
/* 🙅‍♂ Not Recommended */
body:has(dialog[open]) {
  overflow: hidden;
}
```

この書き方には2つの問題があります。`open` 属性は、モーダルでない `show()` で開いたダイアログにも付くので、背面を操作できるはずのダイアログでもスクロールが止まります。また、`body` に指定した `overflow` は、`position: sticky` の要素の動きを妨げることがあります。

```css title="🙆‍♂ Recommended: モーダルが開いている間、ルート要素のスクロールを止める"
:where(:root:has(:modal)) {
  overflow: hidden;
}
```

`:modal` は、`showModal()` や `command="show-modal"` でモーダルとして開いたダイアログに一致する擬似クラスです（全画面表示にした要素にも一致します）。ルート要素に指定した `overflow` はビューポートに伝わるので、`position: sticky` の要素にも影響しません。

スクロールを止めるとスクロールバーが消え、その幅の分だけコンテンツが横にずれます。これを防ぐのが、kiso.cssが `:root` に指定している `scrollbar-gutter: stable` です。スクロールバーの有無にかかわらず、その幅の領域を確保するので、ダイアログを開閉してもレイアウトはずれません。

`overflow: hidden` の代わりに `overflow: clip` を使う方法もありますが、2025年5月の時点ではFirefoxで背面を固定できなかったので使いません。また、iOSのSafariでは、この方法でも背面のスクロールを完全には止められません。完全に止める必要がある場合は、JavaScriptを併用します。ダイアログそのものの実装は、「[11-3 開閉するUI](/interaction/disclosure/)」で扱います。

## スクロールバーの領域を確保し、見た目は変えない

`scrollbar-gutter: stable` は、ページの内容が増えてスクロールバーが現れたときのずれも防ぎます。kiso.cssが指定しているので、ベーススタイルで書き足す必要はありません。

<Baseline id="scrollbar-gutter" />

Safariは18.2で対応したので、本書が対象とするブラウザ（Safari 18系の最終版以降）では、すべて動作します（2026年9月確認）。スクロールバーの幅をJavaScriptで測って余白を補う処理は、もう要りません。

一方、スクロールバーの色や太さは、できるだけ変えません。スクロールバーの見た目はOSやユーザーの設定で決まるもので、サイトごとに変えると操作の一貫性が損なわれます。強制カラーモードでは、指定した色のせいでスクロールバーが見えなくなるおそれもあります。

デザインの都合でどうしても変える場合は、強制カラーモードでないとき（`forced-colors: none`）に限り、標準の `scrollbar-color` と `scrollbar-width` で指定します。どちらも、2025年12月までにすべての主要なブラウザで使えるようになりました。

```css title="🙆‍♂ Recommended: スクロールバーを変えるなら、強制カラーモードでないときだけにする"
._scroller {
  overflow-x: auto;

  @media (forced-colors: none) {
    scrollbar-color: var(--scrollbar--thumb) var(--scrollbar--track);
    scrollbar-width: thin;
  }
}
```

## interpolate-sizeはベーススタイルで有効にする

`interpolate-size: allow-keywords` は、`auto` や `fit-content` のようなキーワードで決まる大きさと、数値の大きさの間でアニメーションできるようにするプロパティです。`block-size: 0` から `block-size: auto` への変化も、トランジションでなめらかにつなげられます。

```css title="🙆‍♂ Recommended: 動きを減らす設定がないときだけ、キーワードの大きさへの補間を有効にする"
:where(:root) {
  @media (prefers-reduced-motion: no-preference) {
    interpolate-size: allow-keywords;
  }
}
```

このプロパティは継承されるので、`:root` に1回書けば文書全体で有効になります。アニメーションのための指定なので、動きを減らす設定をしていないとき（`prefers-reduced-motion: no-preference`）に限ります。

便利な機能ですが、kiso.cssには入れていません。`transition: all` のように対象を限定しないトランジションを書いた既存のコードでは、これまで一瞬で切り替わっていた大きさの変化まで、アニメーションするようになるからです。`interpolate-size` の初期値が数値だけを補間する `numeric-only` になっているのも、既存のサイトとの互換性のためです。影響を判断できるのはプロジェクトの側なので、ベーススタイルで有効にします。

本書では `transition: all` を使わないので、この問題は起きません（「[11-2 モーションを実装する](/interaction/motion/)」）。

<Baseline id="interpolate-size" />

2026年9月の時点で、`interpolate-size` に対応しているのはChrome系のブラウザだけです。対応していないブラウザでは、大きさが一瞬で切り替わるだけで、機能は損なわれません。プログレッシブ・エンハンスメントとして、安心して使える機能です。

## フレックスアイテムとグリッドアイテムの最小幅を0にする

最後に、全称セレクタに `min-inline-size: 0` を指定します。フレックスやグリッドのレイアウトで起きがちな、原因の分かりにくいはみ出しを防ぐための指定です。

```css title="🙆‍♂ Recommended: すべての要素の最小幅を0にする"
*,
::before,
::after {
  min-inline-size: 0;
}
```

`min-inline-size`（`min-width`）の初期値 `auto` は、通常は0として扱われます。ところが、フレックスアイテムとグリッドアイテムでは、中身の最小幅（`min-content`）として扱われます。そのため、長い英単語やURL、ブラウザが最小幅を決めている `input`、横にスクロールさせる表を含むアイテムは、それ以上縮まずに親からはみ出します。

文字列の折り返しは、kiso.cssの `overflow-wrap: anywhere` で解決できます。しかし、入力欄や表のはみ出しは残ります。全称セレクタで最小幅を0にしておけば、こうした要素も親の幅まで縮みます。

副作用がまったくないわけではありません。縮ませたくない要素まで縮むことがあるので、アイコンのような要素には、個別に `flex-shrink: 0` などを指定します。それでも私は、原因の分かりにくいはみ出しに悩むより、「縮みすぎる」という目に見える問題を直すほうが簡単で合理的だと考えています。はみ出しを防ぐほかの書き方は、「[7-3 変化に強いレイアウト](/layout/defensive/)」で説明します。

## ベーススタイルのまとめ

ここまでの指定をまとめると、次のようになります。これを `base` レイヤーに読み込み、プロジェクトの色やフォントの指定を足していきます。

```css title="🙆‍♂ Recommended: この節で説明したベーススタイルのまとめ"
*,
::before,
::after {
  min-inline-size: 0;
}

:where(:root) {
  @media (prefers-reduced-motion: no-preference) {
    interpolate-size: allow-keywords;
  }
}

:where(:root:has(:target):not(:has(:focus-visible))) {
  @media (prefers-reduced-motion: no-preference) {
    scroll-behavior: smooth;
  }
}

:where(:root:has(:modal)) {
  overflow: hidden;
}

:where(:focus-visible) {
  --_b--ring-width: 3px;
  --_b--ring-offset: 3px;

  box-shadow: 0 0 0 calc(var(--_b--ring-offset) + var(--_b--ring-width)) Canvas;
  outline: var(--_b--ring-width) solid CanvasText;
  outline-offset: var(--_b--ring-offset);
}

:where([id], :focus) {
  scroll-margin-block-start: 4rlh;
}
```

`scrollbar-gutter: stable` は、kiso.cssが指定しているので、ここには含めていません。kiso.cssを使わない場合は、`:root` に書き足してください。
