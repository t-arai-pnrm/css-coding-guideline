第9章は、CSSの「書き方」の規約をまとめた章です。クラス名の付け方と名前に使う語の意味、`@scope` とネストの分担、ネストの深さと何をネストするかの判断、宣言の並び順、新しい記法への統一、コメントの書き方を定めます。この中には、表記をそろえるための規約と、意図しない適用や上書きを防ぐための規約があります。命名、名前に使う語、コメントは表記をそろえる規約で、そろっていないと、コードを読むたびに書いた人の癖を読み解くことになります。スコープの下限、ネストのセレクタと詳細度、宣言とネストしたルールの並び順、論理プロパティは、どの要素に当たるかや表示の結果に関わります。

規約は、ツールで検査できる形にします。宣言の並び順や `display` の書き方は、機械的に判断できます。こうしたものはStylelintに任せ、人はレビューで命名や設計の判断に集中します。この章の規約の多くは、本書のStylelintの設定で検出できます。

ただし、ツールに従えば安全というわけではありません。私のテンプレートでは、Stylelintの並び順の設定に従った結果、メディアクエリによる上書きの効かないコンポーネントをいくつも作っていました。規約とツールの設定は、ブラウザでの実際の動きと照らして見直す必要があります。この章には、その経験から生まれた規約も含まれています。

命名も、何度か変えてきました。ブログではPascalCaseのBEMを使い、テンプレートでは `scoped PascalCase` の形を経て、現在は `scoped kebab-case` の形に落ち着いています。この章では、いちばん新しい書き方を紹介します。

節は次の9つです。

- [9-1 命名規則](/notation/naming/)：5種類のクラス名を見分ける接頭辞と、自分で付ける名前の `--`
- [9-2 名前に使う語](/notation/terminology/)：`inner` と `outer`、`gutter` と `gap`、`link` と `button`、`navigation` と `menu` のような語の意味と使い分け、省略語と数字の扱い
- [9-3 @scopeとネストの使い分け](/notation/scope-and-nesting/)：BEMのBlockとElementを `@scope` で、Modifierをネストで表す分担と、スコープの下限を `.scoped` にする理由
- [9-4 ネストの書き方](/notation/nesting/)：セレクタは2層までのネスト、主語のルールの中に書く自身の状態、セレクタの中に書く条件付きのアットルール
- [9-5 ネストの判断基準](/notation/nesting-criteria/)：ネストしてよい関係、直下の子に書く宣言、`&` の詳細度とセレクタリスト、ネストしたルールの後ろの宣言
- [9-6 プロパティの並び順](/notation/property-order/)：ルールの中の並びと、taks-stylelint-orderによる宣言の並び順
- [9-7 モダンな記法にそろえる](/notation/modern-syntax/)：論理プロパティへの統一、`display` の2値構文、個別の変形プロパティ、色の関数の書き方
- [9-8 論理プロパティと論理値](/notation/logical-properties/)：論理プロパティを使う理由、物理でしか書けないものとの混在、`margin-inline` を左右の余白として扱うこと、右から左へ書く言語と縦書きでの振る舞い
- [9-9 コメントの書き方](/notation/comments/)：ファイル先頭の説明ブロックと、「なぜ」だけを書くコメント

コード例で使っている `@scope` とネストの仕組みは、第4章の「[4-4 @scopeでスタイルを閉じ込める](/cascade/scope/)」と「[4-5 CSSネストの基礎](/cascade/nesting/)」で説明しています。カスタムプロパティの名前の付け方は第10章の「[10-5 公開プロパティと内部プロパティ](/components/custom-properties/)」、コンテナの名前とクエリの範囲構文は[第13章「レスポンシブデザイン」](/responsive/)で扱います。Stylelintの設定の運用は、「[19-1 Stylelintでルールを守る](/operations/stylelint/)」で説明します。この章のコード例では、説明に関係しない `@layer` の記述を省略しています。

## 最初に押さえるルール

{/* 要確認: 著者の判断。最初に押さえるルールを著者の優先順位で選び直す（レビューの提案にもとづく下書き） */}

次のルールを先に押さえ、ほかのルールは、該当する場面で付録A「[ルール一覧](/appendix/rules/)」から引けば足ります。

- [`child-class-underscore`](/notation/naming/#rule-child-class-underscore)：コンポーネントの子要素のクラス名は、`._title` のように `_` で始まるkebab-caseにします。
- [`no-nesting-concatenation`](/notation/nesting/#rule-no-nesting-concatenation)：`&__title` のように、`&` に文字をつなげてクラス名を作りません。
- [`conditions-inside-rules`](/notation/nesting/#rule-conditions-inside-rules)：`@media` と `@container` は、`@scope` やファイルの直下ではなく各セレクタの中に書きます。
- [`display-two-value-syntax`](/notation/modern-syntax/#rule-display-two-value-syntax)：`display` は `block flex` のような2値構文で書きます。
- [`comments-why-only`](/notation/comments/#rule-comments-why-only)：コードの途中のコメントには「なぜそう書くのか」と「なぜ別の書き方をしないのか」だけを書き、何をしているかは書きません。
