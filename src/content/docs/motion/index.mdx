この章では、UIの動きをCSSで書く方法を扱います。動かすかどうかの判断から始め、動きを減らす設定への対応、イージングと再生時間の選び方、トランジションと `@keyframes` の書き分けを説明します。そのあと、要素の出現と退場、スクロールに合わせた動き、描画の負荷、View Transitionsによる画面の切り替えを扱います。

動きは、状態の変化や操作の結果を伝える手段です。うまく使えば、何が起きたのかが分かりやすくなります。一方で、毎日のように繰り返し触るUIに装飾的な動きを足すと、待ち時間が増えるだけです。動きを減らす設定をしているユーザーにとっては、めまいや吐き気の原因にもなります。そのため本書では、動きを足す前に目的を確かめ、動かすと決めたものだけを、決まった手順で実装します。

この章の節は、動きを足すときに確かめる順番で並べています。まず目的があるかを判断し（18-1）、動きを減らす設定でどう見せるかを決め（18-2）、イージングと再生時間を選びます（18-3）。そのうえで実装の手段を選び（18-4〜18-9、18-11）、最後に描画の負荷を確かめます（18-10）。レビューで動きを確かめるときも、この順番で見ていきます。

私自身、以前は動きを減らす設定に、全称セレクタと `!important` で全体の動きを止めるCSSで対応していました。これでは、状態の変化を伝えるフェードまで消えてしまいます。いまは動きを種類ごとに分け、止めるもの、フェードにするもの、短くするもの、そのまま残すものを選んでいます。

## この章で判断できるようになること

この章を読むと、動きを足す前に、その動きが状態の変化や操作の結果を伝えるものか、どのくらいの頻度で見られるものかを確かめ、入れるかどうかを決められるようになります。動きを減らす設定に対しては、止めるか、フェードにするか、短くするか、そのまま残すかを動きの種類ごとに選べます。実装の手段は、トランジションと `@keyframes`、`@starting-style`、スクロール駆動アニメーション、View Transitionsから選べます。描画の負荷も、レイアウト、ペイント、合成のどれが起きるかから見積もれます。

## この章の節

この章は次の11の節で構成しています。

- [18-1 動かすかどうかを決める](/motion/purpose/)：動きの目的の判断表、機能的な動きと装飾的な動き、見る頻度、CSSを先に検討すること
- [18-2 動きを減らす設定に対応する](/motion/reduced-motion/)：無効化、簡素化、短縮、維持の4段階と、大きな変動の基準
- [18-3 イージングと再生時間](/motion/easing-and-duration/)：イージングのトークン、再生時間の目安、`transform-origin` と拡大の起点、押したときの縮小、ばねの `linear()`
- [18-4 トランジションの基本と中断](/motion/transitions-and-keyframes/)：トランジションの書き方、途中で取り消される動き、トランジションと `@keyframes` と `@starting-style` の使い分け
- [18-5 トランジションを応用する](/motion/transition-techniques/)：入るときと外れるときの再生時間、長押しで確定するボタン、ぼかしを使ったクロスフェード、`@property` で登録した1つの値で複数の値を動かす方法
- [18-6 @keyframesを設計する](/motion/keyframes/)：`@keyframes` の命名と置き場所、自明な `from` と `to` の省略、起点を渡すカスタムプロパティ、`animation-fill-mode`、Web Animations API
- [18-7 出現と退場](/motion/entry-and-exit/)：`@starting-style` と `transition-behavior`、カスケードの注意、DOMに追加した要素、ダイアログ、ポップオーバー、`<details>` の開閉
- [18-8 重ねて出すパネルと順に出す要素](/motion/overlays-and-stagger/)：`clip-path` で現すメガメニュー、頻度の低いUIのスタッガー、ツールチップの表示の遅延
- [18-9 スクロールに合わせて動かす](/motion/scroll-driven/)：スクロール駆動アニメーション、`view()` のタイムラインとスタイルクエリで一度だけ再生する演出、`IntersectionObserver` と `data-motion-mode`
- [18-10 動きの負荷を抑える](/motion/performance/)：レイアウト、ペイント、合成のどれが起きるか、`will-change`、`contain`、`filter` と `backdrop-filter`
- [18-11 View Transitionsで画面の切り替えをつなぐ](/motion/view-transitions/)：同じページの中とページ間の切り替え、`view-transition-name` と `view-transition-class` の付け方、名前の重複の注意点

キーボード操作のフォーカスに動きを付けない書き方は、「[17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)」で扱います。`interpolate-size` の有効化とスムーススクロールは「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」で説明しています。イージングと再生時間のトークンの定義は「[10-4 デザイントークン](/components/design-tokens/)」で、変形の個別プロパティは「[9-8 モダンな記法にそろえる](/notation/modern-syntax/)」で扱います。この章のコード例では、説明に関係しない `@layer` の記述を省略しています。デモのCSSには省略せずに書いています。

## 初めて読むとき

初めて読むときは、「[18-1 動かすかどうかを決める](/motion/purpose/)」「[18-2 動きを減らす設定に対応する](/motion/reduced-motion/)」を読みます。18-3以降は、実際に動きを付けるときに読んでください。

## 最初に押さえるルール

次のルールを先に押さえ、ほかのルールは、該当する場面で付録A「[ルール一覧](/appendix/rules/)」から引けば足ります。

- [`motion-needs-purpose`](/motion/purpose/#rule-motion-needs-purpose)：アニメーションを足す前に目的があるかを確かめ、目的のない動きは入れません。
- [`motion-only-with-no-preference`](/motion/reduced-motion/#rule-motion-only-with-no-preference)：装飾的な動きのうちフェード以外は、`@media (prefers-reduced-motion: no-preference)` の中で指定します。
- [`simplify-large-motion-when-reduced`](/motion/reduced-motion/#rule-simplify-large-motion-when-reduced)：機能的な動きでも大きな変動は、動きを減らす設定でフェードに置き換えます。
- [`scale-in-from-near-one`](/motion/easing-and-duration/#rule-scale-in-from-near-one)：拡大して現れる動きは `scale: 0` から始めず、`transform-origin` をトリガーのある側に向けます。
- [`no-transition-all`](/motion/transitions-and-keyframes/#rule-no-transition-all)：`transition: all` や `transition-property: all` を使いません。
- [`starting-style-for-entry`](/motion/entry-and-exit/#rule-starting-style-for-entry)：`display: none` から表示する要素の出現と退場は、`@starting-style` と `transition-behavior: allow-discrete` で動かします。

## この章の判断のまとめ

動きが遅い、邪魔だと感じたら、再生時間やイージングを詰める前に、その動きに目的があるかと、どれだけ繰り返し見られるかを確かめます。動きを減らす設定でどう見せるかは、位置と大きさが大きく変わるかで決め、変わる動きは止めるかフェードに置き換え、位置と大きさの変わらないフェードは残します。

手段は、途中で取り消されることがあるならトランジションを、出現だけを動かすなら `@keyframes` を、スクロール位置に合わせて値が連続して変わるならスクロール駆動アニメーションを選びます。かくつくときは、見た目ではなく、変えたプロパティがレイアウト、ペイント、合成のどこから処理をやり直させるかを見ます。

## 次の章へ

第11章からこの章までで、レイアウト、文字、色、装飾、操作、動きについて、書き方のルールを決めてきました。ルールは、書いた時点では守られていても、人の入れ替わりや作業の分担、AIが出力するコードによって少しずつ崩れ、CMSのようにルールの前提が成り立たない環境もあります。第19章「[実務での運用](/operations/)」では、Stylelintとレビューでルールを守り続ける方法と、前提が成り立たない環境での書き方を説明します。
