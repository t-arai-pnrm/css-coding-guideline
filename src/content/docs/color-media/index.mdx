この章では、色、画像、装飾の書き方を扱います。結論を先に書くと、色は `oklch()` で定義して、派生させた色は元の色から関数で作ります。そのうえで、ブラウザやユーザーの設定によって色が置き換わる場面まで考えておきます。画像と装飾も、比率やアイコンの色を指定するだけでなく、画像が表示されない場合や強制カラーモードで壊れない書き方を選びます。

色は見た目だけの問題に見えますが、実際にはアクセシビリティに直結します。たとえば強制カラーモードでは、`background-color` で描いたアイコンが消え、背景色だけで範囲を示していたボタンは、ただの文字になります。Windowsのユーザーの約4%が強制カラーモードを使っているというデータもあり、決して少ない数ではありません。色の違いだけで伝えた情報は、色の見え方が違う人には届かないので、実装後にはグレースケールの表示でも確かめます。

もうひとつの動機は、色の書き方そのものが大きく変わったことです。16進数で色を管理していた頃は、透過させた色のためにRGBの値を別のトークンとして持つ必要がありました。いまは、相対カラー構文と `color-mix()` で、元の色から派生させた色を作れます。ダークモードも `light-dark()` を使えば、トークンの側だけで切り替えられます。

この章は次の3つの節で構成しています。

- [10-1 色とダークモード](/color-media/color/)：`oklch()`、相対カラー構文、`color-mix()` で色を定義する方法と、`light-dark()` とメタ要素の `color-scheme` によるダークモードとテーマの切り替え
- [10-2 強制カラーモードとコントラスト](/color-media/forced-colors/)：システムカラー、透明な枠線、背景色で描いた図形のフォールバックと、グレースケールやコントラスト比による確認
- [10-3 画像と装飾](/color-media/images-and-decoration/)：`aspect-ratio` と `object-fit`、`srcset` と `sizes`、`clip-path` とマスク、`currentColor` のアイコン、影と角丸

色の関数をスペースで区切る記法は[第5章「記法の規約」](/notation/)で、色のトークンをプリミティブとセマンティクスの2層で持つ設計は[第6章「コンポーネントとカスタムプロパティ」](/components/)で扱います。ダークモードに対応しないときの `color-scheme` の注意と、フォーカスリングは[第4章「リセットとベーススタイル」](/reset/)で、ホバーのときの色の変え方は[第11章「インタラクションとモーション」](/interaction/)で説明します。この章のコード例では、説明に関係しない `@layer` の記述を省略しています。デモのCSSには省略せずに書いています。
