画像の縦横比は `aspect-ratio` で決め、中身は `object-fit` の `cover` か `contain` で収めます。初期値の `fill` のまま、画像を引き伸ばさないようにします。`<img>` には `width` と `height` の属性を書き、`srcset` と `sizes` の値は、手で計算せずにツールで確かめて決めます。

単色のアイコンは `currentColor` で文字色に合わせ、三角形のような図形は `clip-path` で描いて、形をトークンにします。影と角丸もトークンから選びます。影の色は、ライトモードでは背景の色相に寄せ、ダークモードでは黒のままにして不透明度で強さを変えます。

## 古い書き方で比率を保つと起きること

`aspect-ratio` が使えなかった頃は、`padding-top` に割合を指定して、縦横比を保っていました。`padding` の割合は親要素の幅を基準に計算されるので、`9 / 16 * 100%` を指定すれば、幅に対して16:9の高さを作れます。

```css title="🙅‍♂ Not Recommended: padding-top の割合で比率を作る"
/* 🙅‍♂ Not Recommended */
.frame {
  position: relative;
}

.frame::after {
  content: "";
  display: block;
  padding-top: calc(9 / 16 * 100%);
}

.frame img {
  position: absolute;
  inset: 0;
  width: 100%;
  height: 100%;
  object-fit: cover;
}
```

この書き方では、比率を作るための擬似要素と、中身を重ねるための絶対配置が必要です。中身は枠から外れた状態になるので、テキストが増えても枠は伸びません。コードを読んでも、`padding-top` が比率のための指定だとすぐには分かりません。

画像の側にも、よくある問題があります。枠の大きさに合わせようとして、画像へ `width: 100%` と `height: 100%` だけを指定すると、比率の違う画像が縦や横に引き伸ばされます。CMSで編集者が画像を差し替えるサイトでは、どのような比率の画像が入るかを事前に決められません。

## aspect-ratio で比率を決める

縦横比は `aspect-ratio` で指定します。幅が決まれば、高さは比率から計算されます。擬似要素と絶対配置は要りません。

```css title="🙆‍♂ Recommended: aspect-ratio で比率を決め、object-fit で収める"
._thumbnail {
  inline-size: 100%;
  aspect-ratio: 16 / 9;
  object-fit: cover;
}

._avatar {
  inline-size: 48px;
  aspect-ratio: 1;
  border-radius: calc(infinity * 1px);
  object-fit: cover;
}
```

正方形や正円にしたいときは、`aspect-ratio: 1` と書きます。`aspect-ratio` は `<img>` だけでなく、動画や `<iframe>`、背景を持つ `<div>` のような、縦横比が決まっている要素なら何にでも使えます。高さを固定したくなったら、まず `aspect-ratio` で表せないかを考えます。高さの決め方は「[8-1 検討する順番](/responsive/escalation/)」でも取り上げています。

`<img>` には、画像の実際の大きさを `width` と `height` の属性で書きます。ブラウザは、この2つの属性から縦横比を計算し、画像を読み込む前から表示する場所を確保します。属性がないと、画像が読み込まれた瞬間に高さが決まり、下にある文章がずれて、読んでいた位置を見失います。

```html
<img src="thumbnail.avif" width="800" height="450" alt="" />
```

属性に書いた値が、そのまま表示の大きさになるわけではありません。kiso.cssは、画像に `max-inline-size: 100%` と `block-size: auto` を指定しています。枠より大きな画像は枠の幅まで縮み、高さは属性の比率を保ったまま決まります。

## object-fit は cover か contain にする

大きさを決めた画像には、`object-fit` を指定します。初期値の `fill` は、画像を枠いっぱいに引き伸ばすので、比率の違う画像が歪みます。`fill` が望ましい場面は、ほとんどありません。

<Demo title="16:9の画像を正方形の枠に入れたときの、object-fit の違い" html={objectFitHtml} css={objectFitCss} variant="neutral" />

`cover` は、比率を保ったまま枠を覆うように拡大し、はみ出した部分を切り取ります。写真のサムネイルやメインビジュアルのように、枠を埋めることを優先する画像に向いています。`contain` は、画像全体が枠に収まるように縮めます。ロゴや図版のように、切り取られると困る画像に使います。

私のテンプレートでは、ベーススタイルで `<img>` と `<video>` を `cover` にしています。`contain` が必要な画像だけ、コンポーネントで上書きします。切り取る位置は `object-position` で調整できます。人物の顔が写真の上のほうにあるなら、`object-position: 50% 20%` のように上寄りにすれば、顔が切れにくくなります。

```css title="🙆‍♂ Recommended: 画像と動画は cover を既定にする"
:where(img, video) {
  object-fit: cover;
}
```

### 隣の要素の高さに合わせる

グリッドの中で、画像の高さを隣の本文の高さに合わせたい場合があります。画像に `block-size: 100%` を指定すると、画像の元の高さで行が押し広げられ、本文の下に余白ができて間延びします。この場合は、`block-size: 0` と `min-block-size: 100%` を組み合わせます（2026年9月、Chrome 153で確認）。

```css title="🙆‍♂ Recommended: 画像の高さを、同じ行の本文の高さに合わせる"
._image {
  inline-size: 100%;
  block-size: 0;
  min-block-size: 100%;
  object-fit: cover;
}
```

`block-size: 0` で画像が行の高さを押し広げないようにし、`min-block-size: 100%` でセルの高さまで広げています。行の高さは本文だけで決まり、画像はその高さに合わせて `cover` で切り取られます。

### 画像の上の文字には背景色を用意する

画像や動画の上に文字を載せるときは、画像が表示されなかった場合に備えて、文字と対になる背景色を指定しておきます。通信の状態によって画像を読み込めないと、白い背景の上に白い文字だけが残り、読めなくなるからです。

```css title="🙆‍♂ Recommended: 画像がなくても白い文字が読める背景色を敷く"
@scope (.scoped.hero-header) to (.scoped) {
  :scope {
    display: block grid;
    grid-template-areas: "--stack";
    background-color: oklch(20% 0 0deg);
    color: oklch(100% 0 0deg);
  }

  img,
  ._body {
    grid-area: --stack;
  }

  img {
    inline-size: 100%;
    block-size: 0;
    min-block-size: 100%;
    object-fit: cover;
  }
}
```

背景色は、画像の平均的な色ではなく、文字色とのコントラストが取れる色にします。このコード例では、白い文字に対して暗いグレーを敷いています。画像と本文は同じグリッドのエリアに重ね、画像の高さは前の項目と同じ方法で本文に合わせています。

## レスポンシブ画像

画面の幅や解像度に合わせて、大きさの違う画像を出し分けるには、`srcset` と `sizes` の属性を使います。`srcset` には画像の候補とその幅を、`sizes` には画像がレイアウトの中で表示される幅を書きます。ブラウザは、表示される幅と画面の解像度から、ちょうどよい候補を選んで読み込みます。

```html
<img
  src="photo-800.avif"
  srcset="photo-400.avif 400w, photo-800.avif 800w, photo-1200.avif 1200w"
  sizes="(width >= 1024px) 50vw, 100vw"
  width="1200"
  height="800"
  alt="川沿いの桜並木"
/>
```

難しいのは `sizes` です。表示される幅はCSSのレイアウトで決まるので、余白、段組み、コンテナクエリによる切り替えまで考えて、ビューポートの幅との関係を書き出す必要があります。私は、`sizes` を手で計算しません。仮の値を入れたページでRespImageLintのブックマークレットを実行し、提案された値を採用しています。

RespImageLintが提案する `sizes` の値は、`vw` を使って書かれています。`sizes` はCSSのプロパティではなくHTMLの属性で、画像を選ぶ時点のビューポートの幅を基準にします。本書では、`sizes` の中の `vw` を、`vw` を使わないという規約（「[3-2 ビューポート単位とコンテナ単位](/values/viewport-and-container-units/)」）の例外として扱います。

`<picture>` の `<source>` にある `media` 属性は、ビューポートを基準にした条件しか書けません。コンテナクエリで配置を切り替えるコンポーネントでも、画像の切り替えはビューポートを基準にして書くしかありません。この制約は「[8-2 コンテナクエリ](/responsive/container-queries/)」でも取り上げています。

### 形式と読み込みの優先度

写真のような画像は、AVIFで書き出します。AVIFは、WebPより10〜30%ほど小さく、2024年1月にすべての主要なブラウザで使えるようになりました。Webページで表示する画像では、ブラウザの対応を理由にJPEGやPNGを主な形式にする必要はもうありません。ただし、AVIFへの変換はWebPの2倍以上の時間がかかるので、画像の多いサイトでは、ビルドの時間を見積もっておきます。

ファーストビューに表示される画像には、`loading="lazy"` を指定しません。遅延読み込みにすると、ページでいちばん大きな要素の表示が遅れるからです。代わりに `fetchpriority="high"` を指定して、優先して読み込ませます。スクロールしないと見えない画像と `<iframe>` にだけ、`loading="lazy"` を付けます。

<Baseline id="loading-lazy" />

遅延読み込みは、通信やデコードの仕事をなくすのではなく、あとへ先送りするだけです。先送りした先がスクロールや操作の最中だと、通信、デコード、レイアウトの処理が同じ時間に重なり、操作への応答（INP）や体感を悪くすることがあります。ページ内のすべての `<img>` に一括で付けると、この状態を作りやすくなります。ファーストビューの直下の画像にまで付けるかどうかは、実測で決めます。遅延読み込みする画像や埋め込みにも、`width` と `height` の属性か `aspect-ratio` で場所を確保しておきます。確保しないと、読み込んだ瞬間にレイアウトがずれます。

装飾のための画像や、隣の見出しと同じ内容を表すだけの画像には、`alt=""` を指定します。カードのサムネイルのように、見出しのリンクと同じ内容を繰り返す画像がその例です。意味のある画像には、内容が伝わる代替テキストを書きます。

なお、遅延読み込みの画像で `sizes` を自動で決める `sizes="auto"` は、Safariが対応していません（2026年9月確認）。

## 図形は clip-path とマスクで描く

吹き出しの三角形のような図形は、`clip-path` で描きます。以前は、透明な `border` を組み合わせて三角形を作る方法がよく使われていました。

```css title="🙅‍♂ Not Recommended: border を組み合わせて三角形を作る"
/* 🙅‍♂ Not Recommended */
.tooltip::after {
  --size: 16px;

  border-left: calc(var(--size) / 2) solid transparent;
  border-right: calc(var(--size) / 2) solid transparent;
  border-top: calc(tan(60deg) * calc(var(--size) / 2)) solid;
}
```

この方法では、三角形の大きさを3つの `border` の幅から逆算する必要があり、どの向きの三角形なのかもコードから読み取りにくくなります。`clip-path` なら、要素の幅と高さを決めて、形で切り抜くだけです。

```css title="🙆‍♂ Recommended: 形をトークンにして、clip-path で切り抜く"
:root {
  --shape--triangle-top: polygon(50% 0, 100% 100%, 0 100%);
  --shape--triangle-bottom: polygon(0 0, 100% 0, 50% 100%);
  --shape--triangle-right: polygon(0 0, 100% 50%, 0 100%);
  --shape--triangle-left: polygon(0 50%, 100% 0, 100% 100%);
}

._tooltip {
  position: relative;
}

._tooltip::after {
  --_size: 16px;

  content: "";

  /* ツールチップの下端の中央から、下へ突き出す */
  position: absolute;
  inset-block-start: 100%;
  inset-inline-start: 50%;
  clip-path: var(--shape--triangle-bottom);
  inline-size: var(--_size);
  block-size: calc(var(--_size) / 2 * tan(60deg));
  background-color: inherit;
  translate: -50% 0;
}
```

三角形は、ツールチップの本体を基準に絶対配置します。絶対配置した擬似要素はブロックの箱になるので、`display` を指定しなくても、`inline-size` と `block-size` が効きます。`translate: -50% 0` で三角形の幅の半分だけ戻し、本体の中央にそろえます。

`polygon()` の値は直接書かず、トークンとして定義します。`polygon(0 0, 100% 0, 50% 100%)` という値を見て、下向きの三角形だとすぐに気づく人は多くないでしょう。`--shape--triangle-bottom` という名前なら、形がすぐに分かります。高さを `tan(60deg)` で計算すると、正三角形になります。

アイコンは、SVGを `mask-image` のマスクにして描く方法もあります。テンプレートでは、矢印のアイコンをdata URIのトークン（`--chevron--rightward` など）として定義し、擬似要素の `mask-image` で参照しています。色は `background-color` で塗るので、文字色やホバーの状態に合わせて変えられます。

```css title="🙆‍♂ Recommended: マスクで切り抜き、背景色で塗る"
._more::after {
  content: "";

  /* 空の擬似要素はインラインになり、幅と高さが効かないので、箱を作る */
  display: inline flow-root;
  mask-image: var(--chevron--rightward);
  mask-repeat: no-repeat;
  mask-position: center;
  mask-size: contain;
  inline-size: 1em;
  aspect-ratio: 1;
  background-color: var(--background-current);
}
```

`display: inline flow-root` は、空の擬似要素に幅と高さを持たせるための指定です。親が `display: inline flex` のようなフレックスコンテナなら、擬似要素はフレックスアイテムとしてブロックの箱になるので、この指定がなくても描けます。

`background-color` に `currentColor` を直接書かず、`--background-current` から受け取っているのは、強制カラーモードでアイコンを消さないためです。この仕組みは「[10-2 強制カラーモードとコントラスト](/color-media/forced-colors/)」で説明しています。マスクのプロパティは、2023年12月までにすべての主要なブラウザが接頭辞なしで対応したので、`-webkit-` の接頭辞は要りません。

## アイコンは currentColor で文字色に合わせる

インラインSVGのアイコンは、`fill` や `stroke` を `currentColor` にして、文字色に合わせます。ボタンの種類や状態ごとにアイコンの色を指定し直す必要がなくなり、文字色を変えるだけで、アイコンも一緒に変わります。

```css title="🙅‍♂ Not Recommended: 状態ごとにアイコンの色を指定し直す"
/* 🙅‍♂ Not Recommended */
.button--primary {
  color: var(--color-primary);
}

.button--primary svg {
  fill: var(--color-primary);
}

.button:disabled {
  color: var(--color-disabled);
}

.button:disabled svg {
  fill: var(--color-disabled);
}
```

```css title="🙆‍♂ Recommended: アイコンは文字色に合わせ、文字色だけを切り替える"
._button {
  color: var(--foreground--base);

  &:disabled {
    color: var(--foreground--muted);
  }
}

._icon {
  fill: currentColor;
}
```

`border` の色を省略した場合も、初期値は `currentColor` です。文字と同じ色の枠線なら、`border: 1px solid` とだけ書けば足ります。色を2か所に書かなければ、片方だけ変え忘れることもありません。

アイコンの大きさは、`inline-size: 1em` と `aspect-ratio: 1` で文字の大きさに合わせます。テンプレートでは `.icon` というクラスで、`--icon--size` を受け取れるようにしています。アイコンを画面の幅に合わせて変える必要がないことは、「[8-1 検討する順番](/responsive/escalation/)」で説明しています。

### インラインSVGの代替テキスト

意味を持つアイコンをインラインSVGで置くときは、SVGに `aria-hidden="true"` を付けて読み上げの対象から外し、隣に視覚的に隠したテキストを置きます。

```html
<a href="https://example.com/" target="_blank">
  関連資料
  <svg class="icon" aria-hidden="true" viewBox="0 0 24 24" fill="none" stroke="currentColor">
    <path d="M17 2H22V7" />
    <path d="M13 11L21.5 2.5" />
  </svg>
  <span class="-visually-hidden">新しいウィンドウが開きます</span>
</a>
```

SVGの中の `<title>` や `aria-label` で名前を付ける方法もありますが、これらは機械翻訳されず、ページ内検索の対象にもなりません。ふつうのテキストとして置けば、翻訳、検索、選択してのコピーのすべてに対応できます。視覚的に隠すユーティリティは「[6-2 コンポジションとユーティリティ](/components/compositions-and-utilities/)」で扱います。

### 単色のアイコンの描き方を選ぶ

単色のアイコンを置く方法は、擬似要素の `mask-image`、インラインSVG、外部のファイルを読み込む `<img>` の3つです。どれを選ぶかは、文字色に合わせたいか、HTMLにアイコンを書けるかで決まります。違いを次の表にまとめます。

| 方法 | 色を文字色に合わせる | 強制カラーモード | 代替テキスト | 向く場面 |
| --- | --- | --- | --- | --- |
| 擬似要素の `mask-image` | `background-color` で合わせられる | 背景色が消えるので、`--background-current` でシステムカラーに戻す | 持てない。意味があれば隣にテキストを置く | 矢印や外部リンクの印のように、CSSだけで足す装飾 |
| インラインSVG | `fill` や `stroke` の `currentColor` で合わせられる | 色が置き換わらないことがあるので、`fill` と `stroke` をシステムカラーに固定する | `aria-hidden="true"` にして、隣に視覚的に隠したテキストを置く | 意味のあるアイコンや、線と塗りを使い分ける複雑な形 |
| 外部のファイルの `<img>` | 合わせられない。画像の中の色のまま | 影響を受けないので、背景に溶け込むなら `filter` で塗りつぶす | `alt` 属性で付ける | 色を変えないロゴや、多色の画像 |

{/* 要確認: 出典なし（「向く場面」の列と、<img> のSVGがページの文字色を受け取らないこと） */}

文字色に合わせる必要があるアイコンは、`mask-image` かインラインSVGのどちらかになります。HTMLに手を入れずにCSSだけで足したい装飾なら `mask-image` を、HTMLの中で意味を持たせたいアイコンならインラインSVGを選びます。強制カラーモードの補正は、どちらも「[10-2 強制カラーモードとコントラスト](/color-media/forced-colors/)」で説明しています。

## 影と角丸はトークンから選ぶ

影は、段階的に強くなる「高さ」のスケールとしてトークンにします。画面の光源は1つに決め、どのトークンも同じ向きの影にします。本書の例は真上からの光なので、水平方向のオフセットは0です。斜めの光にするなら、水平と垂直のオフセットの比を、すべてのトークンでそろえます。要素が高く浮くほど、オフセットとぼかしを大きくし、不透明度は下げます。浮いた要素ほど、影が遠くまで広がって薄くなるからです。

```css title="🙆‍♂ Recommended: 光源をそろえ、高いほどオフセットとぼかしを大きく、不透明度を低くする"
:root {
  --shadow--hue: 250deg;
  --shadow--color: light-dark(oklch(30% 0.05 var(--shadow--hue) / 14%), oklch(0% 0 0deg / 30%));
  --shadow--sm: 0 2px 4px -1px var(--shadow--color);
  --shadow--md:
    0 4px 8px -2px color-mix(in oklab, var(--shadow--color) 80%, transparent),
    0 2px 4px -2px var(--shadow--color);
  --shadow--lg:
    0 8px 16px -4px color-mix(in oklab, var(--shadow--color) 60%, transparent),
    0 4px 6px -2px color-mix(in oklab, var(--shadow--color) 80%, transparent);
}
```

ライトモードの影は、背景の色相に寄せます。灰色がかった黒の影を色のある背景に重ねると、背景がくすんで見えるからです。背景の色相に合わせ、明度と彩度を下げた色にすると、背景と自然になじみます。上の例では、背景のアクセントカラーの色相を `--shadow--hue` に持たせています。背景が無彩色のサイトでは、彩度が0の黒のままでも構いません。

影の色は、ダークモードでは黒のままにします。暗い背景で白い影を付けると、影ではなく光って見えてしまうからです。代わりに、ダークモードでは黒の不透明度を上げて、暗い背景の上でも奥行きが分かるようにします。影は強制カラーモードでは消えるので、要素の境界は影だけで表しません。

複数の影を重ねたトークンは、描画の計算量が影の数に比例して増えます。`transition` や `animation` で影そのものを動かすと、古い端末ではコマ落ちしやすくなります。影を動かしたいときは、影を付けた擬似要素の `opacity` だけを動かします。{/* 要確認: 出典なし */}透明な部分の輪郭に沿わせたいときは、`box-shadow` ではなく `filter: drop-shadow()` を使います。

角丸も、`--rounded--sm` から `--rounded--xl` までの段階と、完全な角丸の `--rounded--full` をトークンにしています。`--rounded--full` の値は `calc(infinity * 1px)` です。`999px` のような大きな値を書く方法もありますが、「十分に大きい値」という意図は `infinity` のほうが正確に伝わります。角の曲線そのものを変える `corner-shape` や、画面いっぱいのときだけ角丸を消す書き方は、「[10-4 角と形を作る](/color-media/shapes/)」で説明しています。

```css title="🙆‍♂ Recommended: 内側の角丸は、外側の角丸から余白を引いた値にする"
@scope (.scoped.menu) to (.scoped) {
  :scope {
    --_radius: var(--rounded--md);
    --_padding: 4px;

    padding: var(--_padding);
    border-radius: var(--_radius);
  }

  ._item {
    border-radius: calc(var(--_radius) - var(--_padding));
  }
}
```

角丸の要素の中に、角丸の要素を入れ子にする場合は、内側の角丸を「外側の角丸から間の余白を引いた値」にします。外側と内側に同じ値を指定すると、角の部分だけ余白が広く見えてしまいます。影や角丸の値をpxで指定する理由は、「[3-1 pxとremを使い分ける](/values/px-and-rem/)」で説明しています。

## すりガラスの背景は、真後ろの色だけが混ざる

`backdrop-filter: blur()` で、要素の背後をぼかしたすりガラスの背景を作れます。効果を見せるには、要素の背景を半透明にします。ぼかしの対象になるのは、その要素の真後ろにあるピクセルだけです。固定ヘッダーの少し下にある色付きの要素は、ヘッダーに重なるまでぼかしに混ざらず、スクロールの途中で急に色が現れます。

```css title="🙆‍♂ Recommended: 半透明の背景に backdrop-filter を重ねる"
._header {
  position: sticky;
  inset-block-start: 0;
  background-color: oklch(from var(--background--base) l c h / 70%);
  backdrop-filter: blur(12px);
}
```

`-webkit-` の接頭辞は書きません。Safariは18から接頭辞なしで対応しています（2026年9月確認）。`backdrop-filter` は、固定配置の子孫の包含ブロックにもなるので、子に `position: fixed` を置くと、期待した位置になりません。詳しくは「[7-9 重なりと配置](/layout/positioning/)」で説明しています。祖先に `opacity` や `mask`、`clip-path` があると、ぼかしの対象がその祖先の内側に限られる点にも注意します。

<Baseline id="backdrop-filter" />

固定ヘッダーの背景色を、スクロール位置のセクションに合わせて切り替えたいときは、ヘッダーの背景を書き換える代わりに、ヘッダーの後ろに `position: sticky` の色付きの要素（ブロッカー）を置く方法があります。ブロッカーは、自分の入っているセクションの外へは追従しないので、セクションを抜けると次のセクションの色に入れ替わります。ただし、各セクションの先頭に、ヘッダーと同じ高さの余白が必要です。ヘッダーを高さのあるときだけ固定する場合（「[7-9 重なりと配置](/layout/positioning/)」）は、ブロッカーも同じ条件の中に書き、余白が取れない場面では別の方法を選びます。

## 番号付きリストのマーカーは ::marker で装飾する

`<ol>` の番号の色や太さを変えたいときは、`::marker` を使います。リストの意味を保ったまま、`color`、`font-*`、`content` を指定できます。

```css title="🙆‍♂ Recommended: マーカーの色と太さを ::marker で変える"
._step::marker {
  color: var(--color--accent--500);
  font-weight: 700;
}
```

`::marker` には、`background` や `border`、`padding` のようなボックスのプロパティを指定できません。番号を円で囲むような装飾には足りないので、そのときだけ `list-style-type: ""` でマーカーを空にし、`::before` に `counter()` で番号を描きます。古い記事にある `list-style: none` での書き方は、本書では使いません。理由は「[4-3 グローバルに書いてはいけないもの](/reset/global-pitfalls/)」で説明しています。

## 文字の縁取りは塗りの下に描く

写真の上の見出しやバナーの文字に、縁取りを付けたいことがあります。文字の縁取りは `-webkit-text-stroke` で描きます。接頭辞が付いていますが、WHATWGのCompatibility Standardで定義され、すべての主要なブラウザが対応しています。接頭辞のない書き方はないので、理由のコメントを添えて、Stylelintの警告を無効にします。

<Baseline id="text-stroke-fill" name="-webkit-text-stroke" />

ただし、縁取りの線は字形の輪郭を中心に、内側と外側へ半分ずつ描かれます。初期値では塗りの上に線を重ねるので、線を太くするほど、内側の半分が塗りを覆って文字が細くなります。画数の多い漢字では、字の中のすき間が線で埋まり、読めなくなることもあります。

```css title="🙅‍♂ Not Recommended: 太い縁取りを塗りの上に重ねる"
/* 🙅‍♂ Not Recommended */
.title {
  color: oklch(100% 0 0deg);
  -webkit-text-stroke: 8px oklch(25% 0 0deg);
}
```

`paint-order: stroke fill` を指定すると、線を先に描き、その上に塗りを重ねます。線の内側の半分は塗りに隠れ、外側の半分だけが縁取りとして見えます。字の形が崩れないので、縁取りを太くしても読みやすさを保てます。

```css title="🙆‍♂ Recommended: 縁取りを塗りの下に描く"
._title {
  color: oklch(100% 0 0deg);

  /* 文字の縁取りは、接頭辞付きの指定でしか書けない（2026年9月） */
  /* stylelint-disable-next-line property-no-vendor-prefix */
  -webkit-text-stroke: 8px oklch(25% 0 0deg);
  paint-order: stroke fill;
}
```

<Demo title="paint-order を指定すると、縁取りが塗りの下に描かれる" html={strokeHtml} css={strokeCss} variant="neutral" />

見えるのは線の外側の半分なので、線の幅は、見せたい縁取りの2倍を指定します。上の例では、8pxの線で4pxの縁取りになります。`paint-order` はもともとSVGのプロパティで、HTMLの文字には、2024年3月にすべての主要なブラウザで使えるようになりました。対応していない環境では、縁取りが塗りの上に重なるだけです。

<Baseline id="paint-order" />

縁取りは、読みやすさを補う装飾として使います。`-webkit-text-fill-color: transparent` で塗りを消して、縁取りだけの文字にすると、細い線だけで字の形を読み取ることになり、背景とのコントラストも確かめにくくなります。本文や長い見出しには使わず、短い装飾の文字に限ります。{/* 要確認: 出典なし */}
