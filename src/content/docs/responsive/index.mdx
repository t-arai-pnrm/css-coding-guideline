この章は、画面の幅や置き場所の違いへのCSSの対応を扱います。レスポンシブ対応は、「どの幅で切り替えるか」から考え始めず、「そもそも切り替えが必要か」から順に検討します。クエリは、ほかの手段で解決できないときに使う最後の手段です。

私自身、以前はデザインカンプの幅に合わせてブレイクポイントを決め、コンポーネントごとにメディアクエリを書いていました。しかし、この方法で見た目を保証できるのはカンプの幅だけです。画面の幅は無数にあり、ユーザーは文字サイズも変えられるため、すべての環境で見た目を一致させる「ピクセルパーフェクト」は実現できません。CSSでできるのは、幅や文字サイズが変わっても破綻しない指定を用意することです。

もうひとつの前提は、コンポーネントの置き場所が決まっていないことです。同じカードをメインエリアとサイドバーの両方に置くと、ビューポートの幅が同じでもカードの幅は異なるため、ビューポートの幅だけではカード内の配置を決められません。そこで、ページ全体の段組みはビューポートの幅で、コンポーネント内の配置は置かれた場所の幅で決めます。この役割分担が、章全体に共通する考え方です。

節は次の5つです。

- [8-1 検討する順番](/responsive/escalation/)：静的、イントリンシック、コンテナクエリ、メディアクエリの順に検討する理由
- [8-2 コンテナクエリ](/responsive/container-queries/)：置き場所の幅に合わせて振る舞うコンポーネントの書き方と、コンテナの副作用
- [8-3 メディアクエリとブレイクポイント](/responsive/media-queries/)：ページ全体の段組みの切り替えと、ブレイクポイントの決め方
- [8-4 実践パターン：2サイズのデザインカンプを再現する](/responsive/design-comp-pattern/)：カンプの比率を保つ案件で使う、画面モードと比例スケール
- [8-5 セーフエリアに対応する](/responsive/safe-area/)：ノッチやホームインジケーターを避ける余白と、画面の下に固定する要素の書き方

単位の選び方（pxとrem、ビューポート単位とコンテナ単位）は[第3章「値と単位」](/values/)で、コード例で使っている `@scope` とカスケードレイヤーは[第2章「カスケードを制御する」](/cascade/)で説明しています。この章のコード例では、説明に関係しない `@layer` の記述を省略しています。デモのCSSでは省略していません。
