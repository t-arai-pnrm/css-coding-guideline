狭い画面用と広い画面用の2サイズでデザインカンプが用意され、その比率を保った再現を求められる案件があります。こうした案件では、ビューポートの判定を1か所に集めた「画面モード」（`--screen`）と、カンプの寸法をそのまま書ける「比例スケール」（`--px` と `--rem`）を組み合わせると、コードの見通しがよくなります。

ただし、これは「[8-1 検討する順番](/responsive/escalation/)」の原則に対する例外です。どちらもビューポートを基準にする方法なので、置き場所に合わせて振る舞うべきコンポーネントには向きません。この節では、パターンの書き方と一緒に、使ってよい条件を説明します。

## カンプの比率を保つ案件の悩み

Webサイト制作の現場では、幅375pxと幅1280pxのように、2つの幅のデザインカンプを渡されることがよくあります。カンプの間の幅は、比率を保って拡大・縮小してほしいという要望も珍しくありません。

この要望を通常の方法で実装しようとすると、2つの問題にぶつかります。1つ目は、すべてのコンポーネントに同じブレイクポイントのメディアクエリが散らばることです。ブレイクポイントを変えたくなったら、すべてのファイルを直さなければなりません。

2つ目は、寸法の変換の手間です。カンプの余白や文字サイズをすべて `clamp()` の流体値に変換していくと、式が増えてカンプとの対応が読み取りにくくなります。カンプに「40px」と書いてある値が、コードのどこにあるのかを探すことになります。

本書は、すべての環境で見た目を一致させるピクセルパーフェクトを目指さない立場です。それでも、カンプの比率を保つことが案件の要件として合意されているなら、その要件に最短で応える書き方を持っておく価値はあります。この節のパターンは、原則を捨てるものではなく、要件がはっきりしている場面に限って使う道具だと考えてください。

## 画面モードを1か所で決める

1つ目の問題には、ビューポートの判定を `:root` の1か所に集めて解決します。メディアクエリで決めるのは `--screen` というカスタムプロパティの値だけで、各所の分岐はその値を見るスタイルクエリで書きます。

```css title="🙆‍♂ Recommended: 画面モードを :root で決め、各所はスタイルクエリで分岐する"
:root {
  --screen: --compact;

  @media (width >= calc(768 / 16 * 1rem)) {
    --screen: --spacious;
  }
}

._heading {
  font-size: calc(24 * var(--rem));

  @container style(--screen: --spacious) {
    font-size: calc(40 * var(--rem));
  }
}
```

スタイルクエリは、コンテナのカスタムプロパティの値を条件にできるコンテナクエリです。サイズのクエリと違って、すべての要素が最初からスタイルクエリのコンテナになっているので、`container` の指定は要りません。`--screen` は `:root` から継承されるので、どの要素からでも同じ値を参照できます。

この形なら、ブレイクポイントの値は `:root` の1か所にしかありません。各所のコードは「広い画面のモードのとき」という意味で書かれ、具体的な幅を知りません。

モードの名前は `--compact` と `--spacious` のように、デバイスではなく状態を表す名前にします。`--sp` や `--pc` のようなデバイス名は、「[8-3 メディアクエリとブレイクポイント](/responsive/media-queries/)」で説明したのと同じ理由で使いません。名前を `--` で始めるのは、コンテナの名前や `@keyframes` の名前と同じく、自分で付けた名前だとひと目で分かるようにするためです。スタイルクエリの値として使う名前も、この規則にそろえます。

同じ考え方は、ページ全体ではなくコンポーネントの単位でも使えます。コンポーネントのルートでメディアクエリか名前付きのコンテナクエリを使って `--_density` のような値を決め、中の要素はスタイルクエリで分岐する形です。判定を1か所に集めるという点は、画面モードと変わりません。

スタイルクエリは、2026年5月にすべての主要なブラウザで使えるようになったばかりの機能です（2026年9月確認）。本書の対象のブラウザ（Safari 18系の最終版以降）では動作しますが、対応していない古いブラウザでは、スタイルクエリの中の指定がすべて無視されます。そのため、`--compact` の表示はクエリの外に基本のスタイルとして書き、`--spacious` との差分だけをスタイルクエリで書きます。こうしておけば、古いブラウザでもコンパクトな表示で内容を読めます。

## カンプの寸法を比例させる

2つ目の問題には、カンプの寸法をそのまま書ける比例スケールを用意します。画面の幅をカンプの幅で割った比率（`--zoom-scale`）を求め、それを掛けた `--px` と `--rem` を単位のように使います。

```css title="🙆‍♂ Recommended: 画面の幅から比率を求め、単位のように使う"
@property --100svi {
  syntax: "<length>";
  inherits: false;
  initial-value: 0;
}

@property --1rem {
  syntax: "<length>";
  inherits: false;
  initial-value: 0;
}

:root {
  --100svi: 100svi;
  --1rem: 1rem;
  --window-width: calc(tan(atan2(var(--100svi), 1px)) * min(1, 16 / tan(atan2(var(--1rem), 1px))));
  --zoom-scale: calc(var(--window-width) / 375);
  --px: calc(1px * var(--zoom-scale));
  --rem: calc(1 / 16 * 1rem * var(--zoom-scale));

  @media (width >= calc(768 / 16 * 1rem)) {
    --zoom-scale: min(var(--window-width) / 1280, 1680 / 1280);
  }
}
```

少し込み入っているので、順に説明します。`--window-width` は、画面の幅から単位を外した数値です。長さを長さで割る計算（`100svi / 1px`）はまだ一部のブラウザでしか使えないので、`tan(atan2(長さ, 1px))` という三角関数の組み合わせで、同じ結果を得ています。`@property` で型を登録しているのは、`100svi` と `1rem` を `:root` の時点で絶対的な長さに変換し、子孫の要素に同じ値を引き継ぐためです。

`--window-width` の後半の `min(1, 16 / …)` は、ユーザーが文字サイズを大きくしているときに、画面を実際より狭いものとして扱うための補正です。たとえば文字サイズを125%（20px）に設定しているユーザーでは、画面の幅を0.8倍として計算します。広い画面のモードでは、比率を1280pxのカンプに対して計算し直し、1680px相当で拡大を止めています。

使うときは、カンプ上のピクセル値をそのまま掛けます。余白なら `padding: calc(20 * var(--px))`、2つの値の合計なら `calc((60 + 72) * var(--px))` のように、カンプとの対応を式で残せます。

文字サイズには必ず `--rem` を使います。先ほどの補正によって、文字サイズを125%にしているユーザーでは `--px` が0.8倍に縮みますが、`--rem` はremの分（1.25倍）が掛かるので、文字の大きさはデフォルトのユーザーと同じに保たれます。余白などが縮んだ分、文字が相対的に大きく表示されるわけです。文字サイズに `--px` を使うと、文字まで0.8倍に縮んでしまいます（2026年9月、Chromeで確認）。

いろいろな場所で使い回す部品では、`--px` や `--rem` が定義されていない環境に置かれることも考えて、`var()` にフォールバックの値を書いておきます。フォールバックには、比率が1のときの値（`1px` と `calc(1 / 16 * 1rem)`）を使います。こうしておけば、比例スケールのないページに置かれても、カンプどおりの寸法で表示されます。

```css title="🙆‍♂ Recommended: 使い回す部品ではフォールバックを書く"
._cluster {
  gap: calc(16 * var(--px, 1px));
  font-size: calc(14 * var(--rem, calc(1 / 16 * 1rem)));
}
```

## 使ってよい条件と注意点

このパターンを使うのは、2サイズのデザインカンプが用意され、その比率を保って再現することを関係者と合意している案件に限ります。ビューポートを基準にして全体を拡大・縮小する方法なので、「[8-1 検討する順番](/responsive/escalation/)」で説明したイントリンシックな方法やコンテナクエリの利点とは両立しません。サイドバーとメインエリアの両方に置かれる部品や、別のサイトでも使い回すコンポーネントでは、コンテナクエリを使います。

画面モードを使うなら、ビューポートのメディアクエリは `--screen` を決める1か所だけにします。別の場所にもメディアクエリを書くと、判定が2か所に分かれ、1か所に集めた意味がなくなります。

もうひとつ注意したいのは、広い画面のモードへ切り替わった直後の文字の大きさです。768px相当の幅では1280pxのカンプを0.6倍に縮小して表示するので、カンプ上で16pxの本文は9.6pxになります。切り替える幅を決めるときは、縮小後の文字が読める大きさかどうかを、デザイナーと一緒に確認してください。

スタイルクエリの条件も、ほかのクエリと同じく、各セレクタの中に書きます。`@scope` の直下に条件のブロックを置き、その中に宣言をじかに書くと、宣言やその後ろのルールは無視されることがあります。条件を各セレクタの中に書くという規約は、「[5-2 ネストとプロパティの並び順](/notation/nesting-and-order/)」で説明します。
