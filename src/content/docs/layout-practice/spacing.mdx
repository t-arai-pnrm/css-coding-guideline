要素の間の余白は、間隔の決まり方で作り方を選びます。すべての間が同じ間隔なら、子要素の `margin` ではなく、親の `gap` で作ります。見出しの下は24px、本文の下は16pxのように間ごとに大きさが違っても、要素の構成と配置が決まっていれば、`grid-template` に空のセルの行を置いて作ります。余白の指定が `grid-template` の1か所にまとまるからです。要素の有無が状況で変わる場所や、本文のように種類の違う要素が続く領域では、前後の要素によって間隔が変わるので、通常フローのまま `margin` で作ります。

最後の場面では、`margin` が今でも役に立ちます。最近は「`margin` を使わない開発」を勧める声もありますが、私は、`margin` もまだ現役だと考えています。ただし、レイアウトのために `margin` を使う場面は、確実に減っています。どの書き方を選ぶかの基準は、「[11-1 レイアウト手法の選び方](/layout-practice/choosing/)」の、間隔が前後の要素で変わる縦の並びの説明と同じです。

縦の `margin` は、次兄弟結合子で前の要素を条件にして、後ろの要素の `margin-block-start` に付けます。セレクタは `& > * + *` や `& > :is(:heading, h1, h2, h3, h4, h5, h6) + *` のように書きます。余白は要素そのものの性質ではなく、隣り合う2つの要素の関係から決まるからです。要素自身に `margin-block-end` を付けて、最後の子で打ち消す書き方はしません。

コンポーネントのルートに外側の `margin` を持たせない理由は、「[10-2 コンポーネントの境界を守る](/components/boundaries/)」で説明しています。

## 子要素のmarginで間隔を作ると起きること

お知らせの一覧のように、同じ種類の要素を縦に並べる場面を考えます。子要素の下に `margin` を付け、最後の要素だけ打ち消す書き方をよく見かけます。

```css title="🙅‍♂ Not Recommended: 子要素の margin で間隔を作り、最後だけ打ち消す"
/* 🙅‍♂ Not Recommended */
._news-list {
  & > li {
    margin-block-end: 24px;
  }

  & > li:last-child {
    margin-block-end: 0;
  }
}
```

1列で並べている間は問題なく見えます。しかし、広い画面で2列のグリッドに変えると、最後の行の左側の要素には `margin-block-end` が残ったままになります。列の間隔は別に指定しなければならず、列数を変えるたびに「どの要素の余白を打ち消すか」を考え直すことになります。

`margin` には、ブロック方向に隣り合う要素の間で大きいほうだけが残る「相殺」という仕組みもあります。上の要素の `margin-block-end` と下の要素の `margin-block-start` を両方指定すると、合計ではなく大きいほうの値だけが効きます。上下のどちらに付けるかをチームで決めておかないと、相殺と打ち消しが入り混じり、実際の間隔がどの指定で決まっているのかを追えなくなります。

相殺は、親と最初の子、親と最後の子の間でも起き、子に付けた余白が親の外へ出て、親の背景が余白を含まなくなります。止めるなら、親に `display: flow-root` を指定します。相殺が起きる条件と起きない条件、負の値を含む計算は「[7-6 マージンの相殺](/layout/margin-collapse/)」で詳しく説明しています。

<Baseline id="display-flow-root" />

```css title="🙆‍♂ Recommended: 親子の相殺は flow-root で止める"
._section {
  display: block flow-root;
}
```

`overflow: auto` や、見えない `padding` と `border` でも相殺は止まりますが、使いません。`overflow` はスクロールコンテナを作り、中の `position: sticky` を妨げるほか、影や絶対配置の要素を切り取ります（「[7-10 positionの基礎](/layout/positioning/)」）。FlexboxやGridにした要素の子も、親との間では相殺しません。余白を子と親の枠の間に取りたいだけなら、親の `padding` で足ります。

## 親の `gap` による間隔

FlexboxやGridで並べた要素の間隔は、親の `gap` で作ります。`gap` は要素と要素の間にだけ空くので、最初や最後の要素の余白を打ち消す必要がありません。

```css title="🙆‍♂ Recommended: 間隔は親の gap で作る"
._news-list {
  display: block grid;
  gap: 24px;

  @media (width >= calc(768 / 16 * 1rem)) {
    grid-template-columns: repeat(2, 1fr);
    column-gap: 32px;
  }
}
```

列の数を変えても、子要素の側には何も書き足す必要がありません。行と列の間隔は `row-gap` と `column-gap` で別々に決められ、要素が折り返したときも、行の頭に余計な余白が残りません。間隔を決める情報が親の1か所にあるので、「この一覧の間隔は何pxか」という問いには、親のルールを見るだけで答えられます。

`gap` はFlexboxでも使えます。要素を横に並べて折り返す `cluster` や、縦に積む `stack` のようなコンポジションは、どれも `gap` で間隔を作っています。コンポジションの間隔のデフォルト値を0にして、使う側で指定する理由は「[10-3 コンポジションとユーティリティ](/components/compositions-and-utilities/)」で説明しています。

## 間ごとに違う余白と空のグリッドセル

`gap` の弱点は、すべての間隔が同じ大きさになることです。お問い合わせのセクションのように、見出しの下は24px、本文の下は16pxと、間ごとに余白が違うデザインはよくあります。これを `gap` で作ろうとすると、差の分だけ `padding` を持つ `div` を足したり、特定の子要素にだけ `margin` を付けたりすることになります。余白の指定がHTMLとCSSのあちこちに散らばり、どこで余白が決まっているのかを推理しなければなりません。

そこで私が勧めているのが、空のグリッドセルで余白を作る方法です。`grid-template` の中の `.` は、何も置かない空のセルを表します。要素を置く行の間に、高さを指定した空のセルの行を挟めば、その行の高さがそのまま余白になります。

```css title="🙆‍♂ Recommended: 余白を、高さを指定した空のセルの行で作る"
@scope (.scoped.contact-section) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  ._layout {
    display: block grid;
    reading-flow: grid-rows;
    grid-template:
      "--heading"
      "." 24px
      "--lead"
      "." 16px
      "--contact-link";

    @container --scoped (inline-size >= calc(560 / 16 * 1rem)) {
      grid-template:
        "--heading"
        "." 48px
        "--lead"
        "." 32px
        "--contact-link";
    }

    & > ._heading {
      grid-area: --heading;
    }

    & > ._lead {
      grid-area: --lead;
    }

    & > ._contact-link {
      grid-area: --contact-link;
    }
  }
}
```

`grid-template` の各行は、エリアの名前と行の高さの組です。高さを省略した行は `auto` になり、要素の大きさに合わせて決まります。余白の行だけに高さを書いておけば、上から順に「見出し、24pxの余白、本文、16pxの余白、ボタン」と読めます。

次のデモでは、置かれた場所の幅が560px相当以上になると、余白の行の高さが2倍に変わります。クエリの中で書き換えているのは `grid-template` だけで、子要素のCSSには余白の指定がありません。幅のボタンで320pxや480pxを選ぶと、見出しの下は24px、本文の下は16pxで、768px以上を選ぶと、それぞれ48pxと32pxに広がります。

<Demo title="空のグリッドセルの行で、見出しの下と本文の下に違う大きさの余白を作る" html={emptyCellsHtml} css={emptyCellsCss} />

この方法の利点は3つあります。1つ目は、余白を1か所で管理できることです。ブレイクポイントごとに余白を変えるときも、`grid-template` を書き換えるだけで済みます。2つ目は、余白のための要素が要らないことです。3つ目は、`grid-template` を見ればレイアウトの構造が分かることです。

余白の行の高さには、`"." calc(var(--spacing--lg) * 1px)` のようにトークンも使えます。トークンを使うかどうかは、ほかの余白と同じ基準で決めます。ここでは分かりやすさのため、pxの値をそのまま書きました。トークンの設計は「[10-4 デザイントークン](/components/design-tokens/)」で扱います。

子要素の側から見ると、この方法では自分の周りに余白が一切ありません。余白を持つのは親のテンプレートだけなので、子要素をほかの場所へ移しても、余計な余白が付いてくることはありません。「[10-2 コンポーネントの境界を守る](/components/boundaries/)」で説明した、外側の余白は置く側が持つという考え方を、そのまま形にしたものです。

## 余白の大小でまとまりを伝える

余白の大きさを決めるときは、グループの間の余白を、グループの中の余白より大きくします。人は、近くにあるものを同じまとまりとして読み取るからです。デザインの原則では「近接」と呼ばれます。カードの一覧なら、カードの中の見出しと本文の間より、カードとカードの間を広くします。{/* 要確認: 出典なし */}

```css title="🙆‍♂ Recommended: カードの中の間隔より、カードの間の間隔を大きくする"
._card-list {
  display: block grid;
  gap: 32px;
}

._card {
  display: block grid;
  gap: 8px;
}
```

2つの余白の差が小さいと、見出しが上のカードと下のカードのどちらに属するのかが分からなくなります。本文の流れでも同じで、見出しの上の余白を下の余白より大きくすると、見出しは後ろに続く段落とひとまとまりに見えます。デザインカンプの余白がこの原則から外れているときは、実装の前にデザイナーへ確認します。{/* 要確認: 出典なし */}

## 余白の列でコンテンツの幅を決める

空のセルは、列にも使えます。ページのセクションで、コンテンツの最大幅と画面の端の余白（ガター）を決めるとき、`max-inline-size` と `margin-inline: auto` の代わりに、左右に余白の列を持つグリッドを作ります。

```css title="🙆‍♂ Recommended: 左右に余白の列を置き、中央の列にコンテンツを置く"
@scope (.scoped.page-section) to (.scoped) {
  ._layout {
    --_gutter: 16px;
    --_content-max-width: calc(1140 / 16 * 1rem);

    display: block grid;
    grid-template-columns:
      [--full-start] minmax(var(--_gutter), 1fr)
      [--content-start] min(100% - var(--_gutter) * 2, var(--_content-max-width))
      [--content-end] minmax(var(--_gutter), 1fr)
      [--full-end];

    & > * {
      grid-column: --content;
    }

    & > ._banner {
      grid-column: --full;
    }
  }
}
```

中央の列は、最大で1140px相当の幅になり、画面が狭いときも左右にガターの分だけ余白が残ります。子要素は、デフォルトでは中央の列に置かれ、`._banner` だけが左右の余白の列まで広がって、画面幅いっぱいに表示されます。列の境界の線にも `--full-start` のように名前を付けておくと、子要素の側は `--content` や `--full` という名前だけで置き場所を選べます。

最大幅と左右の `padding` で同じことをしようとすると、`box-sizing: border-box` の環境では、最大幅から `padding` の分だけコンテンツが狭くなります。そこで「最大幅に左右の `padding` を足す」という計算をしがちですが、余白の列を使えば、中央の列の最大幅がそのままコンテンツの幅になります。画面幅いっぱいに広げる子要素がない1つの要素なら、その要素だけ `box-sizing: unset` で `content-box` に戻せば、`padding` で書いても足し算は要りません（「[7-3 ボックスモデルの基礎](/layout/box-model/#rule-unset-box-sizing-for-content-max-width)」）。

1つのセクションだけなら、`margin-inline: auto` のほうが簡潔かもしれません。この方法が有効なのは、コンテンツの幅に収まる要素と、画面幅いっぱいに広げたい要素が混在する場合です。ビューポートの単位を使った負の `margin` で要素を広げる必要がなくなります。画面幅いっぱいに広げるほかの方法は「[11-6 重なりと全幅](/layout-practice/layering/)」で比べます。第12章のコンポジション `primary-layout` は、この形に「少し狭い」「少し広い」などの列を加えて部品にしたものです。

## ページに並べるセクションの上下の余白

ページは、背景色の違うセクションを縦に並べて作ることがよくあります。このとき、セクションの間を親の `gap` や、セクションの外側の `margin` で空けると、背景が途切れます。セクションの背景は、`margin` の領域には描かれず、親の `gap` の部分にも描かれないからです。`gap` や `margin` で空けた部分には親の背景が見え、色の付いたセクションの間に、ページの背景の帯が挟まります。

```css title="🙅‍♂ Not Recommended: セクションの間を、ページの gap で空ける"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.page-home) to (.scoped) {
  main {
    display: block grid;
    gap: 80px;
  }
}

@scope (.scoped.news-section) to (.scoped) {
  :scope {
    background-color: var(--background--muted);
  }
}
```

この例では、お知らせのセクションの上下に、ページの背景が80pxずつ見えます。さらに、セクションの中に `padding` がないので、見出しは色の付いた領域の上端に接します。背景の上端から見出しまでの余白と、セクションどうしの間隔は、どちらもセクションの上下の余白です。それを親とセクションのどちらに書くかで迷うと、この例のように、片方に足りない余白が生まれます。

そこで、セクションの上下の余白は、各セクションのルートの `padding-block` で作ります。ページの側は、セクションを間隔なしで縦に積むだけにします。`padding` の領域には背景が描かれるので、背景はセクションの端から端まで途切れず、中身と背景の端の間にも余白が確保されます。

```css title="🙆‍♂ Recommended: 上下の余白を、セクション自身の padding-block で作る"
@scope (.scoped.news-section) to (.scoped) {
  :scope {
    padding-block: calc(var(--spacing--xxl) * 1px);
    background-color: var(--background--muted);
  }
}
```

次の2つのデモは、同じHTMLに2通りのCSSを当てたものです。1つ目では、色の付いた2つのセクションの間と上下に、ページの背景が帯になって見え、見出しも背景の上端に接しています。2つ目では、各セクションが自分の `padding-block` で上下の余白を持つので、背景が隙間なく続き、中身の上下にも余白が空いています。

<Demo title="セクションの間をページの gap で空けると、間にページの背景が帯になって見える" html={sectionSpacingHtml} css={sectionSpacingBadCss} variant="not-recommended" />

<Demo title="上下の余白を各セクションの padding-block で持つと、背景が途切れない" html={sectionSpacingHtml} css={sectionSpacingCss} />

コンポーネントのルートに外側の `margin` を持たせないという「[10-2 コンポーネントの境界を守る](/components/boundaries/)」の原則とも矛盾しません。`margin` は周りの要素との距離なので、置かれる場所によって必要な値が変わります。一方、`padding-block` は背景の端から中身までの距離で、セクション自身の見た目として完結しています。背景のないセクションも、同じく `padding-block` で上下の余白を持たせます。あとで背景色を付けることになっても、余白の作り方を変えずに済むからです。

同じ背景のセクションが続く箇所では、上のセクションの下の `padding` と、下のセクションの上の `padding` が足し合わされます。`padding` は、`margin` と違って相殺しないからです。デザインカンプでセクションの間隔を測るときは、この足し算を前提にして、各セクションの上下の値を読み取ります。{/* 要確認: 出典なし */}

## 縦の `margin` と隣り合う要素の関係

このあと説明する、要素の有無が変わる場所と本文の流れでは、間隔を縦の `margin` で作ります。そのときは、`margin` を要素そのものに付けず、次兄弟結合子で前の要素を条件にして、後ろの要素の `margin-block-start` に指定します。`& > * + *` は前に兄弟がある要素を、`& > :is(:heading, h1, h2, h3, h4, h5, h6) + *` は見出しの直後の要素を選びます。

こう書くのは、余白が要素そのものの性質ではないからです。段落の上に16pxが要るのは前に段落があるからで、見出しの直後なら8pxでよく、先頭の段落には余白が要りません。間隔を決めているのは、「段落の次の段落」「見出しの次の段落」という、隣り合う2つの要素の関係です。

要素そのものに余白を付けると、この関係がコードから抜け落ちます。次の例は、見出しに下の余白を無条件に付け、段落にも下の余白を付けて、最後の段落だけ打ち消したものです。

```css title="🙅‍♂ Not Recommended: 要素そのものに下の余白を付け、最後の子で打ち消す"
/* 🙅‍♂ Not Recommended */
._body {
  & > :is(:heading, h1, h2, h3, h4, h5, h6) {
    margin-block-end: 8px;
  }

  & > p {
    margin-block-end: 16px;
  }

  & > p:last-child {
    margin-block-end: 0;
  }
}
```

見出しの下の8pxは、後ろに何があっても付きます。CMSで本文が空になり、見出しだけが出力されると、見出しの下に8pxが残り、そのカードだけ下の余白が広くなります。段落の余白は、打ち消しを書かなければ最後の段落の下に残るので、`:last-child` の指定が欠かせません。リストや図のように余白を書いていない要素が段落の代わりに並ぶと、その後ろの間隔は0になります。

関係をセレクタで表せば、どの問題も起きません。

```css title="🙆‍♂ Recommended: 前の要素を条件にして、後ろの要素の上に余白を付ける"
._body {
  & > * + * {
    margin-block-start: 16px;
  }

  & > :is(:heading, h1, h2, h3, h4, h5, h6) + * {
    margin-block-start: 8px;
  }
}
```

余白は、前に要素があり、その関係が成り立つときだけ付きます。見出しだけが出力されれば見出しの下には何も付かず、最後の子の打ち消しも要りません。`* + *` は要素の種類を問わないので、リストや図が並んでも間隔は空きます。余白はいつも後ろの要素の `margin-block-start` に付くので、最初の節で触れた「上下のどちらに付けるか」で迷うこともありません。

次の2つのデモは、同じHTMLに2通りのCSSを当てたものです。左から、見出しだけのカード、見出しと段落のカード、段落の間にリストを挟んだカードを並べ、各要素の箱を点線で示しています。1つ目では、見出しだけのカードの下の余白が8pxだけ広く、リストと後ろの段落の間が空いていません。2つ目では、3枚のカードのどれも、要素の間にだけ余白が空いています。

<Demo title="前の要素を条件にして後ろの要素の上に余白を付けると、要素の間にだけ余白が空く" html={siblingMarginHtml} css={siblingMarginCss} />

この書き方の対象は、通常フローで縦に積む要素の間隔です。FlexboxやGridの子の間隔は親の `gap` で作り、子に `margin` を足しません。`margin-block-start: auto` で末尾に寄せる指定や、親の `padding` を打ち消す負の値のように、間隔ではなく位置を決める `margin` も対象外です。`:heading` はブラウザの対応が分かれるので、タイプセレクタと並べて `:is()` の中に書きます（「[5-1 擬似クラスと擬似要素の基本](/pseudo/basics/#rule-heading-with-fallback)」）。

## 要素の有無が変わる場所の余白

空のグリッドセルにも、向かない場面があります。ページによって本文がない、フォームを置いた場合はボタンが要らない、というように、要素の有無や数が状況で変わる場合です。空のセルで余白を決めておくと、要素が欠けたときに、その前後の余白の行だけが残ってしまいます。

こうした場所では、前の節の書き方で、2つ目以降の要素にだけ `margin-block-start` を付けます。前に要素があるときだけ余白が付くので、どの要素が欠けても、残った要素の間にだけ間隔が空きます。注記の前だけ間隔を変えたいときは、`& > * + ._note` のように後ろの要素をクラスで絞ります。

```css title="🙆‍♂ Recommended: 前に要素があるときだけ、上に余白を付ける"
._body {
  & > * + * {
    margin-block-start: 16px;
  }

  & > * + ._note {
    margin-block-start: 8px;
  }
}
```

要素が1つ欠けるだけなら、`:has()` でテンプレートを切り替える方法もあります。しかし、欠ける可能性のある要素が複数あると、組み合わせの数だけテンプレートが必要になります。そもそも置かれる文脈ごとにレイアウトが大きく変わるなら、コンポーネントを分けることも検討します。

## 本文の流れの間隔

記事の本文のように、見出し、段落、リスト、図が続く領域でも、間隔は `* + *` の `margin` で作ります。本書では、この並び方を `prose` というコンポジションにしています。間隔は公開プロパティ `--prose--space` で受け取ります。

```css title="🙆‍♂ Recommended: 本文の間隔を、2つ目以降の子の margin-block-start で作る"
/**
 * 本文の流れの間隔を作る。
 *
 * @prop {length} --prose--space [0] - 子要素の間隔
 */
.prose {
  & > * + * {
    margin-block-start: var(--prose--space, 0);
  }
}
```

`margin-block-start` は子要素に指定されるので、`var(--prose--space)` も子要素の側で値が決まります。そのため、見出しの前だけ間隔を広げたいときは、その見出しに `style="--prose--space: …"` のように値を渡せば、その要素の間隔だけを変えられます。

本文の領域を、FlexboxやGridにして `gap` で間隔を作ることはしません。1つ目の理由は、`float` による回り込みを使えなくなることです。フレックスアイテムやグリッドアイテムでは、`float` が無視されます。2つ目の理由は、`margin` の相殺を活かせなくなることです。通常フローなら、図の下の `margin` のように要素が自分で持っている余白と、流れの間隔が隣り合っても、足し算にはならず大きいほうだけが効きます。`gap` の中では `margin` が相殺されず、`gap` に足されるので、要素ごとの余白を調整しにくくなります。
