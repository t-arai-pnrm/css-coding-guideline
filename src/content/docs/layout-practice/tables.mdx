表は、置かれた場所の幅に合わせて縮めません。`min-inline-size` で表の最小の幅を決め、それより狭い場所では、表を包む要素（スクロールのラッパー）の中で横にスクロールさせます。見出しのセルを `position: sticky` で留めるときは、表に `border-collapse: separate` を指定して、枠線をセルごとに持たせます。数値の列は、`font-variant-numeric: tabular-nums` で数字の幅をそろえ、末尾に揃えます。

行どうしを比べる必要がなく、1行ごとに完結した記録を並べる表は、狭い幅で縦に積む方法もあります。その場合は、`display` を変えた表が表として扱われなくなるブラウザがあるので、HTMLに `role` を書いて表の意味を残します。この節では、表が崩れる理由、スクロールのラッパー、見出しのセルの留め方、数値の列のそろえ方、縦に積む方法を順に説明します。

## 狭い場所で表が崩れる理由

表の列の幅は、既定の `table-layout: auto` では、セルの中身から決まります。表の幅は、各列の最小の幅（折り返せるところをすべて折り返した幅）の合計より狭くなりません。この最小の幅が、狭い画面で表が崩れるかどうかを決めます。

kiso.cssは、`:root` に `overflow-wrap: anywhere` を指定しています。この値は、単語の途中でも折り返せる位置として、列の最小の幅の計算にも使われます。そのため、表は1文字ずつ折り返せる幅まで縮み、狭い画面では各列が1〜2文字の幅になります。`12,100` のような数値も途中で折り返され、桁を読み取れなくなります。

反対に、折り返せない長い語や `white-space: nowrap` のセルがあると、表は最小の幅で止まり、親からはみ出します。はみ出した分はページ全体の横スクロールになり、ほかの内容まで横に動きます。どちらの崩れも、表の幅を置かれた場所の幅だけで決めていることが原因です。

対策は2つあります。1つは、表に読める最小の幅を決め、それより狭い場所では、ラッパーの中で表を横にスクロールさせる方法です。もう1つは、狭い幅で行を縦に積み、カードのような形に組み替える方法です。売上の推移のように行どうしを比べる表は、列が並んでいないと比べられないので、スクロールさせます。注文の履歴のように、1行ごとに完結した記録を並べる表は、縦に積んでも読めます。{/* 要確認: 出典なし */}

## スクロールのラッパーで包む

スクロールさせるときは、表を `<div>` で包み、この要素に `overflow-x: auto` を指定します。表には、すべての列が読める幅を `min-inline-size` で指定します。閾値と同じく、列の幅を足した式を `calc()` で書きます。文字が入る中身の幅はremに変換し、pxで指定したセルの `padding` と枠線は、remへ変換せず、pxのまま足します（「[13-2 ブレイクポイントの決め方](/responsive/breakpoints/)」）。

```css title="🙆‍♂ Recommended: 表に最小の幅を決め、包む要素の中で横にスクロールさせる"
@scope (.scoped.sales-table) to (.scoped) {
  :scope {
    overflow-x: auto;
  }

  table {
    inline-size: 100%;

    /*
     * 支店の列の中身 72px 相当と、数値の列の中身 64px 相当 × 7 に、
     * セルの左右の余白 12px × 2 を 8 列分と、支店の列の右の枠線 1px を足した幅
     */
    min-inline-size: calc(72 / 16 * 1rem + 64 / 16 * 1rem * 7 + 12px * 2 * 8 + 1px);
  }
}
```

表そのものの `display` を `block` に変えて、表自体をスクロールさせる書き方も見かけます。ラッパーが要らないので手軽ですが、MDNによれば、`table` の `display` を `block`、`grid`、`flex` に変えると、ブラウザによってはアクセシビリティツリーでの扱いが変わります。その結果、スクリーンリーダーが表として正しく読み上げなくなります。表の構造はHTMLのまま残し、スクロールは外側の要素に任せます。

```css title="🙅‍♂ Not Recommended: 表の display を変えて、表自体をスクロールさせる"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.sales-table) to (.scoped) {
  table {
    display: block flow;
    overflow-x: auto;
  }
}
```

ラッパーには、`role="region"`、`caption` を指す `aria-labelledby`、`tabindex="0"` を付けます。スクロールコンテナにキーボードでフォーカスできるかは、ブラウザによって違います。`tabindex="0"` があれば、どのブラウザでもTabキーで枠にフォーカスし、矢印キーでスクロールできます。フォーカスできる要素には名前が必要なので、`region` のランドマークにして、表の名前を `caption` から借ります。見出しのセルは `th` にし、列の見出しには `scope="col"` を、行の見出しには `scope="row"` を付けて、各セルがどの見出しに属するかを示します。

```html title="🙆‍♂ Recommended: スクロールする枠に、表のキャプションで名前を付ける"
<div class="scoped sales-table" role="region" aria-labelledby="sales-table-caption" tabindex="0">
  <table>
    <caption id="sales-table-caption">支店別の月間売上（2026年度上期、単位：千円）</caption>
    <thead>
      <tr>
        <th scope="col">支店</th>
        <th scope="col" class="_numeric">4月</th>
        <!-- ... -->
      </tr>
    </thead>
    <tbody>
      <tr>
        <th scope="row">札幌</th>
        <td>8,426</td>
        <!-- ... -->
      </tr>
    </tbody>
  </table>
</div>
```

スクロールの方向は、本書の論理プロパティの規約では `overflow-inline` で書きたいところです。しかし、`overflow-inline` に対応したのはSafari 26からなので、2026年10月の時点では `overflow-x` を使います（「[9-8 論理プロパティと論理値](/notation/logical-properties/)」）。表の端が枠で切れて見えることも、横にスクロールできることの手がかりになります。端までスクロールしたら消える「→」の案内は、`scroll-state(scrollable: inline-end)` のコンテナクエリで作れます。現状はChrome系のブラウザだけの機能なので、案内がなくても使える前提で上乗せします（「[11-5 固定ヘッダー](/layout-practice/sticky-header/#留まっている間だけ見た目を変える)」）。

## 見出しのセルを留める

`position: sticky` は、いちばん近い祖先のスクロールコンテナを基準に留まります。そして、`overflow-x` に `auto` を指定すると、`overflow-y` の `visible` も `auto` として計算されます。ラッパーは縦方向でもスクロールコンテナになるので、列の見出しに `inset-block-start: 0` を指定しても、ページをスクロールしたときには留まりません（2026年10月、Chrome 152で確認）。ラッパー自身は縦にスクロールしないからです。

列の見出しを留めたいときは、ラッパーに `max-block-size` を指定し、ラッパーの中で縦にもスクロールさせます。縦の上限を設けたくない表では、列の見出しは留めず、行の見出し（先頭の列）だけを `inset-inline-start: 0` で横方向に留めます。ラッパーには `scrollbar-gutter: stable` も指定します。スクロールバーが幅を取る環境では、行が増えて縦のスクロールバーが現れたときに表の幅が変わるからです。仕様上、`scrollbar-gutter` が確保するのは行の始めと終わりの辺の領域で、横のスクロールバーの領域は確保できません。

次に、枠線の持たせ方を変えます。kiso.cssは `table` に `border-collapse: collapse` を指定しています。`collapse` では、隣り合うセルが1本の枠線を共有するので、枠線はどちらか一方のセルのものではありません。留めたセルを動かしても、共有の枠線は元の位置に残ります。2026年10月にChrome 152で確かめたところ、列の見出しを留めてスクロールすると、見出しの上下の枠線が見出しと一緒に動かず、見出しの下の線が消えたように見えました。{/* 要検証: ブラウザ。Firefox と Safari での見え方 */}

そこで、表に `border-collapse: separate` と `border-spacing: 0` を指定し、枠線を各セルに持たせます。`separate` では、セルの枠線はそのセルのボックスの一部なので、留めたセルと一緒に動きます。隣り合うセルの枠線が二重にならないよう、各セルには `border-block-end` のように1辺ずつ指定します。

```css title="🙆‍♂ Recommended: 枠線をセルに持たせ、列の見出しと行の見出しを留める"
@scope (.scoped.sales-table) to (.scoped) {
  :scope {
    overflow: auto;
    max-block-size: calc(320 / 16 * 1rem);
    isolation: isolate;
    scrollbar-gutter: stable;
  }

  table {
    border-collapse: separate;
    border-spacing: 0;
  }

  th,
  td {
    border-block-end: 1px solid var(--color--neutral--200);
  }

  thead th {
    position: sticky;
    inset-block-start: 0;
    background-color: var(--color--neutral--50);

    &:first-child {
      inset-inline-start: 0;
      z-index: var(--z--forwards);
    }
  }

  tbody th {
    position: sticky;
    inset-inline-start: 0;
    background-color: var(--color--neutral--0);
  }
}
```

留めたセルには、不透明な背景色を指定します。背景がないと、下を通るセルの文字が透けて見えるからです。`z-index` を指定するのは、縦と横の両方に留める左上の角のセルだけです。列の見出しは横に、行の見出しは縦に動いて、どちらも角のセルの下にだけ入ります。角のセルを前に出せば、ほかの留めたセルどうしは重ならないため、`z-index` を指定せずDOMの順番どおりに描かせてかまいません。内部の要素に相対的な `z-index` を指定するため、ルートには `isolation: isolate` を指定します（「[10-2 コンポーネントの境界を守る](/components/boundaries/)」）。

## 数値の列をそろえる

数値の列は、末尾に揃えます。桁数の違う値を並べたとき、1の位がそろうので、大きさを見比べられるからです。列の見出しのセルも、同じ列の数値に合わせて末尾に揃えます。kiso.cssは `th` の `text-align` を `unset` にしていて、見出しのセルは先頭に揃うからです。

末尾に揃えるだけでは、桁はそろいません。多くのフォントの数字はプロポーショナルで、`1` と `0` のように字によって幅が違います。そのため、同じ桁数の値でも、千の位の位置が行ごとにずれます。表に `font-variant-numeric: tabular-nums` を指定すると、数字が同じ幅になり、各桁が縦にそろいます。この指定は、フォントに等幅の数字（OpenTypeの `tnum` 機能）があるときだけ反映されます。

<Baseline id="font-variant-numeric" name="font-variant-numeric" />

```css title="🙆‍♂ Recommended: 数字の幅をそろえ、数値の列を末尾に揃える"
@scope (.scoped.sales-table) to (.scoped) {
  table {
    font-variant-numeric: tabular-nums;
  }

  td {
    text-align: end;
    white-space: nowrap;
  }

  ._numeric {
    text-align: end;
  }
}
```

この例の表は、データのセルがすべて数値なので、`td` にまとめて指定し、列の見出しには `._numeric` のクラスを付けています。本書は、明確な理由がない限り `white-space: nowrap` を指定しません（「[11-3 変化に強いレイアウト](/layout-practice/defensive/)」）。スクロールのラッパーの中の数値は、その理由がある場面です。折り返しを止めると、列の最小の幅に数値全体の幅が入り、数値の途中で折り返さなくなります。はみ出した分は、ラッパーのスクロールで読めます。単位は各セルに繰り返さず、`caption` か列の見出しにまとめます。{/* 要確認: 出典なし */}

次のデモは、ここまでの指定をまとめた売上の表です。幅のボタンで320pxや480pxを選ぶと、表は縮まずに枠の中で横にスクロールします。枠の中を縦にスクロールすると列の見出しが、横にスクロールすると支店の列が留まり、見出しの下の線も一緒に動きます。

<Demo title="最小の幅を決めた表を、包む要素の中でスクロールさせ、見出しのセルを留める" html={scrollHtml} css={scrollCss} />

数値はすべて末尾に揃い、`tabular-nums` で桁の位置が縦にそろっています。千円単位の表であることは `caption` に書き、各セルには数値だけを置いています。

## 狭いときに縦に積む

1行ごとに完結した記録を並べる表は、狭い幅で行をカードのように縦に積めます。表が複数の場所に置かれることを考え、切り替えはコンテナサイズクエリで書きます。ルートを `container: --scoped / inline-size` のコンテナにし、閾値には、各列の中身の最小の幅とセルの `padding` を足した式を書きます（「[13-3 コンテナサイズクエリ](/responsive/container-size-queries/)」）。

縦に積むには、`table`、`tbody`、`tr`、`td` の `display` を変える必要があります。先に挙げたとおり、`display` を変えた表を表として扱わなくなるブラウザがあります。MDNは、`display: grid` などで表の意味が上書きされる場合に、ARIAの表の `role` を書いて意味を加え直す方法を挙げています。そこで、HTMLの各要素に `role` を書きます。`table` には `role="table"`、`thead` と `tbody` には `role="rowgroup"`、`tr` には `role="row"` を書きます。見出しのセルには `role="columnheader"` か `role="rowheader"` を、データのセルには `role="cell"` を書きます。{/* 要検証: ブラウザ。2026年10月時点で、display を変えた表の意味が失われるブラウザ */}

```css title="🙆‍♂ Recommended: 狭いときだけ、行をカードのように縦に積む"
@scope (.scoped.order-table) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
  }

  table {
    --_density: --compact;

    display: block grid;
    gap: 8px;

    /*
     * 注文番号 72px・注文日 112px・商品 176px・数量 40px・金額 72px・状態 72px（どれも中身の幅で px 相当）に、
     * セルの左右の余白 12px × 2 を 6 列分足した幅
     */
    @container --scoped (inline-size >= calc((72 + 112 + 176 + 40 + 72 + 72) / 16 * 1rem + 12px * 2 * 6)) {
      --_density: --spacious;

      display: block table;
    }
  }

  tr {
    @container style(--_density: --compact) {
      display: block grid;
      gap: 4px;
    }
  }

  td {
    @container style(--_density: --compact) {
      display: block flex;
      gap: 16px;
      justify-content: space-between;
    }
  }

  ._label {
    display: none;

    @container style(--_density: --compact) {
      display: block flow;
    }
  }
}
```

閾値はルートの直下の `table` に1回だけ書き、`--_density` を、狭いときの `--compact` から広いときの `--spacious` に切り替えます。子孫の要素は、この値をスタイルクエリ（祖先の要素で宣言したカスタムプロパティの値を条件にするクエリ）で読みます。仕組みは「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」で説明しています。`table` 自身は、自分で宣言した `--_density` をスタイルクエリで読めないので、`display` の切り替えはコンテナサイズクエリの中に書きます。

子孫の要素では、縦に積む指定を `@container style(--_density: --compact)` の中に書いています。表は、表の形がブラウザの既定のスタイルで、縦に積む形のほうが指定の多い形です。縦積みの指定をクエリの外に書くと、広い幅ではその指定をひとつずつ打ち消して、表の形へ戻さなければなりません。狭いときの条件の中に書けば、広い幅では子孫の要素がブラウザの既定のスタイルのまま表の形になり、打ち消すのは `table` 自身の `display` だけで済みます。

縦に積んだときは、各セルの値の前に列の名前を表示します。列の名前は、`::before` の `content` ではなく、HTMLの `<span class="_label" aria-hidden="true">` に書きます。意味のある文字はHTMLに書くという本書の方針に合わせるためです（「[5-9 生成コンテンツと装飾の擬似要素](/pseudo/generated-content/)」）。`aria-hidden` を付けるのは、`role` で残した列の見出しと重ねて読み上げないためです。`thead` を `display: none` で消すと、列の見出しとの関連づけまで失われるおそれがあります。そこで `thead` は、視覚的にだけ隠します。{/* 要確認: 出典なし */}

幅のボタンで480px以下を選ぶと、各行が枠で囲んだカードになり、列の名前と値が左右に並びます。768pxを選ぶと、同じHTMLが表の形に戻ります。

## 補足と注意点

`table-layout: fixed` は、列の幅を中身ではなく、表の幅と最初の行のセル（または `<col>`）の幅から決める指定です。2行目以降の中身を見ずに列の幅が決まるので、行の多い表でも描画が速くなります。その代わり、中身が列の幅より長いと、折り返すかはみ出します。本書では、`min-inline-size` で最小の幅を決めたうえで、既定の `auto` のまま中身に合わせて列の幅を配らせます。列の幅をデザインで決めたい表にだけ、`fixed` と `<col>` の幅を使います。{/* 要確認: 出典なし */}

縦に積む方法は、列が少なく、各行が独立した表に向いています。列が多い表を縦に積むと、1行のカードが長くなり、行どうしを見比べられなくなります。どちらにするか迷う表は、スクロールのラッパーで包みます。表の形と列の並びが保たれ、`role` の上書きも要らないからです。
