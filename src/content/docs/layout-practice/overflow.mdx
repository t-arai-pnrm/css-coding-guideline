ページに横スクロールが出たら、まず、はみ出している要素を特定して、その要素を直します。ルートで横方向のはみ出しを切り取るのは、そのうえでの備えです。はみ出しを切り取るときは、`overflow: hidden` ではなく `overflow: clip` を使います。`hidden` は要素をスクロールコンテナにするので、`position: sticky` やスクロール駆動アニメーションの基準を変えてしまうからです。`hidden` を使うのは、`0fr` で畳むアコーディオンの中身のように、スクロールコンテナであることが要る場面に限ります。

中身を中央に寄せたスクロール領域では、中身がはみ出したときに先頭側が切れます。中央寄せには `safe` を付け、はみ出すときは先頭に寄せます。はみ出しを起こしにくい書き方（幅の上限、最小の長さ、アイテムの最小幅0）は、「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/)」で説明しています。

## 横スクロールの原因を特定する

ページに横スクロールが出たら、まず、はみ出している要素を特定します。DevToolsのコンソールで次のスクリプトを実行すると、すべての要素に枠線を付けたうえで、ビューポートより広い要素を一覧できます。`$$()` は、DevToolsのコンソールで使える `querySelectorAll()` の省略形です。

```js title="DevTools のコンソールで、ビューポートより広い要素を探す"
const windowWidth = document.documentElement.clientWidth;
$$('*').forEach((el) => {
  el.style.outline = '1px solid tomato';
  if (windowWidth < el.getBoundingClientRect().width) console.log(el);
});
```

`margin` が原因のはみ出しは、このスクリプトでは見つかりません。枠線を目で追って確かめます。原因が分かったら、その要素を直します。直し方は「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/)」にまとめています。

そのうえで、画面の端まで広げた装飾などが意図せずはみ出す場合に備えて、ベーススタイル（`base` レイヤー）で、ルートの横方向のはみ出しを切り取ることがあります。このとき、`overflow-x: hidden` ではなく `clip` を使います。理由は次の見出しで説明します。

```css title="🙆‍♂ Recommended: 横方向のはみ出しを clip で切り取る"
@layer base {
  :root,
  body {
    overflow-inline: clip;

    @supports not (overflow-inline: clip) {
      overflow-x: clip;
    }
  }
}
```

<Baseline id="overflow-clip" />

`overflow: clip` は、本書の対象のすべてのブラウザで使えます。論理プロパティの `overflow-inline` は、Safariでは26から対応したので、対応していない環境には `@supports` で `overflow-x` を指定しています（2026年9月確認）。はみ出しの対策に `contain: paint` を使う方法もありますが、中にある `position: fixed` の要素の基準が変わってしまうので使いません。この仕組みは「[7-9 positionの基礎](/layout/positioning/)」で説明します。

ルートでは、`clip` を選ぶ理由がもう1つあります。`html` と `body` の両方に `overflow-x: hidden` を指定すると、`body` がスクロールコンテナになり、ページのスクロールが `body` に移ることがあります（「[11-10 ページのスクロールとルートスクローラー](/layout-practice/root-scroller/)」）。

## `overflow: hidden` より `clip` を優先する

はみ出しを切り取るだけなら、場所を問わず、`overflow: hidden` ではなく `overflow: clip` を使います。どちらも、はみ出した中身を切り取る点は同じです。違うのは、要素がスクロールコンテナになるかどうかです。`hidden` の要素は、ユーザーのスクロール操作を受け付けないだけで、スクロールコンテナになります。CSS Overflow Module Level 3では、`hidden` の中身はプログラムからはスクロールできなければならないと定めています。`clip` は、プログラムからのスクロールも含めて、あらゆるスクロールを禁止し、スクロールコンテナを作りません。

スクロールコンテナになると、中身の位置がずれる場合もあります。`hidden` の要素の中で、はみ出した位置にある要素へフォーカスを移したり、ページ内リンクで移動したりすると、ブラウザはその要素を見せるために、`hidden` の要素の中身をスクロールさせます。スクロールバーがないので、ユーザーは元の位置に戻せません。JavaScriptの `scrollIntoView()` や `scrollTo()` も、同じように中身を動かします。`clip` の要素は、どの方法でもスクロールしません（フォーカスと `scrollIntoView()` はChrome 152で確認。ページ内リンクは未確認）。{/* 要検証: ブラウザ。ページ内リンクで hidden の要素の中身がスクロールすること */}

スクロールコンテナを探す仕組みにも影響します。`scroll()` で作るスクロール駆動アニメーションのタイムラインは、デフォルトでいちばん近い祖先のスクロールコンテナを基準にします。祖先に `hidden` の要素があると、そこが基準になり、ページをスクロールしてもアニメーションが進みません。スクロール駆動アニメーションは「[18-6 スクロールに合わせて動かす](/motion/scroll-driven/)」で説明しています。

同じ理由で、`position: sticky` も留まらなくなります。`sticky` の要素は、いちばん近い祖先のスクロールコンテナを基準に留まるからです。祖先が `hidden` だと、その要素は自身の中身の高さまで伸びているのでスクロールせず、ページをスクロールしても `sticky` の要素はその要素と一緒に流れていきます。`sticky` が動かない原因の切り分けは「[7-9 positionの基礎](/layout/positioning/)」にまとめています。

```css title="🙅‍♂ Not Recommended: はみ出した装飾を hidden で切り取る"
/* 🙅‍♂ Not Recommended */
._section {
  position: relative;
  overflow: hidden;
}
```

```css title="🙆‍♂ Recommended: はみ出した装飾を clip で切り取る"
._section {
  position: relative;
  overflow: clip;
}
```

次の2つのデモは、右上の装飾の円がはみ出すセクションに、`position: sticky` の見出しを置いたものです。デモの枠の中をスクロールすると、`hidden` で切り取った1つ目では、見出しが段落と一緒に流れていきます。`clip` で切り取った2つ目では、見出しが枠の上端に留まります。どちらも、円のはみ出しは同じように切り取られています。

片方の軸だけを切り取りたいときも、`clip` を使います。`overflow-x: hidden` のように片方の軸を `hidden` にすると、もう片方の軸の `visible` は `auto` として計算され、要素はその軸でもスクロールコンテナになります。横のはみ出しを隠したつもりで縦にスクロールバーが出るのは、このためです。`clip` なら、もう片方の軸は `visible` のまま残ります。ただし、もう片方の軸を `auto` や `scroll` にすると、`clip` は `hidden` として計算されます。

`clip` には、`hidden` が作る新しいBFCを作らないという違いもあります。`overflow: hidden` で親子の `margin` の相殺を止めていた箇所を `clip` に変えると、相殺が戻ります。BFCが目的なら、`overflow` ではなく `display: flow-root` を使います（「[11-2 余白を設計する](/layout-practice/spacing/#rule-flow-root-for-margin-collapse)」）。切り取る位置を外側へ広げたり内容の辺へ寄せたりする `overflow-clip-margin` は、「[11-16 文字の切り詰めと読み込み中の表示](/layout-practice/truncation-and-skeletons/)」で扱います。

## `overflow: hidden` を使う場面

`overflow: hidden` を使うのは、スクロールコンテナであることが要る場面に限ります。代表的なのが、`grid-template-rows` を `0fr` と `1fr` で切り替えて、アコーディオンの中身を開閉する場合です。`fr` の値は補間できるので、`interpolate-size` に対応していないブラウザでも、高さをトランジションで動かせます。

この書き方では、中身を包んだグリッドアイテムを0の高さまで縮めます。ところが、グリッドアイテムの `min-block-size` の初期値 `auto` は、次の3つの条件をすべて満たすとき、中身の大きさから決まる最小サイズとして扱われます。この規則は、CSS Grid Layout Module Level 1の「グリッドアイテムの自動の最小サイズ」で定められています。1つ目は、`overflow` の算出値がスクロールできる値（`hidden`、`scroll`、`auto`）ではないことです。2つ目は、最小値が `auto` の行にまたがっていること、3つ目は、複数の行にまたがるなら、どれも `fr` の行ではないことです。`0fr` は `minmax(auto, 0fr)` の省略形なので、2つ目の条件を満たします。そのため、`overflow` が `visible` や `clip` のアイテムは、行が `0fr` になっても中身の高さより縮みません。

`overflow: hidden` のアイテムは1つ目の条件を外れるので、仕様のとおり最小サイズが0になり、行と一緒に0まで縮みます。はみ出した中身の切り取りと、最小サイズを0にすることを、1つの指定で済ませられます。本書のベーススタイルが0にしているのは `min-inline-size` だけなので（「[8-2 ベーススタイルに書くもの](/reset/base-styles/#rule-global-min-inline-size-zero)」）、高さの方向の最小サイズはここで外す必要があります。

```css title="🙆‍♂ Recommended: 0fr で畳む中身は overflow: hidden で最小サイズを0にする"
@scope (.scoped.disclosure) to (.scoped) {
  ._panel {
    display: block grid;
    grid-template-rows: 1fr;

    @media (prefers-reduced-motion: no-preference) {
      transition-duration: var(--duration--slow);
      transition-property: grid-template-rows;
      transition-timing-function: var(--ease--out-quint);
    }

    /* 閉じている間は、スクリプトで inert 属性を付ける */
    &[inert] {
      grid-template-rows: 0fr;
    }
  }

  ._body {
    overflow: hidden;
  }
}
```

`clip` で同じことをするなら、`min-block-size: 0` を別に書く必要があります。2つの指定の組み合わせは、片方を消すと開閉が崩れるのに、それぞれの目的がコードから読み取りにくくなります。この場面では、スクロールコンテナになることが目的に合っているので、`hidden` を選びます。実際に、`::details-content` を `grid-template-rows` で開閉する方式では、Safari 18.4で `clip` のラッパーでは開閉が崩れ、`hidden` のラッパーが必要でした（2025年5月確認）。

スクロールコンテナになるので、前の見出しで説明したとおり、閉じた中身へフォーカスを移すと、中身の位置がずれる場合もあります。この例では、閉じている間はスクリプトで `inert` 属性を付け、中身にフォーカスが移らないようにしています。`<details>` の開閉に使う例は「[18-5 出現と退場](/motion/entry-and-exit/)」にあります。ほかに `hidden` が要るのは、モーダルを開いている間にルート要素のスクロールを止める場面です（「[8-2 ベーススタイルに書くもの](/reset/base-styles/#rule-modal-scroll-lock-root)」）。

## 中央に寄せたスクロール領域の先頭が切れる

`justify-content: center` や `align-content: center` で中身を中央へ寄せ、`overflow: auto` でスクロールを付けた要素では、中身が要素より大きくなると先頭側が切れます。中央に寄せる計算は、はみ出した分を前後に均等に振り分けます。そのため、先頭側へはみ出した部分は、スクロールで戻れない位置に置かれるからです。モーダルの中身や、横にスクロールするカードの列でよく起きます。

`safe` キーワードを付けて `safe center` と書くと、中身が収まるときは中央に寄せ、はみ出すときは先頭に寄せます。先頭から読めるので、スクロールで末尾まで確かめられます。

```css title="🙆‍♂ Recommended: はみ出すときは先頭に寄せる"
@scope (.scoped.dialog-body) to (.scoped) {
  :scope {
    display: block grid;
    align-content: safe center;
    overflow-y: auto;
    max-block-size: calc(100svb - 32px * 2);
  }
}
```

`safe` は、Safariでは17.6から使えるので、本書の対象のブラウザはすべて対応しています。中身が要素に収まるかどうかがデザインカンプの時点で決まっていない場所では、中央寄せに `safe` を付けておきます（2026年10月、Chrome 152で確認）。
