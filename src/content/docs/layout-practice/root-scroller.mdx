ページ全体のスクロールは、ビューポートのスクロール（ルートスクローラー）に任せます。`html` や `body` の高さを固定し、その内側の要素に `overflow: auto` を指定してページをスクロールさせると、見た目はほとんど変わらないまま、ブラウザがページのスクロールのために用意した機能が使えなくなります。高さは `min-block-size` で最小値だけを決め、画面に留めたい要素は `position: sticky` で留め、横のはみ出しは `overflow-x: clip` で切り取ります。

## ルートスクローラーとは何か

ルートスクローラーは、文書全体をスクロールさせるスクロールコンテナのことです。仕様の上では、ビューポートがスクロールするという形で定義されています。ブラウザの実装や解説では、これをルートスクローラーと呼びます。何も指定していないページで、マウスホイールやスクロールバーを動かしたときにスクロールしているのは、このビューポートです。

ビューポートは要素ではないので、CSSを直接は指定できません。そのため、`overflow` はルート要素（`html`）からビューポートへ伝わる仕組みになっています。CSS Overflow Module Level 3では、ルート要素の `overflow` をビューポートに適用すると定めています。ただし、ルート要素の値が両方の軸で `visible` のときは、代わりに `body` の値を適用します。値を伝えた側の要素は、`overflow` が `visible` として扱われます。`body` だけに指定した `overflow-x: hidden` がページ全体の横スクロールを止めるのは、この伝播のためです。

JavaScriptからは、`document.scrollingElement` でルートスクローラーに対応する要素を取得できます。CSSOM Viewでは、標準モードの文書ではルート要素を、互換モード（`<!doctype html>` のない文書）では条件付きで `body` を返すと定めています。注意したいのは、この値が「ページがどの要素でスクロールしているか」を調べた結果ではないことです。内側のラッパーがスクロールしていても、標準モードなら `html` が返ります。

一方、`overflow` が `auto`、`scroll`、`hidden` の要素は、それぞれがスクロールコンテナになります。この節で入れ子のスクロールコンテナと呼ぶのは、ページ全体を包む要素が、ビューポートの代わりにページの内容をスクロールさせている状態です。表やコードブロックのように、ページの一部だけを横にスクロールさせる要素は、ここでは問題にしません。

## ルートスクローラーだけが持つ機能

ブラウザがページのスクロールのために用意した機能の多くは、ルートスクローラーだけを対象にしています。ページを入れ子のスクロールコンテナでスクロールさせると、見た目は同じでも、これらの機能が使えなくなります。

1つは、JavaScriptのAPIです。`window.scrollY` はビューポートのスクロール量を返し、`window.scrollTo()` はビューポートをスクロールさせます。スクロールのイベントも、ビューポートがスクロールしたときは `Document` で発生して `window` まで伝わりますが、要素がスクロールしたときはその要素で発生するだけで、伝わりません。ページをラッパーでスクロールさせると、`window.scrollY` は0のまま変わらず、`window` に登録したスクロールのイベントも発生しません。スクロール量でヘッダーの見た目を変える処理や、外部の解析ツールのスクロール計測が、何も起きないまま動かなくなります。

もう1つは、操作の機能です。SpaceキーやPage Downキーでページを送る操作は、ページを開いた直後でも、どこにもフォーカスがない状態でもルートスクローラーに効きます。入れ子のスクロールコンテナは、クリックやTabキーでその中にフォーカスを移すまで、キーで送れないことがあります。{/* 要確認: 出典なし */}リンク先から戻ったときのスクロール位置の復元も、HTMLの仕様ではスクロールできる領域が対象とされていますが、確実に働くのはビューポートです。入れ子のスクロールコンテナでは、ブラウザや中身の描画のタイミングによって、先頭に戻ってしまうことがあります。{/* 要確認: 出典なし */}

印刷も影響を受けます。印刷では、ページの全体が複数の用紙に分けて出力されます。高さを固定したラッパーの中でスクロールしている内容は、見えている範囲だけを1枚に収め、残りを出力しないことがあります。{/* 要確認: 出典なし */}

モバイルのブラウザには、さらに多くの機能があります。下にスクロールするとアドレスバーなどのUIが縮んで本文を広く表示する、上端を越えて引っ張るとページを再読み込みする、iOSのSafariで画面上端をタップすると先頭に戻る、といった動きです。Chromeの開発者が書いた提案の説明では、これらは文書のスクロールだけを対象にした機能として挙げられています。2026年10月の時点で、各ブラウザの公式の資料では、すべてを確かめられていません。{/* 要確認: 出典なし */}

## 入れ子のスクロールコンテナになる2つの書き方

ページ全体が入れ子のスクロールコンテナになる書き方は、2つに分けられます。1つは、意図してページ全体をラッパーの中でスクロールさせるものです。ヘッダーとサイドバーを画面に残したまま本文だけをスクロールさせる管理画面や、全画面の演出をするページで見かけます。

```css title="🙅‍♂ Not Recommended: html と body を固定し、ラッパーをスクロールさせる"
/* 🙅‍♂ Not Recommended */
html,
body {
  overflow: hidden;
  block-size: 100%;
}

.page-wrapper {
  overflow-y: auto;
  block-size: 100%;
}
```

この例では、ルート要素の `overflow: hidden` がビューポートに伝わり、ページそのものはスクロールしなくなります。ラッパーが、画面と同じ高さのスクロールコンテナとして、ページの内容をスクロールさせます。前の見出しで挙げた機能は、どれもラッパーでは働きません。

もう1つは、意図しないまま入れ子になるものです。横スクロールを防ぐ `overflow-x: hidden` と、全画面のレイアウトのための `height: 100%` を、`html` と `body` の両方に指定すると起きます。

```css title="🙅‍♂ Not Recommended: html と body に、overflow-x: hidden と height: 100% を指定する"
/* 🙅‍♂ Not Recommended */
html,
body {
  overflow-x: hidden;
  height: 100%;
}
```

ルート要素の `overflow` が `visible` ではないので、伝わるのはルート要素の値だけで、`body` の `overflow-x: hidden` は `body` 自身に残ります。さらに、片方の軸が `hidden` のとき、もう片方の軸の `visible` は `auto` として計算されます。そのため、`body` は縦方向のスクロールコンテナになります。高さが `100%` に固定されているので、内容は `body` の中でスクロールし、ビューポートはスクロールしなくなります。`height: 100%` がなければ、`body` は内容の高さまで伸びるのでスクロールはしません。それでも `body` はスクロールコンテナのままなので、中の `position: sticky` が留まらなくなります（「[7-9 positionの基礎](/layout/positioning/)」）。

## ページがどこでスクロールしているかを確かめる

ページが入れ子のスクロールコンテナでスクロールしているかは、見た目からは分かりません。DevToolsのコンソールで、ページを少しスクロールしてから `window.scrollY` を調べるのが手早い方法です。ルートスクローラーでスクロールしていれば0より大きい値が返り、入れ子のスクロールコンテナなら0のままです。

```js title="DevTools のコンソールで、スクロールしている場所を確かめる"
// ページを少しスクロールしてから実行する。0 なら、ページはビューポートでスクロールしていない
console.log(window.scrollY);

// スクロールのイベントは伝わらないので、捕捉の段階で受け取り、発生した場所を表示する
document.addEventListener('scroll', (event) => console.log(event.target), { capture: true });
```

2つ目の処理は、スクロールしたときに、スクロールした場所を表示します。ルートスクローラーなら `#document` が、入れ子のスクロールコンテナならその要素が表示されます。

スクロールしている要素が分かったら、DevToolsの要素のパネルで、その要素と祖先の `overflow` と `height` を確かめます。`html` と `body` の `overflow` は、ビューポートに伝わった値も計算値として要素に表示されます。値が表示されていることだけでは、スクロールコンテナかどうかは決まらないので、伝播の規則に当てはめて読み取ります。

## 用途ごとの直し方

入れ子のスクロールコンテナは、多くの場合、ほかの目的を果たすための手段として作られています。直すときは、その目的を確かめ、スクロールコンテナを作らない方法に置き換えます。よくある目的は、フッターを下端に置くこと、ヘッダーやサイドバーを留めること、横のはみ出しを隠すこと、モーダルの背面を止めることの4つです。

内容が短いページでもフッターを画面の下端に置きたいなら、高さを固定せず、最小の高さを決めます。`height: 100%` で固定すると内容があふれ、あふれた分を収めるための `overflow` が必要になります。最小値であれば、内容が長いときは要素が伸び、スクロールはビューポートで起きます。

```css title="🙆‍♂ Recommended: ページのレイアウトに最小の高さを決め、フッターを下端に置く"
@scope (.scoped.site-layout) to (.scoped) {
  :scope {
    display: block grid;
    grid-template-rows: auto 1fr auto;
    min-block-size: 100svb;
  }
}
```

kiso.cssは、`body` に `min-block-size: 100dvb` を指定しています（kiso.css 1.2.4で確認）。`body` の直下にページのレイアウトの要素を置く場合、その要素に `min-block-size: 100%` と書いても効きません。親の `body` の高さが最小値でしか決まっておらず、`%` の基準にならないからです。そこで、レイアウトの要素にも `100svb` を指定します。内容が画面より短いページはスクロールしないので、ブラウザのUIは表示されたままで、小さいほうのビューポートの高さが見えている高さと一致します。ビューポート単位の使い分けは「[6-2 ビューポート単位とコンテナ単位](/values/viewport-and-container-units/)」で説明しています。

ヘッダーやサイドバーを画面に残したいなら、ページの高さを固定して本文だけをスクロールさせるのではなく、`position: sticky` で留めます。ページ全体はビューポートでスクロールし、留めたい要素だけがその中で位置を保ちます。

```css title="🙆‍♂ Recommended: 本文をスクロールさせず、サイドバーを sticky で留める"
@scope (.scoped.app-layout) to (.scoped) {
  :scope {
    display: block grid;
    grid-template-columns: calc(240 / 16 * 1rem) 1fr;
    min-block-size: 100svb;
  }

  ._sidebar {
    position: sticky;
    inset-block-start: 0;
    align-self: start;
    overflow-y: auto;
    max-block-size: 100svb;
  }
}
```

サイドバーに指定した `overflow-y: auto` は、サイドバーの中身が画面より長いときのためのもので、ページのスクロールには関わりません。`align-self: start` と高さの上限が必要な理由は「[7-9 positionの基礎](/layout/positioning/)」で説明しています。ヘッダーを留めるなら、ビューポートの高さが十分なときだけにします（「[11-5 固定ヘッダー](/layout-practice/sticky-header/)」）。

## はみ出しの切り取りとモーダルの背面

横のはみ出しを隠したいなら、`hidden` ではなく `clip` を使います。`clip` ははみ出した部分を切り取るだけで、スクロールコンテナを作りません。`html` と `body` の両方に `overflow-x: clip` を指定しても、ルート要素の値はビューポートに伝わり、ビューポートでは `hidden` として扱われます。`body` に残った `clip` はスクロールコンテナを作らないので、ページは引き続きビューポートでスクロールします。書き方は「[11-3 変化に強いレイアウト](/layout-practice/defensive/)」のルール[`overflow-clip-over-hidden`](/layout-practice/defensive/#rule-overflow-clip-over-hidden)のとおりです。

<Baseline id="overflow-clip" />

ただし、`clip` は、はみ出した要素を直したうえでの備えです。あわせて、`html` と `body` から `height: 100%` を外します。`clip` に変えればスクロールはビューポートに戻りますが、`body` の高さは画面の高さのままで、内容は `body` の外へはみ出します。`body` の高さを基準にしたレイアウトが崩れる原因になるので、高さの固定もやめます。

モーダルを開いている間の背面のスクロールは、`:root:has(:modal)` に `overflow: hidden` を指定して止めます（「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」のルール[`modal-scroll-lock-root`](/reset/base-styles/#rule-modal-scroll-lock-root)）。ルート要素の `overflow` はビューポートに伝わるので、止めているのはルートスクローラーです。ページが入れ子のスクロールコンテナでスクロールしていると、この指定は何も止めません。スクロールバーが消えたときのずれは、kiso.cssが `:root` に指定している `scrollbar-gutter: stable` で防ぎます。

## ルートに書くスクロールの指定

ページのスクロールに関わるプロパティには、ルート要素に指定するとビューポートに適用されるものがあります。`scroll-behavior` は、CSSOM Viewで、ルート要素の値がビューポートに適用されると定められています。`scroll-padding` と `scroll-snap-type` も、CSS Scroll Snapで同じ扱いです。どれも、`overflow` と違い、`body` の値はビューポートに伝わりません。

本書のほかの節の指定も、この仕組みを前提にしています。「[8-2 ベーススタイルに書くもの](/reset/base-styles/)」では、スムーススクロールを `:root` に指定しています。「[11-5 固定ヘッダー](/layout-practice/sticky-header/)」では、固定ヘッダーの高さを `:root` の `scroll-padding-block-start` で除いています。ページを入れ子のスクロールコンテナでスクロールさせると、これらの指定も効かなくなります。

ページを開いたときの最初のスクロール位置をCSSで決める `scroll-initial-target` も、CSS Scroll Snap Module Level 2で定義されています。要素に `scroll-initial-target: nearest` を指定すると、いちばん近い祖先のスクロールコンテナは、最初からその要素の位置までスクロールした状態で表示されます。間にほかのスクロールコンテナを挟まない要素なら、スクロールするのはルートスクローラーです。ただし、2026年10月の時点で対応しているのはChrome 133以降だけなので、本書では今のところ採用しません。ほかのブラウザではページが先頭から表示され、最初に見せる内容がブラウザによって変わるからです。ページの途中から見せたいときは、URLのフラグメント（`#` のあとのID）でその要素へ移動させます。

<Baseline id="scroll-initial-target" />

文書の先頭の `<!doctype html>` も確かめます。これがない文書は互換モードで描画され、`document.scrollingElement` が `body` を返すなど、スクロールの扱いが標準モードと変わります。HTMLの構文解析の規則では、doctypeより前に空白以外の文字があっても互換モードになります。

AIが生成するコードでは、`html, body { height: 100%; }` に `overflow-x: hidden` を加えた組み合わせをよく見かけます。どちらも単独では理由のある指定に見えるので、レビューで見落としやすい組み合わせです。`html` と `body` に `height` や `overflow` が指定されていたら、ページがビューポートでスクロールしているかを、前の方法で確かめます。
