この章では、要素を並べる、間を空ける、重ねるといったレイアウトの書き方を扱います。レイアウトは、まず親の `grid-template` で配置と余白を決められないかを考え、子要素の側には配置のための指定をなるべく書きません。そのうえで、内容の長さや量が変わっても崩れないように、守りの指定を加えます。

私が勧めているのは、FlexboxではなくGridから考え始めることです。「1次元ならFlexbox、2次元ならGrid」という分け方が広まっていますが、1行の並びでもGridのほうが簡潔に書ける場面は多くあります。何でもFlexboxで組むと、子要素の側に幅の計算や打ち消しの指定が散らばり、レイアウトの全体像がどこにも書かれていない状態になりがちです。

もうひとつ大事にしているのは、内容が変わっても崩れないことです。一般的なWebサイトは公開後も更新が続き、とくにCMSの案件では、デザインカンプにない長さの見出しや、画像のない記事が入ってきます。既存のサイトの改修では、長いURLや入力欄が枠を突き抜ける不具合を直す作業が、定期的に発生します。こうした不具合の多くは、書くときに「もし〜だったら」と考えておけば防げるという印象です。

この章は次の15の節で構成しています。8-1〜8-7は、ほかの節が前提にしている仕組みと、レイアウトの方式ごとの基礎です。

- [8-1 レイアウトの基礎](/layout/fundamentals/)：レイアウトの方式の全体像、方式を決める親の `display`、包含ブロックの要約、重なり、FlexboxとGridの配置のプロパティ
- [8-2 通常フローの基礎](/layout/normal-flow/)：ブロック方向とインライン方向、ブロックとインラインのボックス、行ボックスと匿名ボックス、幅と高さの決まり方、`display: flow-root`
- [8-3 ボックスモデルの基礎](/layout/box-model/)：内容・`padding`・`border`・`margin` の領域、`box-sizing`、大きさの決まり方と `%` の基準
- [8-4 マージンの相殺](/layout/margin-collapse/)：相殺が起きる条件と起きない条件、負のマージンを含む計算、相殺の止め方
- [8-5 Flexboxの基礎](/layout/flexbox-basics/)：主軸と交差軸、`flex-grow`・`flex-shrink`・`flex-basis` による空間の配り方、折り返し
- [8-6 Gridの基礎](/layout/grid-basics/)：トラック・線・エリアの用語、明示的なグリッドと暗黙のグリッド、配置のプロパティ
- [8-7 positionの基礎](/layout/positioning/)：`position` の5つの値、包含ブロック、`sticky` が留まらない原因、固定ヘッダー、アンカーポジショニング、重なりの検出
- [8-8 Gridから考える](/layout/grid-first/)：FlexboxとGridの使い分け、`grid-template` のエリア、サブグリッドでそろえるカード
- [8-9 余白を設計する](/layout/spacing/)：`gap` と `margin` の使い分け、空のグリッドセルで作る余白、本文の流れの余白
- [8-10 変化に強いレイアウト](/layout/defensive/)：内容の長さや量が変わっても崩れない書き方（ディフェンシブCSS）
- [8-11 重なりと全幅](/layout/layering/)：Gridで要素を重ねる方法、スタッキングコンテキストと重なり順、画面幅いっぱいに広げる手法
- [8-12 ページのスクロールとルートスクローラー](/layout/root-scroller/)：ページ全体のスクロールを入れ子のスクロールコンテナにしてしまう原因と、用途ごとの直し方
- [8-13 grid-lanesで石積みのレイアウトを組む](/layout/masonry/)：高さの違う項目を詰める `display: block grid-lanes`、未対応の環境へのフォールバック、`columns` との使い分け
- [8-14 コンポジション集](/layout/compositions/)：stack、cluster、switcher、gridなど、配置のパターンを部品にしたコンポジションの使い方と使い分け（8-14-1〜8-14-11）
- [8-15 表示順と読み上げ順を合わせる](/layout/reading-flow/)：並べ替えた配置で、読み上げとフォーカスの順番を `reading-flow` で見た目に合わせる書き方と、DOMの順番を先に直す理由

コンポーネントのルートに外側の余白を持たせない考え方と、z-indexの管理は[第7章「コンポーネントとカスタムプロパティ」](/components/)で扱います。幅に応じてレイアウトを切り替える方法は[第9章「レスポンシブデザイン」](/responsive/)で、フレックスアイテムとグリッドアイテムの最小幅を0にするベーススタイルは[第5章「リセットとベーススタイル」](/reset/)で説明しています。

この章のコード例では、説明に関係しない `@layer` の記述を省略しています。デモのCSSには省略せずに書いています。

## 最初に押さえるルール

{/* 要確認: 著者の優先順位で選び直す（レビューの提案にもとづく下書き） */}

次のルールを先に押さえ、ほかのルールは、該当する場面で付録A「[ルール一覧](/appendix/rules/)」から引けば足ります。

- [`minmax-min-capped-at-100-percent`](/layout/defensive/#rule-minmax-min-capped-at-100-percent)：`minmax()` の最小値や `min-inline-size` に固定の長さを書くときは、`min(100%, …)` で親の幅を上限にします。
- [`overflow-clip-over-hidden`](/layout/defensive/#rule-overflow-clip-over-hidden)：はみ出しを切り取るだけなら、`overflow: hidden` ではなく `clip` を使います。
- [`sticky-align-self-start`](/layout/positioning/#rule-sticky-align-self-start)：GridやFlexboxの子に `position: sticky` を指定するときは、その要素に `align-self: start` も指定します。
- [`full-bleed-offset-formula`](/layout/layering/#rule-full-bleed-offset-formula)：親の幅を超えて画面の端まで広げる量は「画面の幅と親の幅の差の半分」の式で書き、`100vw` を使いません。
- [`flexbox-no-visual-reorder`](/layout/flexbox-basics/#rule-flexbox-no-visual-reorder)：フォーカスできる要素や順番に意味のある要素を、`order` や `row-reverse` で見た目だけ入れ替えません。
