CSSのレイアウトは、1つの仕組みではなく、通常フロー、Flexbox、Grid、位置指定（`position`）といった複数の方式の組み合わせでできています。同じ `margin` や `align-items` でも、要素がどの方式の中に置かれているかで、効き方が変わります。指定が思いどおりに効かないときは、値を足す前に、その要素がどの方式の中にあるかを確かめます。

あわせて確かめるのは、大きさや位置の基準になる要素（包含ブロック）と、重なり順を決める範囲（スタッキングコンテキスト）です。この節では、ほかの節が前提にしているこれらの仕組みを、一通り説明します。ボックスモデル、マージンの相殺、Flexbox、Gridは、続く7-2〜7-5でそれぞれ詳しく説明します。仕組みを知っていれば、「なぜ効かないのか」を推測ではなく理由から説明できます。

## 「効かない」指定はどこから来るのか

レイアウトの不具合を直すとき、値を少しずつ変えて見た目を合わせる人は少なくありません。インライン要素に `margin-block` を付けても上下が空かない、`vertical-align: middle` にしても真ん中に来ない、`position: sticky` が留まらない、といった場面です。こうした指定は、壊れているわけではなく、その方式の規則どおりに振る舞っています。

規則を知らないまま値を足すと、不具合は見た目の上では消えても、原因は残ります。たとえば、インライン要素の上下の余白を `position: relative` と `top` でずらして作ると、その要素だけが行から浮き、文字の大きさを変えたときに重なります。正しい直し方は、要素を `inline flow-root` にして、ブロックの規則で余白を持たせることです。直し方を選ぶには、どの方式の規則が働いているかを知る必要があります。

AIが生成するコードにも、同じ傾向があります。方式の違いを考えずに、`display: flex` と `align-items: center` を何にでも足し、効かなければ `position: absolute` で位置を合わせるコードはよく見かけます。レビューで「なぜこの指定が要るのか」を問うためにも、方式ごとの基本の振る舞いを押さえておきます。

## 通常フローの2つの方向

何も指定しない要素は、通常フローという方式で並びます。通常フローには2つの方向があります。ブロックレベルの要素は、ブロック方向（横書きでは上から下）に積まれます。インラインの要素と文字は、インライン方向（横書きでは左から右）に流れ、行の端で折り返します。

この2つの方向は、物理的な上下左右ではなく、`writing-mode` で決まります。縦書きにすると、ブロック方向は右から左に、インライン方向は上から下に変わります。本書が `width` や `margin-top` ではなく、`inline-size` や `margin-block-start` のような論理プロパティを使うのは、書字方向が変わっても同じ意味で働くからです。論理プロパティについては「[5-3 モダンな記法にそろえる](/notation/modern-syntax/)」で説明しています。

ブロックの中に文字とインライン要素が混ざると、ブラウザは要素に包まれていない文字にも、目に見えない箱（匿名ボックス）を作ります。`<p>これは<em>強調</em>です</p>` なら、「これは」と「です」がそれぞれ匿名のインラインボックスになり、`<em>` と並んで1行に流れます。匿名ボックスにはクラスを付けられないので、スタイルは親から継承した値で決まります。

匿名ボックスは、HTMLの改行や空白からも作られます。要素を `inline flow-root`（`inline-block`）にして横に並べると、タグの間の改行が1文字分の空白として行に入り、要素の間に意図しない隙間ができます。

```css title="🙅‍♂ Not Recommended: inline-block で横に並べる"
/* 🙅‍♂ Not Recommended */
.tag-list > li {
  display: inline-block;
  margin-right: 8px;
}
```

この隙間は、親の `font-size` によって幅が変わるので、`margin` の値を調整しても消えません。親の `font-size` を0にする、HTMLの空白を消すといった回避策もありますが、どれも別の副作用を生みます。要素を横に並べるときは、Flexboxにして `gap` で間隔を決めます。Flexboxのアイテムの間にある空白は、匿名ボックスにならないからです。

```css title="🙆‍♂ Recommended: Flexbox にして gap で間隔を決める"
.tag-list {
  display: block flex;
  flex-wrap: wrap;
  gap: 8px;
}
```

## `display` の外側と内側

`display` の値は、2つの役割を持っています。1つは、その要素が親のレイアウトの中でブロックとして積まれるか、インラインとして流れるかという外側の振る舞いです。もう1つは、その要素の子をどの方式で並べるかという内側の振る舞いです。本書が `display: block flex` のような2値構文で書くのは、この2つを分けて読めるようにするためです（「[5-3 モダンな記法にそろえる](/notation/modern-syntax/)」）。

`inline-block` は、2値構文では `inline flow-root` になります。外側はインラインなので、文字と同じ行に並び、ベースラインにそろいます。内側は `flow-root` なので、新しいブロック整形コンテキストを作り、`inline-size` や上下の `padding` と `margin` が効きます。インライン要素に上下の余白を付けたいときに `inline flow-root` を選ぶのは、この内側の性質を使うためです。

`flow-root` は、中の子のマージンが外へ出ない、`float` が外へはみ出さない、という独立した範囲（ブロック整形コンテキスト）を作る値です。親子のマージンの相殺を止める手段として、「[7-3 マージンの相殺](/layout/margin-collapse/)」でも使っています。`display: flex` や `grid` も内側の値で、子を通常フローではなく、それぞれの方式で並べます。

## ボックスの大きさと包含ブロック

すべての要素は、内側から順に、内容、`padding`、`border`、`margin` の層を持つ箱として扱われます。kiso.cssはすべての要素を `box-sizing: border-box` にしているので、本書のコード例では、`inline-size` は `border` までを含んだ幅です（「[4-1 壊さないリセット](/reset/kiso/)」）。

`inline-size: 50%` のような `%` は、包含ブロックの大きさに対する割合です。包含ブロックは、通常フローの要素なら、たいていはいちばん近いブロックの親の内容の領域です。上下の `padding` や `margin` の `%` もインライン方向の大きさに対する割合になること、`margin-inline: auto` で中央に寄る仕組みなど、大きさの決まり方は「[7-2 ボックスモデルの基礎](/layout/box-model/)」で詳しく説明しています。

位置指定の要素は、包含ブロックの決まり方が違います。`position: absolute` の要素は、`position` が `static` 以外のいちばん近い祖先の `padding` の領域を基準にし、`fixed` の要素はビューポートを基準にします。ただし、祖先に `transform` などがあると、その祖先が包含ブロックになります。詳しくは「[7-9 重なりと配置](/layout/positioning/)」で説明しています。

## インラインのボックスと行

インラインの要素は、行の中に並びます。行の高さは `line-height` で決まり、行の中の要素は、デフォルトでは文字のベースライン（アルファベットの下端の線）にそろいます。インライン要素に上下の `padding` や `border` を付けると、背景は広がって見えますが、行の高さは変わらず、上下の行と重なります。

`vertical-align: middle` は、要素の中心を、親のベースラインからx-height（小文字の「x」の高さ）の半分だけ上の位置に合わせる指定です。フォントのx-heightで位置が決まるので、行の見た目の真ん中とは一致しないことがあります。アイコンと文字の中央をそろえたいときは、親をFlexboxやGridにして `align-items: center` を使います。この場合は、生成された箱の大きさで中央が決まり、フォントの寸法に左右されません。

画像の下に数ピクセルの隙間ができる現象も、ベースラインが原因です。`<img>` はインラインの要素なので、ベースラインに下端をそろえ、その下には文字のディセンダー（「g」や「y」の下に出る部分）のための空きが残ります。kiso.cssは、画像や動画に `vertical-align: bottom` を指定して、この隙間をなくしています。

インライン要素が複数の行にまたがると、背景、`border`、`padding` は、各行の断片に分けて描かれます。デフォルトでは1つの帯を行の端で切ったように描かれ、行の端の `padding` と角丸は失われます。各行の断片をそれぞれ独立した箱として描きたいときは、`box-decoration-break: clone` を指定します。Safariは接頭辞付きの `-webkit-box-decoration-break` だけに対応しています（2026年10月確認）。{/* 要確認: 出典なし */}

## 配置の方式と重なり

`position` を指定すると、要素は位置指定の方式で配置されます。`relative` と `sticky` は、通常フローの中に場所を残したまま、`inset` の値だけずらします。`absolute` と `fixed` は、通常フローから外れ、元の場所は詰められます。

| `position` | 通常フローに場所を残すか | 位置の基準 |
|---|---|---|
| `static` | 残す | なし（`inset` は効かない） |
| `relative` | 残す | 元の位置 |
| `absolute` | 残さない | `static` 以外のいちばん近い祖先 |
| `fixed` | 残さない | ビューポート |
| `sticky` | 残す | いちばん近いスクロールする祖先 |

要素の前後の重なりは、デフォルトではHTMLの順番で決まり、後に書いた要素が手前に描かれます。`z-index` で順番を変えられるのは、同じスタッキングコンテキストの中だけです。親が `z-index: 1` のスタッキングコンテキストを作っていれば、子に `z-index: 99` を指定しても、親の兄弟の `z-index: 2` の要素より手前には出ません。スタッキングコンテキストは、`opacity` が1未満の要素や、`transform` を持つ要素などでも作られます。意図して作るときは `isolation: isolate` を使います。仕組みは「[7-9 重なりと配置](/layout/positioning/)」で、`sticky` が留まらない原因は「[7-11 sticky が動かないとき](/layout/sticky/)」で説明しています。

## FlexboxとGridが通常フローを置き換える

`display` の内側を `flex` や `grid` にすると、その要素の子は、通常フローではなくFlexboxやGridの規則で並びます。子の外側の値は無視され、`<span>` のようなインラインの要素も、ブロックのように大きさを持つアイテムになります。マージンの相殺も、アイテムの間では起きません。

Flexboxは、アイテムの中身の大きさから出発して、余った空間や足りない空間をアイテムに配ります。Gridは、先に親で行と列を決め、アイテムをそのセルに置きます。前者は中身から外へ、後者は外から中身へと大きさを決める、と言い換えることもできます。それぞれの仕組みは「[7-4 Flexboxの基礎](/layout/flexbox-basics/)」と「[7-5 Gridの基礎](/layout/grid-basics/)」で、本書がGridから考え始める理由は「[7-6 Gridから考える](/layout/grid-first/)」で説明しています。

配置のプロパティは、`*-items` と `*-content` で対象が違います。`align-items` は、各アイテムを、自分に割り当てられた領域（Gridならセル）の中でそろえます。`align-content` は、行や列のまとまり全体を、コンテナの中でそろえます。コンテナに余白があるときに、この違いが見た目に現れます。Gridでの使い分けは「[7-5 Gridの基礎](/layout/grid-basics/)」で詳しく説明しています。

`align-content` は、2024年からブロックコンテナにも使えるようになりました（2026年10月確認）。親を `display: block grid` に変えなくても、`align-content: center` だけで、中身を上下の中央に置けます。ただし、ブロックコンテナでは `justify-content` は効かないので、左右の中央寄せは、`margin-inline: auto` か、親をGridにして `place-content: center` で書きます。{/* 要確認: 出典なし */}
