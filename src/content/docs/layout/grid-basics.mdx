Gridは、親の要素で線とトラック（行と列）を決め、子をその線に合わせて置くレイアウトの方式です。トラックの大きさは `fr`、`minmax()`、`repeat()` で書き、行の数がアイテムの数で変わるなら、行は `grid-template-rows` ではなく `grid-auto-rows` で決めます。意味のある位置に置くアイテムは、線の番号ではなく、`--` で始まる線の名前で指定します。

Gridの指定で読み違えが起きやすいのは、3つの区別です。明示的なグリッドと暗黙のグリッドの区別、配置のプロパティの `*-items` と `*-content` の区別、そしてトラックの最小幅を中身で決めるのか0にするのかの区別です。Gridを選ぶ理由と `grid-template` のエリアは「[7-6 Gridから考える](/layout/grid-first/)」で扱います。

## Gridの指定はどこで読み違えられるのか

Gridは2017年から主要なブラウザで使えますが、Gridを使ったコードには、書いた人の意図と違う振る舞いがよく紛れ込みます。原因の多くは、構文の誤りではなく、グリッドの仕組みの読み違えです。

典型的なのは、`grid-row: 1 / -1` でサイドバーを全行にまたがらせたつもりが、途中の行で止まってしまう例です。`-1` は、アイテムが増えて足された行を数に入れないからです。

配置のプロパティでは、`align-items: center` は効くのに `align-content: center` は効かない、あるいはその逆、という場面がよくあります。2つはそろえる対象が違うので、同じ値でも結果が変わります。

長いURLを含む `1fr` の列だけがほかの列より広がる、という現象もあります。どれも仕様どおりの振る舞いなので、値を足して見た目を合わせる前に、どの規則が働いているかを確かめます。

## グリッドを構成するものの名前

`display: block grid` を指定した要素をグリッドコンテナ、その直接の子をグリッドアイテムと呼びます。孫の要素はアイテムではないので、親のグリッドには参加しません。孫を親のトラックに合わせたいときは、子をサブグリッドにします（「[7-6 Gridから考える](/layout/grid-first/)」）。要素に包まれていない文字も、匿名のアイテムとして1つのセルを占めます。

グリッドを区切る線をグリッド線と呼びます。隣り合う2本の線の間の帯がトラックで、横方向に並ぶものが列、縦方向に並ぶものが行です。3列のグリッドには、列の線が4本あります。線の番号は、インライン方向とブロック方向の始まりの側から1、2、3と数え、終わりの側からは-1、-2と数えます。始まりの側は書字方向で決まり、`direction: rtl` の文書では右端が1本目の線になります。

1つの行と1つの列が交わる区画をセルと呼び、これがグリッドの最小の単位です。4本の線で囲まれた、1つ以上のセルからなる長方形の範囲をグリッドエリアと呼びます。アイテムは、線を指定してエリアに置かれます。トラックとトラックの間の隙間は、`gap` で作る溝（ガター）です。

## トラックの大きさを決める `fr`、`minmax()`、`repeat()`

列の大きさは `grid-template-columns`、行の大きさは `grid-template-rows` に、トラックごとの値を空白で区切って並べます。値には、長さ、中身の大きさを表す `min-content`、`max-content`、`auto`、そして `fr` が使えます。

`fr` は、固定の大きさのトラックと `gap` を引いた残りの空間を、比率で分ける単位です。`calc(200 / 16 * 1rem) minmax(0, 2fr) minmax(0, 1fr)` なら、200px相当の列と溝を除いた残りを、2対1で分けます。溝を除いてから分けるので、`%` で分けたときのように、列の合計が溝の分だけ親の幅を超えることはありません。

```css title="🙆‍♂ Recommended: 固定の列を除いた残りを、fr の比率で分ける"
._layout {
  display: block grid;
  grid-template-columns: calc(200 / 16 * 1rem) minmax(0, 2fr) minmax(0, 1fr);
  gap: 24px;
}
```

`minmax(最小, 最大)` は、トラックの大きさに下限と上限を付ける関数です。最大が最小より小さいときは、最大が無視され、最小の値になります。`fr` は最大の側にだけ書けて、`minmax(1fr, 200px)` のように最小の側に書くと、宣言全体が無効になります。単独で書いた `1fr` は、`minmax(auto, 1fr)` として扱われます。この `auto` の下限が「`1fr` が等分にならない」原因で、仕組みはこの節の後半の「アイテムの最小幅と `gap`」で説明します。

`repeat(回数, トラック)` は、同じトラックの並びを繰り返す関数です。`repeat(3, minmax(0, 1fr))` は等分の3列になり、`repeat(2, minmax(0, 2fr) minmax(0, 1fr))` のように複数のトラックの組も繰り返せます。回数の代わりに `auto-fill` か `auto-fit` を書くと、最小の幅を下回らない範囲で入るだけの列を作ります。2つの違いはアイテムが列の数より少ないときに現れ、`auto-fill` は空の列を残し、`auto-fit` は空の列を幅0に折りたたみます。使い分けは「[8-1 検討する順番](/responsive/escalation/)」と「[7-13-6 grid](/layout/compositions/grid/)」で説明しています。

## 明示的なグリッドと暗黙のグリッド

`grid-template-*` のプロパティで決めたトラックを、明示的なグリッドと呼びます。アイテムが明示的なセルより多いときや、外の線を指定されたときにブラウザの足すトラックを、暗黙のグリッドと呼びます。暗黙のトラックの大きさは、`grid-auto-rows` と `grid-auto-columns` で決まり、どちらも初期値は `auto`（中身の大きさ）です。

カードの一覧のように、行の数がアイテムの数で決まるグリッドでは、行を明示的に決める意味がありません。`grid-template-rows: repeat(2, 160px)` と書くと、3行目からは暗黙の行になり、160pxではなく中身の高さで並びます。行の大きさを `grid-auto-rows` で決めれば、何行になっても同じ高さで並びます。

```css title="🙅‍♂ Not Recommended: アイテムの数で行数が変わるのに、行を明示的に決める"
/* 🙅‍♂ Not Recommended */
._gallery {
  display: block grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  grid-template-rows: repeat(2, 160px);
}
```

```css title="🙆‍♂ Recommended: 暗黙の行の大きさを grid-auto-rows で決める"
._gallery {
  display: block grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  grid-auto-rows: calc(160 / 16 * 1rem);
  gap: 16px;
}
```

アイテムを自動で置く向きは、`grid-auto-flow` で決まります。初期値の `row` では、アイテムを行の端まで順に詰め、足りなくなると暗黙の行を足します。`column` にすると、列の方向に詰め、足りなくなると暗黙の列を足します。`grid-auto-flow: column` と `grid-auto-columns: minmax(0, 1fr)` を組み合わせると、アイテムがいくつあっても1行に等分で並ぶ、ステップ表示のような並びが書けます。

`grid-auto-flow` に `dense` を加えると、複数のトラックにまたがるアイテムのせいで空いたセルへ、後ろのアイテムを先に詰めます。隙間は消えますが、見た目の順番だけが変わり、DOMの順番は変わりません。キーボードの移動と読み上げはDOMの順番のままなので、順序に意味のある並びには使いません（「[7-6 Gridから考える](/layout/grid-first/#rule-no-dense-for-ordered-items)」）。

## 線の番号と線の名前でアイテムを置く

アイテムを置く位置は、`grid-column` と `grid-row` に、始まりの線と終わりの線を `/` で区切って指定します。`grid-column: 2 / 4` は、2本目から4本目の線までの2列にまたがります。終わりの線の代わりに `span 2` と書くと、始まりの線から2トラック分にまたがります。明示的なグリッドより外の線を指定すると、そこまで暗黙のトラックが足されます。

終わりの側から数える負の番号は、明示的なグリッドの端から数えます。暗黙のトラックは数に入りません。`grid-column: 1 / -1` は、列を明示的に決めたグリッドでは端から端まで確実にまたがります。一方、行を決めていないグリッドで `grid-row: 1 / -1` と書くと、`-1` は1本目の線と同じになり、アイテムは1行分にしかまたがりません。

線には名前を付けられます。`grid-template-columns` のトラックの間に `[--content-start]` のように角括弧で名前を書き、アイテムの側でその名前を指定します。本書では、自分で付ける線とエリアの名前を `--` で始めます（「[5-1 命名規則](/notation/naming/)」）。`--content-start` と `--content-end` のように、`-start` と `-end` で終わる名前の組を付けると、その間は `--content` という名前のエリアとして扱われます。アイテムは `grid-column: --content` だけで置けます。

```css title="🙆‍♂ Recommended: 線に名前を付け、アイテムは名前で置く"
._page {
  display: block grid;
  grid-template-columns:
    [--full-start] minmax(16px, 1fr)
    [--content-start] minmax(0, calc(960 / 16 * 1rem))
    [--content-end] minmax(16px, 1fr)
    [--full-end];

  & > * {
    grid-column: --content;
  }

  & > ._hero {
    grid-column: --full;
  }
}
```

この例では、本文の列の左右に余白の列（ガター）を置き、通常のアイテムは本文の列に、`._hero` だけは画面の端から端まで置いています。同じ配置を `grid-column: 2 / 3` と `1 / 4` で書くと、列を1本足しただけで、すべてのアイテムの番号を直すことになります。名前なら、列を足しても名前の位置は変わらず、コードを読めば何の位置に置くのかが分かります。ガターの列を使う設計は「[7-7 余白を設計する](/layout/spacing/#rule-gutter-columns-for-content-width)」で説明しています。

名前を書き間違えたときの振る舞いは、見落としやすいので知っておきます。指定した名前の線がグリッドにないと、ブラウザは暗黙のトラックの線がすべてその名前を持つものとみなし、エラーを出さずに、アイテムを明示的なグリッドの外に置きます。配置がずれたときは、まず名前の綴りを確かめます。`grid-template-areas` で付けたエリアの名前も、同じように `-start` と `-end` の線の名前を作ります。

## `*-items` と `*-content` の違い

配置のプロパティは、方向と対象の組み合わせでできています。`justify-*` はインライン方向（横書きでは横）、`align-*` はブロック方向（横書きでは縦）を扱います。`*-items` は、各アイテムを自分のグリッドエリアの中でそろえ、`*-self` はそれを1つのアイテムだけ上書きします。`*-content` は、トラックのまとまり全体を、グリッドコンテナの中でそろえます。

`*-items` の初期値 `normal` は、Gridではアイテムをエリアいっぱいに伸ばす `stretch` として働きます。ただし、画像のように縦横比を持つアイテムは、伸ばされず `start` として扱われます。

`*-content` が効くのは、トラックの合計がグリッドコンテナより小さく、余りがあるときだけです。`fr` のトラックは余りをすべて受け取るので、`fr` の列だけのグリッドに `justify-content: center` を指定しても、何も変わりません。トラックの大きさを固定の長さや `max-content` で決めたときに、`place-content: center` でまとまりを中央に寄せたり、`space-between` で両端に散らしたりできます。

`*-content` の初期値 `normal` は、`auto` の大きさのトラックを余りの分だけ伸ばします。行を指定していないグリッドに高さを与えると、各行が中身の高さより広がり、余りを等分して受け取るのはこのためです。行を中身の高さのまま上に詰めたいなら、`align-content: start` を指定します。

`place-items` と `place-content` は、`align-*` と `justify-*` をまとめて書くショートハンドです。値を2つ書くときは、ブロック方向の `align-*` が先、インライン方向の `justify-*` が後になります。値が1つなら、両方の方向に同じ値が入ります。なお、Flexboxには `justify-items` と `justify-self` がなく、指定しても無視されます（「[7-4 Flexboxの基礎](/layout/flexbox-basics/)」）。

## コード例とデモ

次のデモは、3列のグリッドにアイテムを7つ置いたものです。左のグリッドは、`grid-template-rows: repeat(2, 64px)` で2行だけを明示的に決めています。3行目は暗黙の行になり、高さは64pxではなく中身の高さです。赤いアイテムは `grid-row: 1 / -1` ですが、明示的な2行にしかまたがりません。

右のグリッドは、`grid-auto-rows: 64px` で暗黙の行の大きさを決めています。どの行も64pxにそろいますが、明示的な行がないので、赤いアイテムは1行分にとどまります。

次のデモは、固定の大きさの2列2行のトラックを、高さ200pxのコンテナに置いたものです。`place-items: center` ではトラックは左上に残り、アイテムがセルの中で縮みます。`place-content: center` ではアイテムはセルいっぱいのまま、トラックのまとまりが中央へ移ります。

<Demo title="place-items と place-content の違い" html={alignmentHtml} css={alignmentCss} />

2つは対象が違うので、組み合わせても打ち消し合いません。アイコンの一覧をコンテナの中央に置き、アイコンもセルの中央に置くなら、両方を指定します。

```css title="🙆‍♂ Recommended: トラックのまとまりとアイテムを、それぞれ中央に置く"
._icon-list {
  display: block grid;
  grid-template-columns: repeat(4, calc(64 / 16 * 1rem));
  gap: 16px;
  place-content: center;
  place-items: center;
}
```

## アイテムの最小幅と `gap`

グリッドアイテムの `min-inline-size` の初期値 `auto` は、0ではありません。下限が `auto` のトラックにまたがるアイテムでは、中身の最小幅（`min-content` に近い値）が下限になります。単独の `1fr` は `minmax(auto, 1fr)` なので、長いURLや幅の大きい入力欄を含むアイテムは、その下限まで列を押し広げます。例外は、`overflow: auto` などでスクロールコンテナになったアイテムで、この場合の下限は0です。

防ぎ方は2つあります。1つは、トラックの側で `minmax(0, 1fr)` と書き、列の下限を0にする方法です（「[7-8 変化に強いレイアウト](/layout/defensive/#rule-minmax-zero-for-fr)」）。もう1つは、ベーススタイルの全称セレクタで `min-inline-size: 0` を指定し、アイテムの下限を0にする方法です（「[4-2 ベーススタイルに書くもの](/reset/base-styles/#rule-global-min-inline-size-zero)」）。本書は両方を使います。グリッドを書くコンポーネントの中で下限を決めておけば、ベーススタイルのない環境へ持ち出しても崩れないからです。

アイテムの間隔は、アイテムの `margin` ではなく、コンテナの `gap` で作ります（「[7-7 余白を設計する](/layout/spacing/#rule-gap-over-child-margin)」）。`gap` は行の間隔と列の間隔を順に書くショートハンドで、片方だけなら `row-gap` か `column-gap` で指定します。溝はトラックとトラックの間にだけ作られ、グリッドの外周にはできません。

溝はトラックではないので、線の番号にも数えられません。一方、溝は空のトラックの間にも作られます。`auto-fit` で折りたたまれた列の溝は一緒に消えますが、暗黙の行がたくさん作られたグリッドでは、高さ0の空の行の間にも溝が残ります。アイテムの数より行が多くなる指定をしたときは、溝の積み重なりで余白が広がっていないかを確かめます。
