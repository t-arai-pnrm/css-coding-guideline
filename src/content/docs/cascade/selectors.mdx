セレクタは、要素を選ぶと同時に、そのルールの詳細度を決めます。本書では、ベーススタイルのタイプセレクタを `:where()` で包んで詳細度を0にし、コンポーネントの中はクラス1つ分（0.1.0）を基本にそろえます。IDセレクタと、詳細度を上げるためだけのセレクタは使いません。

`:is()`、`:not()`、`:has()`、`of S` を付けた `:nth-child()` は、引数によって詳細度が変わります。詳細度の数え方と、カスケードの中での位置付けは「[2-1 カスケード・詳細度・継承](/cascade/cascade-basics/)」で説明しています。

## 詳細度がばらばらなセレクタ

詳細度の問題は、多くの場合、上書きしたい側ではなく、上書きされる側の書き方から始まります。次の例では、フォームのボタンと見出しのスタイルを上書きしようとして、うまくいきません。

```css title="🙅‍♂ Not Recommended: 詳細度がばらばらのセレクタ"
/* 🙅‍♂ Not Recommended */
input[type="submit"] {
  background-color: var(--background--accent);
}

/* 0.1.0 なので、上の 0.1.1 に負ける */
.submit-button {
  background-color: var(--background--muted);
}

#news h2 {
  font-size: calc(24 / 16 * 1rem);
}

/* 0.2.0 なので、上の 1.0.1 に負ける */
.news-list .title {
  font-size: calc(20 / 16 * 1rem);
}
```

`input[type="submit"]` は、タイプセレクタと属性セレクタで0.1.1になります。ボタンに `.submit-button` を付けても、0.1.0なので背景色を変えられません。見出しの例では、IDセレクタを含む `#news h2` が1.0.1になり、クラスをいくつ重ねても勝てなくなっています。

原因は、上書きされる側のセレクタが、必要以上に高い詳細度を持っていることです。上書きする側で工夫しても、さらに高い詳細度が必要になるだけです。そのため、詳細度はセレクタを書く最初の段階で低くそろえておきます。

## IDセレクタと詳細度を上げる技

IDセレクタでは、スタイルを指定しません。詳細度が1.0.0になり、クラスをいくつ重ねても上書きできないからです。オリジンと重要度とレイヤーが同じなら、IDセレクタで指定したスタイルを変えられるのは、別のIDセレクタか `style` 属性、あるいは `!important` だけです。後のレイヤーに書けば詳細度に関係なく上書きできますが、IDのスタイルを変えるたびにレイヤーを分けることになります。本書のStylelintの設定では、`selector-max-id` でIDセレクタを検出しています。

`id` 属性そのものは使います。JavaScriptから要素を参照するとき、`aria-labelledby` などのARIAの属性から参照するとき、ページ内リンクの移動先にするときです。スタイルはクラスで指定し、`id` 属性はこうした用途のために残しておきます。

私は2020年に、`!important` を使わずに上書きする方法として、次のようなセレクタを紹介していました。同じクラスを連結する、`[class]` を足す、存在しないIDを `:not()` に入れる、といった技です。当時はセレクタのほかに詳細度を調整する手段がなく、既存のCSSを直せない場面での最終手段として使っていました。

```css title="🙅‍♂ Not Recommended: 詳細度を上げるためだけのセレクタ"
/* 🙅‍♂ Not Recommended */
.large-text.large-text {
  font-size: calc(24 / 16 * 1rem);
}

.large-text[class] {
  font-size: calc(24 / 16 * 1rem);
}

.large-text:not(#_) {
  font-size: calc(24 / 16 * 1rem);
}
```

いまは、こうした技を使いません。セレクタから意図が読み取れないうえ、次に上書きする人はさらに詳細度を上げる必要があるからです。祖先のクラスを足す書き方（`.top-page .large-text`）や、タイプセレクタを足す書き方（`p.large-text`）も同様です。どちらもHTMLの構造に依存するので、コンポーネントを別の場所で使いにくくなります。

上書きが必要になったら、先に次の手段を検討します。優先順位の問題なら、レイヤーの順番で解決します（[2-3 カスケードレイヤーで順位を決める](/cascade/layers/)）。上書きされる側の詳細度が高すぎるなら、`:where()` で下げます。親のコンポーネントから子のコンポーネントの見た目を変えたいなら、子が公開しているカスタムプロパティに値を渡します（[8-5 公開プロパティと内部プロパティ](/components/custom-properties/)）。

## `:where()` による詳細度0の指定

`:where()` は、引数にどのようなセレクタを書いても、詳細度が0になる擬似クラスです。ベーススタイルのように、あらゆる場所で上書きされる前提のスタイルは、`:where()` で包みます。

```css title="🙆‍♂ Recommended: ベースのタイプセレクタは :where() で包む"
:where(a:any-link) {
  color: var(--foreground--link);
}

:where(h1, h2, h3, h4, h5, h6, caption) {
  font-kerning: normal;
}
```

リンクの色を `a:link, a:visited` ではなく `:where(a:any-link)` と書けば、詳細度は0.1.1から0になります。リンクで作ったボタンにクラスを付ければ、それだけで文字色を上書きできます。`:any-link` は `href` 属性を持つリンクすべてに当てはまる擬似クラスで、`:link` と `:visited` をまとめて書くのと同じ意味です。

私が作ったリセットCSSのkiso.cssも、すべてのセレクタを `:where()` で書いています。カスケードレイヤーを使えない環境でも、どのクラスやタイプセレクタからでも上書きできるようにするためです。反対に、`:where()` を使っていないリセットCSSと組み合わせると、リセットCSSのタイプセレクタの詳細度が上回り、ベーススタイルの指定を打ち消すことがあります。リセットCSSを選ぶときも、詳細度が下げられているかを確認します。kiso.cssの設計は、第6章「[6-1 壊さないリセット](/reset/kiso/)」で説明します。

`:where()` は、コンポーネントの中でも使えます。親のルールの中にネストして直下の子を選ぶと、詳細度は0.2.0に上がります。`& > :where(._heading)` と書けば、子を選ぶ部分の詳細度が0になり、全体は0.1.0のままです。子の要素のルールと詳細度がそろうので、書いた順番どおりに上書きが効きます。

```css title="🙆‍♂ Recommended: 直下の子を選ぶときに詳細度を上げない"
@scope (.scoped.contact-section) to (.scoped) {
  ._layout {
    display: block grid;
    reading-flow: grid-rows;
    grid-template-areas:
      "--heading"
      "--body";

    & > :where(._heading) {
      grid-area: --heading;
    }
  }
}
```

グリッドのエリアのように、親との関係で決まるプロパティは、親のルールの中に書くと構造が読み取りやすくなります。そのときに詳細度まで上がらないようにするのが、`:where()` の役割です。

## イレギュラーな擬似クラスの詳細度

擬似クラスの詳細度は、ふつうはクラスと同じ0.1.0です。ただし、セレクタを引数に取る擬似クラスのうち、次の5つは決まり方が違います。表の「引数の最大」は、引数に書いたセレクタのうち、いちばん詳細度の高いものの詳細度という意味です。

| 擬似クラス | 詳細度の決まり方 | 例 | 例の詳細度 |
| --- | --- | --- | --- |
| `:is()` | 引数の最大 | `:is(h2, ._title)` | 0.1.0 |
| `:not()` | 引数の最大 | `p:not(._note)` | 0.1.1 |
| `:has()` | 引数の最大 | `._card:has(> img)` | 0.1.1 |
| `:nth-child(An+B of S)` | 0.1.0に、Sの最大を足す | `:nth-child(2n of ._item)` | 0.2.0 |
| `:where()` | 引数に関係なく0 | `:where(#news h2)` | 0 |

`:is()`、`:not()`、`:has()` は、自分の0.1.0を持ちません。引数の最大がそのまま擬似クラス全体の詳細度になります。引数の最大は、要素に実際に一致したセレクタではなく、引数に書いたすべてのセレクタから選びます。そのため、`:is(#news, ._card)` は、`._card` に当てはまった要素でも1.0.0です。`:nth-last-child()` も、`of S` を付けたときは `:nth-child()` と同じく、0.1.0にSの最大を足します。`of S` を付けなければ、ほかの擬似クラスと同じ0.1.0です。

`:not()` は否定の擬似クラスですが、詳細度は引数の分だけ加わります。`p:not(._note)` は0.1.1で、`p._note` と同じ詳細度です。引数をカンマで並べると、引数の最大の1つ分だけが加わります。`p:not(._note, ._lead)` は0.1.1、同じ要素を選ぶ `p:not(._note):not(._lead)` は0.2.1です。2020年の上書きの技 `:not(#_)` で詳細度を上げられたのも、この決まり方によるものでした。存在しないIDを引数に書くだけで、`:not()` の詳細度がIDセレクタと同じ1.0.0になるからです。

詳細度が引数で決まるので、意味の違うセレクタが同じ詳細度になることがあります。`._card:has(:not(img))` と `._card:not(:has(img))` は、意味が逆なのに、どちらも0.1.1です。詳細度の差から誤りに気づくことはできないので、入れ子の順序は意味から確かめます。

それぞれの擬似クラスの使い方と、`:not()` の引数の書き分けは、第3章「[3-2 :is()・:where()・:not()](/pseudo/is-where-not/)」で説明しています。`of S` で数える対象を絞る書き方は「[3-4 子要素の位置で選ぶ](/pseudo/child-index/)」で、`:has()` の使いどころは「[3-3 :has() で祖先と前の兄弟を選ぶ](/pseudo/has/)」で説明しています。

## 引数に詳細度の高いセレクタを混ぜない

`:is()` は、複数のセレクタをまとめて書くための擬似クラスです。引数の最大が全体の詳細度になるので、引数にIDセレクタや長いセレクタを1つ混ぜるだけで、ほかの引数に当てはまった要素まで高い詳細度になります。

```css title="🙅‍♂ Not Recommended: 引数に詳細度の高いセレクタを混ぜる"
/* 🙅‍♂ Not Recommended */
:is(#sidebar, .card) ._title {
  font-size: 1rem;
}
```

この例では、`.card` の中の `._title` にも、1.1.0という高い詳細度が付きます。まとめるセレクタの詳細度をそろえるか、詳細度を加えたくないときは `:where()` を使います。`:not()` と `:has()` の引数も同じです。

詳細度が引数で決まることは、状態のスタイルを書くときには役に立ちます。画像があるときだけ2列にするカードの `&:has(> img)` は、`:scope` の0.1.0に `img` の0.0.1が加わり、0.1.1です。状態のスタイルは元のスタイルより詳細度が高くなるので、書く位置に関係なく元のスタイルを上書きできます。引数を短く保てば、こうした上書きの関係も読み取りやすくなります。

## 祖先の状態を `:is()` で書く

`:is()` が特に役立つのは、祖先の状態によって変わるスタイルを、子のルールの中に書くときです。次の例では、`<details>` が開いているときだけ、中のアイコンを回転させています。

```css title="🙆‍♂ Recommended: 祖先の状態による変化を、子のルールの中に書く"
@scope (.scoped.faq-item) to (.scoped) {
  ._icon {
    inline-size: 1em;
    block-size: 1em;

    &:is(:scope[open] *) {
      rotate: 180deg;
    }
  }
}
```

`&:is(:scope[open] *)` は、「開いているスコープのルートの子孫である、この要素」という意味です。スコープのルートは `<details class="scoped faq-item">` で、開いているときだけ `open` 属性を持ちます（2026年9月、Chrome 152で確認）。アイコンのスタイルが `._icon` のルールにまとまるので、状態による変化を探しやすくなります。

同じ指定は、`:scope[open] ._icon` という別のルールとしても書けます。しかし、`._icon` のルールの中にネストして書くなら、ネストしたセレクタを `&` で始めるという本書の規約から、この形になります。ネストの仕組みは「[2-5 CSSネストの基礎](/cascade/nesting/)」で、規約は第7章「[7-4 ネストの書き方](/notation/nesting/)」で説明します。
