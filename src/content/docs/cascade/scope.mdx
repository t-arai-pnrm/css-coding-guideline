コンポーネントのスタイルは、`@scope (.scoped.<名前>) to (.scoped)` の中に書きます。`@scope` は、セレクタが当たる範囲を、スコープのルートから下限までの間に限る仕組みです。`to (.scoped)` を書くと、スコープは入れ子になった別のコンポーネントのルートで止まります。この形を「ドーナツスコープ」と呼びます。

この節では、`@scope` の仕様上の動作を説明します。下限の有無による違い、ネストや `:where()` との比較、詳細度が同じときに勝つ側を決める「スコープの近接度」、`<style>` 要素に書く前置きのない `@scope`、`@scope` が防がないものを順に扱います。ルートと子要素の名前の付け方や、`:scope` と `&` の使い分けのような規約は、第7章「[7-3 @scopeとネストの使い分け](/notation/scope-and-nesting/)」で説明します。

## クラス名の工夫で範囲を限る従来の方法

CSSのセレクタは、ページ全体のどの要素にも当てはまる可能性があります。そのため、コンポーネントのスタイルがほかのコンポーネントに漏れないように、これまではクラス名を工夫してきました。代表的なのが、BEMのようにコンポーネント名を接頭辞にする命名です。

```css title="🙅‍♂ Not Recommended: 子孫セレクタで範囲を限ろうとする"
/* 🙅‍♂ Not Recommended */
.news-card .title {
  color: var(--foreground--accent);
  font-size: calc(24 / 16 * 1rem);
}
```

子孫セレクタで範囲を限ろうとすると、カードの中に置いた別のコンポーネントの `.title` にもスタイルが当たります。詳細度も0.2.0に上がります。BEMのように `.news-card__title` と名前で区別すれば漏れは防げますが、名前が長くなり、すべての子要素に同じ接頭辞を付け続ける必要があります。

`@scope` は、この問題をセレクタが当てはまる範囲そのもので解決します。スコープのルートと下限を指定すれば、その間にある要素にだけスタイルが当たります。ほかのコンポーネントもすべて `@scope` の中に書かれているなら、子要素のクラス名がほかのコンポーネントと同じでも、スタイルはぶつかりません。この条件が成り立たない場合は、「外から入ってくるスタイルは防げない」で説明します。

## `@scope` の基本形

`@scope` の後ろの括弧にスコープのルートを、`to` の後ろの括弧にスコープの下限を書きます。

```css title="🙆‍♂ Recommended: コンポーネントのスタイルを @scope に閉じ込める"
@scope (.scoped.news-card) to (.scoped) {
  :scope {
    display: block grid;
    gap: 8px;
    padding: 16px;
  }

  h2 {
    font-size: calc(20 / 16 * 1rem);
  }

  time {
    color: var(--foreground--muted);
  }
}
```

```html title="index.html"
<article class="scoped news-card">
  <h2>お知らせの見出し</h2>
  <time datetime="2026-09-25">2026年9月25日</time>
</article>
```

`@scope` の中のセレクタは、先頭に「`:scope` と子孫結合子」が省略されたものとして扱われます。`h2` は `:scope h2` と同じ意味で、スコープのルートの子孫にだけ当てはまります。スコープのルートそのものを選ぶときは、`:scope` と書きます。

詳細度の数え方は、ネストと違います。`@scope` の括弧の中のセレクタは、中のルールの詳細度に加わりません。`h2` は0.0.1、`._main-link` のような子クラスは0.1.0のままです。`:scope` は擬似クラス1つ分の0.1.0です。`@scope` の直下に書いた `&` もルートを選びますが、仕様では `:where(:scope)` と同じ扱いで、詳細度は0になります。本書が `&` ではなく `:scope` でルートを選ぶ理由は、「[7-3 @scopeとネストの使い分け](/notation/scope-and-nesting/)」で説明します。

## ドーナツスコープで入れ子のコンポーネントを除く

`to (.scoped)` は、スコープの下限です。ルートの子孫のうち、`.scoped` に当てはまる要素とその中身は、スコープから外れます。下限の要素そのものも、スコープの外です。ルートから下限までの間だけにスタイルが当たるので、穴の開いたドーナツにたとえて「ドーナツスコープ」と呼ばれます。

次のデモでは、`.media-card` の中に、別のコンポーネントの `.author-note` を入れ子にしています。どちらのコンポーネントにも、段落の `p` があります。外側のスコープでは `p` を大きな青い文字にしていますが、入れ子のコンポーネントの段落には届いていません。タイプセレクタで選んだスタイルも、下限で止まります。

<Demo title="to (.scoped) があるので、入れ子のコンポーネントの p に外側のスタイルが届かない" html={donutHtml} css={donutCss} />

下限を書かなかった場合と比べてみます。次のデモは、外側の `@scope` から `to (.scoped)` を消しただけのものです。入れ子のコンポーネントの段落も、青い文字になります。

<Demo title="to (.scoped) がないと、入れ子のコンポーネントの p にも外側のスタイルが届く" html={donutHtml} css={donutBadCss} variant="not-recommended" />

このデモでは、文字の大きさにだけ入れ子のコンポーネントの指定が使われています。どちらの `p` のルールも詳細度は0.0.1なので、この節の後半で説明するスコープの近接度によって、ルートに近い入れ子のコンポーネントの指定が勝つからです。しかし、入れ子のコンポーネントが指定していない色には、外側のスタイルがそのまま当たります。

## 下限のない `@scope` とネストの違い

下限のない `@scope` が当てはまる範囲は、ネストで書いた子孫セレクタと変わりません。次の3つのルールは、どれも `.section` の子孫のすべての `p` に当たり、入れ子になった別のコンポーネントの `p` も除きません。

```css title="下限のない @scope と、同じ範囲に当たるネストの書き方"
@scope (.section) {
  p {
    color: green; /* 詳細度 0.0.1 */
  }
}

.section {
  p {
    color: green; /* 詳細度 0.1.1 */
  }
}

:where(.section) {
  p {
    color: green; /* 詳細度 0.0.1 */
  }
}
```

違いは、まず詳細度です。ネストでは、`p` は `.section p` として扱われ、親のクラスの分だけ詳細度が上がります。`@scope` ではルートのセレクタが詳細度に加わらないので、`p` の0.0.1のままです。この差は、ネストの親を `:where()` で包めば再現できます。反対に、`.section { :where(p) { … } }` と書けば、親のクラスだけが残って0.1.0になります。

もうひとつの違いは、`@scope` の中のルールにだけ、次に説明するスコープの近接度が働くことです。ただし、近接度が働くのは、同じ要素の同じプロパティに、詳細度の同じ宣言が複数あるときだけです。上のデモで外側の色が入れ子のコンポーネントに届いたように、入れ子のコンポーネントが指定していないプロパティには、外側の指定がそのまま当たります。範囲を閉じ込めるという `@scope` の目的は、下限を書いて初めて果たせます。

## スコープの近接度

スコープの近接度は、CSS Cascading and Inheritance Level 6で、カスケードの比較の段階に加わった基準です。カスケードは、オリジンと重要度、コンテキスト、`style` 属性、レイヤー、詳細度、スコープの近接度、出現順の順に比べ、先の段階で決まらなかったときだけ次の段階に進みます。近接度は、詳細度の後、出現順の前です。

近接度で比べるのは、スコープのルートから、スタイルが当たる要素までの距離です。仕様は、ルートが違う宣言どうしでは、要素からルートまでの世代や兄弟の数（ホップ数）の少ないほうが勝つと定めています。近接度は詳細度の後に比べるので、詳細度の高いルールは、ルートが遠くても勝ちます。近接度が順位を決めるのは、詳細度が同じときだけです。

次の例では、ライトとダークの配色を入れ子にしています。どちらのルールも詳細度は0.0.1なので、近接度で比べます。

```css title="詳細度が同じなら、ルートに近いスコープの指定が勝つ"
@scope ([data-theme="dark"]) {
  a {
    color: oklch(80% 0.1 250deg);
  }
}

@scope ([data-theme="light"]) {
  a {
    color: oklch(45% 0.15 250deg);
  }
}
```

```html title="index.html"
<div data-theme="light">
  <div data-theme="dark">
    <a href="/">リンク</a>
  </div>
</div>
```

リンクから見ると、ダークのルートは1つ上、ライトのルートは2つ上にあります。ダークのルールは先に書かれていますが、ルートが近いので勝ち、リンクは明るい色になります。出現順で決まるなら、後に書いたライトの色になるところです（2026年10月、Chrome 152で確認）。

`@scope` の外に書いたルールは、近接度が無限大として扱われます。そのため、詳細度が同じなら、`@scope` の中のルールが、後に書いた `@scope` の外のルールにも勝ちます。`@scope (.s) { :scope { … } }` と、その後ろに書いた `.s { … }` は、どちらも0.1.0ですが、`:scope` の側が勝ちます（2026年10月、Chrome 152で確認）。

## `<style>` に前置きのない `@scope` を書く

`@scope` は、ルートのセレクタ（前置き）を省いて書くこともできます。仕様では、前置きのない `@scope` のルートは、そのスタイルシートを持つ要素の親要素になります。`<style>` 要素の中に書けば、`<style>` を置いた親要素がスコープのルートです。

```html title="index.html"
<section>
  <style>
    @scope {
      :scope {
        padding: 16px;
      }

      p {
        color: oklch(45% 0.15 250deg);
      }
    }
  </style>
  <p>この段落にだけ当たります。</p>
</section>
```

この例では、`<section>` がルートになり、`p` のスタイルはこの `<section>` の中にだけ当たります（2026年10月、Chrome 152で確認）。ルートを選ぶクラス名が要らないので、テンプレートの中にその場限りのスタイルを書く用途を想定した仕組みです。

本書では、この書き方を規約として勧めません。コンポーネントのスタイルがテンプレートのHTMLに散らばると、コンポーネントごとのCSSファイルにまとまらず、Stylelintでも検証できなくなります。同じコンポーネントをページに3つ置けば、同じ内容の `<style>` も3つ出力されます。本書は、コンポーネントのCSSをファイルに分け、ルートに付けたクラスでスコープを作ります。

## 外から入ってくるスタイルは防げない

`@scope` が制限するのは、`@scope` の中に書いたルールが当たる範囲です。スコープの中のスタイルが外へ漏れることは防げますが、`@scope` の外に書かれたルールがスコープの中の要素に当たることは防げません。

この違いは、自分で書いていないCSSと共存するときに表れます。CMSが本文エリアに `.entry-content h2 { border-inline-start: 4px solid; }` のようなスタイルを出力していると、本文エリアに置いたコンポーネントの `h2` にも枠線が付きます。ライブラリのCSSが `.title` のような汎用的なクラス名にスタイルを指定していれば、同じ名前の子クラスにも当たります。子要素のクラス名がほかのコンポーネントと同じでもかまわないのは、ページのCSSがすべて `@scope` で範囲を閉じているときに限ります。

外から入ってくるスタイルへの対処は、レイヤーとCSSの読み込み方の問題です。外部のCSSを自分で読み込めるなら、`vendors` レイヤーに入れ、コンポーネントの指定が勝つようにします（[2-3 カスケードレイヤーで順位を決める](/cascade/layers/)）。ただし、レイヤーで決まるのは同じプロパティを指定したときの優劣なので、コンポーネントが指定していないプロパティには、外部のCSSが当たり続けます。CMSの本文エリアのように直せないCSSと共存する方法は、第18章「18-4 CMSと共存する」で説明します。{/* 第18章の執筆後にリンクする: /operations/cms/ */}

値の継承も、スコープの境界を越えます。`@scope` が制限するのはセレクタの適用範囲なので、外側の要素に指定した `color` や `font-size`、カスタムプロパティの値は、下限の内側にも継承されます。継承されるカスタムプロパティの扱いは「[8-5 公開プロパティと内部プロパティ](/components/custom-properties/)」で説明しています。

## 対応状況と注意点

`@scope` の対応状況は、どの範囲を見るかで2通りに読めます。まず、基本の動作から確認します。

<Baseline id="scope" compatKey="api.CSSScopeRule" name="@scope（基本の動作）" />

`@scope` の基本の動作は、Chrome 118、Safari 17.4、Firefox 146から使えます。すべての主要なブラウザで使えるようになったのは、Firefoxが対応した2025年12月です。本書の対象のブラウザ（Safari 18系の最終版以降と、ほかのブラウザの最新版）では、この節で紹介した形を使えます。ただし、次に説明するとおり、Safari 26.0から26.3には入力欄だけの例外があります。

<Baseline id="scope" name="@scope（機能全体）" />

一方、web-featuresは、`@scope` の機能全体を2026年3月に「新しく利用可能」になったものとして扱っています。MDNのブラウザ互換性データによると、Safari 26.0から26.3には、`@scope` の中のルールが `<input>` と `<textarea>` に当たらない不具合がありました。この不具合はSafari 26.4で直っています（2026年9月確認）。Safari 18系には、この不具合はありません。機能全体のChromeのバージョンが143になっているのは、`@scope` の直下の `&` を `:where(:scope)` として扱う動作を含むためです。

Safari 26.0から26.3を使い続けているユーザーには、スコープの中で指定した入力欄のスタイルが当たりません。ただし、kiso.cssはスコープの外で入力欄に枠線を付けているので、入力欄が見えなくなるわけではありません。

`@scope` は、プログレッシブ・エンハンスメントとしては使いにくい機能です。対応していないブラウザでは `@scope` の中のスタイルがすべて無視され、コンポーネントの見た目がまったく付かないからです。本書の対象のブラウザはすべて基本の動作に対応しているので、本書では前提の機能として使います。対象のブラウザの考え方は、第1章「[1-3 ブラウザサポートとプログレッシブ・エンハンスメント](/principles/browser-support/)」で説明します。
