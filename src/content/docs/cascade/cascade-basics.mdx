同じ要素の同じプロパティに複数の値が指定されたとき、どの値を使うかは「カスケード」という手順で決まります。カスケードは、レイヤー、詳細度、スコープの近さ、書いた順番などを決まった順に比べ、最初に差がついたところで勝ち負けを決めます。

本書では、この仕組みのうちレイヤーと書いた順番で優先順位を設計し、詳細度はできるだけ低く一定に保ちます。`!important` は、詳細度の競争に勝つためには使いません。この節では、カスケードの全体像と継承の仕組み、値を戻すキーワード、`!important` を使ってよい場面を説明します。

## 詳細度で上書きを重ねると何が起きるか

ベーススタイルに、リンクの色を次のように書いたとします。一見すると問題のない指定ですが、この書き方が後の上書きを難しくします。

```css title="🙅‍♂ Not Recommended: 詳細度の高いベーススタイルを、さらに高い詳細度で上書きする"
/* 🙅‍♂ Not Recommended */
a:link,
a:visited {
  color: var(--foreground--link);
}

/* 0.1.0 なので、上の 0.1.1 に負ける */
.button {
  color: var(--foreground--on-accent);
}

/* 勝つために祖先のクラスを足す */
.site-header .button {
  color: var(--foreground--on-accent);
}

/* それでも負ける場面が出たので !important を付ける */
.site-header .button.-small {
  color: var(--foreground--on-accent) !important;
}
```

`a:link` の詳細度は、タイプセレクタ1つと擬似クラス1つで「0.1.1」になります。ボタンのクラス `.button` は「0.1.0」なので、リンクで作ったボタンの文字色を変えられません。そこで祖先のクラスを足して「0.2.0」にし、さらに負ける場面が出ると `!important` を付ける、という流れが生まれます。

こうした上書きは、1回ごとには小さな対応です。しかし、次に誰かが上書きするときには、さらに高い詳細度か `!important` が必要になります。詳細度の競争は一方向にしか進まず、最後は `!important` 同士の競争になります。私は、この詳細度の問題こそがCSSを破綻させるいちばんの原因だと考えています。

問題の出発点は、優先順位を詳細度の高さで決めようとしたことです。カスケードには、詳細度より先に比べられる仕組みがあります。それを使えば、詳細度を上げなくても、意図した順番でスタイルを勝たせられます。

## カスケードが値を決める順番

カスケードは、次の順に宣言を比べます。上の段階で差がつけば、下の段階は比べません。

1. オリジンと重要度：ブラウザのデフォルトスタイル、ユーザーのスタイル、作者のスタイルの区別と、`!important` の有無
2. コンテキスト：Shadow DOMの内側と外側の区別
3. `style` 属性：要素に直接書いたスタイル
4. レイヤー：`@layer` の順番
5. 詳細度：セレクタの強さ
6. スコープの近さ：`@scope` のルートと要素との距離
7. 出現順：後に書いた宣言が勝つ

大事なのは、レイヤーが詳細度より先に比べられることです。レイヤーが違えば、詳細度がどれほど高くても、後ろのレイヤーの宣言が勝ちます。詳細度は、同じレイヤーの中で初めて比べられる値です。

レイヤーに入れていないスタイルは、すべてのレイヤーより後ろにある「暗黙の最後のレイヤー」として扱われます。そのため、`!important` を付けていない宣言どうしでは、レイヤーの外のスタイルが常に勝ちます。この性質がCMSの環境で問題になる理由は、「[2-3 カスケードレイヤーで順位を決める](/cascade/layers/)」で説明します。

詳細度は、IDの数、クラス・属性・擬似クラスの数、タイプセレクタ・擬似要素の数という3つの数で表し、左の数から比べます。本書では、これを「0.1.1」のようにドットでつないで書きます。

```css
/* 詳細度（IDの数.クラスなどの数.タイプセレクタなどの数） */
p {}                    /* 0.0.1 */
.button {}              /* 0.1.0 */
a:link {}               /* 0.1.1 */
.site-header .button {} /* 0.2.0 */
#main {}                /* 1.0.0 */
:where(a:link) {}       /* 0.0.0 */
```

スコープの近さは、`@scope` とともに加わった比べ方です。詳細度が同じ宣言どうしでは、スコープのルートが対象の要素に近いほうが勝ちます。レイヤー、詳細度、スコープの近さのすべてで差がつかなかったときに、最後に書いた宣言が勝ちます。`@scope` の使い方は「[2-4 @scopeでスタイルを閉じ込める](/cascade/scope/)」で説明します。

`style` 属性は、レイヤーと詳細度より先に比べられるので、セレクタで書いたどのルールにも勝ちます。本書では、`style` 属性をコンポーネントの公開カスタムプロパティに値を渡す用途に限って使います。この方法は、第6章「[6-4 公開プロパティと内部プロパティ](/components/custom-properties/)」で説明します。

## 優先順位はレイヤーと書く順番で決める

本書では、優先順位を次の方針で設計します。まず、スタイルの役割ごとにレイヤーを分け、「リセットよりベース、ベースよりコンポーネント、コンポーネントよりユーティリティが強い」という順番をレイヤーで決めます。同じレイヤーの中では詳細度をそろえ、書いた順番で勝ち負けが決まるようにします。

詳細度をそろえる目安は2つです。ベーススタイルとリセットCSSは、`:where()` で包んで詳細度を0にします。コンポーネントの中は、クラス1つ分（0.1.0）を基本にします。`@scope` の中でクラスを1つ書けば、ちょうど0.1.0になります。セレクタの書き方は「[2-2 セレクタで詳細度を設計する](/cascade/selectors/)」で詳しく説明します。

```css title="🙆‍♂ Recommended: 順番はレイヤーで決め、詳細度は低くそろえる"
@layer base {
  :where(a:any-link) {
    color: var(--foreground--link);
  }
}

@layer components {
  @scope (.scoped.button) to (.scoped) {
    :scope {
      color: var(--foreground--on-accent);
    }
  }
}
```

このコードでは、ベースのリンクの色が0.0.0、ボタンの色が0.1.0です。仮に詳細度が逆だったとしても、`components` レイヤーが `base` レイヤーより後ろにあるので、ボタンの色が勝ちます。詳細度とレイヤーの両方で同じ向きの優先順位を作っておけば、上書きのための工夫は要りません。

なお、この節のほかのコード例では、説明に関係しない `@layer` の記述を省略しています。

## 継承されるプロパティとされないプロパティ

カスケードは、「要素に当てはまる宣言のうち、どれを使うか」を決める仕組みです。当てはまる宣言がひとつもないプロパティは、継承されるプロパティなら親の値を受け継ぎ、継承されないプロパティなら初期値になります。

継承されるのは、主に文字に関わるプロパティです。`color`、`font-family`、`font-size`、`line-height`、`letter-spacing` などがこれに当たります。一方で、`margin`、`padding`、`border`、`background-color`、`display` のように、ボックスやレイアウトに関わるプロパティは継承されません。カスタムプロパティは、`@property` で `inherits: false` を指定しない限り継承されます。

継承で受け継いだ値には、詳細度がありません。要素に直接当てはまる宣言がひとつでもあれば、詳細度0の `:where()` の指定であっても、継承した値より優先されます。親に色を指定したのに子の色が変わらないときは、子に当てはまる宣言がどこかにないかを確認します。

この仕組みを活かして、文字の色やサイズは `:root` やコンポーネントのルートでまとめて指定し、子要素では継承を使います。子要素ごとに同じ値を書き直すと、ルートの値を変えたときに直す場所が増えるからです。

```css title="🙆‍♂ Recommended: 継承するプロパティはルートでまとめて指定する"
@scope (.scoped.news-card) to (.scoped) {
  :scope {
    color: var(--foreground--muted);
    font-size: calc(14 / 16 * 1rem);
  }

  ._title {
    color: var(--foreground--base);
    font-size: calc(18 / 16 * 1rem);
  }
}
```

この例では、カードの中の文章はすべてルートの色とサイズを受け継ぎ、見出しだけが違う値を持ちます。本文の段落や日付にクラスを付けて、色を指定し直す必要はありません。

## 戻したい先をキーワードで選ぶ

指定した値を元に戻したいときは、具体的な値を書き直すより、どのプロパティにも使えるキーワードを使います。キーワードによって戻る先が違うので、意図に合うものを選びます。

- `initial`：プロパティの初期値に戻す
- `inherit`：親の値を受け継ぐ
- `unset`：継承されるプロパティなら `inherit`、継承されないプロパティなら `initial` として働く
- `revert`：ブラウザのデフォルトスタイルに戻す
- `revert-layer`：ひとつ前までのレイヤーで決まる値に戻す

注意したいのは `initial` です。`display` の初期値は、要素の種類に関係なく `inline` です。`div` の `display` を `initial` にすると、インライン要素になってしまいます。ブラウザのデフォルトスタイル（`div` なら `block`）に戻したいなら、`revert` を使います。

リセットCSSで消したものを、一部の場所だけ元に戻すときにも `revert` が役に立ちます。kiso.cssはリストのマーカーを `list-style-type: ""` で消しているので、記事の本文のようにマーカーが必要な場所では、次のように戻します。

```css title="🙆‍♂ Recommended: リセットで消したマーカーを、ブラウザのデフォルトに戻す"
@scope (.scoped.article-body) to (.scoped) {
  :where(ul, ol) {
    list-style-type: revert;
  }
}
```

ここで `revert-layer` を使うと、kiso.cssを入れた `reset` レイヤーの値（マーカーなし）に戻るので、マーカーは表示されません（2026年9月、Chrome 152で確認）。どちらのキーワードも「元に戻す」ものですが、戻る先が違います。値を書き直す前に、どこまで戻したいのかを考えてキーワードを選びます。

## `!important` を使ってよい場面

`!important` は、カスケードの最初の段階である「オリジンと重要度」の順位を変える指定です。`!important` が付いた宣言は、付いていない宣言に、レイヤーや詳細度に関係なく勝ちます。これを打ち消せるのは、同じように `!important` を付けた宣言だけです。

さらに、`!important` を付けた宣言どうしでは、レイヤーの順番が逆になります。前のレイヤーの `!important` ほど強く、レイヤーの外の `!important` がいちばん弱くなります。前のレイヤーで `!important` を付けた指定は、後ろのレイヤーから上書きできません。

本書では、詳細度や読み込み順の競争に勝つ目的で `!important` を使いません。どのような上書きにも負けてはいけない指定に限って使います。代表的なのは、kiso.cssの `hidden` 属性の指定です。

```css title="🙆‍♂ Recommended: 状態を確実に反映するときに限って使う"
[hidden]:not([hidden="until-found" i]) {
  display: none !important;
}
```

`hidden` 属性を付けた要素は、どのコンポーネントが `display` を指定していても隠れなければなりません。kiso.cssを `reset` レイヤーに入れると、この `!important` はいちばん前のレイヤーのものになります。後ろのレイヤーで `display: block !important` と書いても、要素は隠れたままです（2026年9月、Chrome 152で確認）。kiso.cssは、閉じている `<dialog>` と開いていないポップオーバーにも、同じ理由で `!important` を使っています。

このほかに `!important` を使うのは、強制カラーモードでSVGの色をシステムカラーに固定する場合と、CMSが要素に直接出力する `style` 属性を打ち消す場合です。どちらも、セレクタでは勝てない相手を上書きするための例外です。前者は「[10-2 強制カラーモードとコントラスト](/color-media/forced-colors/)」で、後者は「[12-1 CMSと共存する](/operations/cms/)」で扱います。

以前の私は、ユーティリティクラスだけは `!important` を使ってよいと考えていました。いまは、ユーティリティクラスにも `!important` を付けません。`utilities` を最後のレイヤーにすれば、`!important` なしでコンポーネントのスタイルに勝つからです。

AIにスタイルの修正を頼むと、上書きが効かない原因を調べずに `!important` を足したコードが返ってくることがあります。`!important` が含まれていたら、詳細度やレイヤーの順番で解決できないかを先に確認してください。
