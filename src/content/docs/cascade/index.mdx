この章では、同じ要素の同じプロパティに複数の値が指定されたとき、どの値が使われるかを扱います。スタイルの優先順位は、詳細度の高さで競わせず、「どのレイヤーに書くか」と「どの範囲に適用するか」で先に決めます。詳細度そのものは、できるだけ低く一定に保ちます。

私は2020年に、`!important` を使わずにスタイルを上書きする技として、同じクラスを連結して詳細度を上げる書き方を紹介していました。当時は、詳細度を調整する手段がセレクタしかなかったからです。いまはカスケードレイヤー、`:where()`、`@scope` がすべての主要なブラウザで使えるので、上書きの技そのものが要らない設計にできます。この章では、上書きで困ってから対処するのではなく、困らない順番と範囲を最初に決めておく設計を扱います。

ただし、新しい仕組みにも向き不向きがあります。私自身、2024年のブログではITCSSにならった7つのレイヤーを使い、2025年に公開したリセットCSSのkiso.cssでは「レイヤーに頼らなくても上書きしやすい」ことを優先しました。現在、Astroで作るサイトのテンプレートでは9つのレイヤーを使っていますが、CMSの案件ではレイヤーをやめています。こうした経験から、レイヤーを使う基準と使わない基準の両方を示します。

この章は次の5つの節で構成しています。

- [4-1 カスケード・詳細度・継承](/cascade/cascade-basics/)：優先順位が決まる仕組みの全体像と、`!important` を使ってよい場面
- [4-2 セレクタで詳細度を設計する](/cascade/selectors/)：`:where()`、`:is()`、`:not()`、`:has()` の詳細度と、使わないセレクタ
- [4-3 カスケードレイヤーで順位を決める](/cascade/layers/)：9つのレイヤーの役割と、レイヤーを使わないと判断する基準
- [4-4 @scopeでスタイルを閉じ込める](/cascade/scope/)：ドーナツスコープの動作、スコープの近接度、`@scope` が防がないもの
- [4-5 CSSネストの基礎](/cascade/nesting/)：`&` が `:is()` と同じように働く仕組みと、Sassのネストとの違い

リセットCSSをレイヤーに入れる方法とベーススタイルの中身は第8章「[リセットとベーススタイル](/reset/)」で、スコープのルートや子要素の命名、`@scope` とネストの使い分け、条件付きのアットルールを書く位置は第9章「[記法の規約](/notation/)」で扱います。親のコンポーネントから子のコンポーネントの見た目を変える方法は、第10章「[コンポーネントとカスタムプロパティ](/components/)」で説明します。

## 初めて読むとき

この章は、本書のほかのすべての章の前提になるので、すべての節を読んでください。

## 最初に押さえるルール

{/* 要確認: 著者の判断。最初に押さえるルールを著者の優先順位で選び直す（レビューの提案にもとづく下書き） */}

次のルールを先に押さえ、ほかのルールは、該当する場面で付録A「[ルール一覧](/appendix/rules/)」から引けば足ります。

- [`no-important-for-specificity`](/cascade/cascade-basics/#rule-no-important-for-specificity)：`!important` は、詳細度や読み込み順の競争で勝つ目的には使いません。
- [`no-specificity-hacks`](/cascade/selectors/#rule-no-specificity-hacks)：上書きのためだけに詳細度を上げるセレクタ（`.a.a` や、祖先を足したセレクタなど）を書きません。
- [`where-for-base-selectors`](/cascade/selectors/#rule-where-for-base-selectors)：`@layer` を使えない場合に限り、ベーススタイルのセレクタを `:where()` で包み、詳細度を0にします。レイヤーを使う場合は、`base` レイヤーに素のセレクタで書きます。
- [`no-layers-with-unlayered-css`](/cascade/layers/#rule-no-layers-with-unlayered-css)：レイヤーに入っていない外部のCSSと共存するCMSのような環境では、`@layer` を使いません。
- [`scope-with-donut`](/cascade/scope/#rule-scope-with-donut)：コンポーネントのスタイルは `@scope (.scoped.<名前>) to (.scoped)` の中に書きます。

## この章で判断できるようになること

この章を読むと、宣言が適用されないときに、レイヤー、詳細度、スコープの近接度、出現順のどれで負けているかを切り分けられるようになります。上書きが要るときは、詳細度を上げる代わりに、書くレイヤーを変えるか、`@scope` で範囲を絞るかを選べます。CMSのようにレイヤーに入っていない外部のCSSと共存する環境では、`@layer` を使わないと判断でき、`!important` を使ってよい場面かどうかも見分けられます。

## 判断の問い

この章の内容で答えられる問いを1つ置きます。答えを開く前に、どの宣言が勝つかを予想してください。

次のCSSで、`<article class="card"><h2 class="title | -text-muted">…</h2></article>` の見出しは何色になりますか。

```css
@layer base, components, utilities;

@layer components {
  .card .title {
    color: var(--foreground--accent);
  }
}

@layer utilities {
  .-text-muted {
    color: var(--foreground--muted);
  }
}

h2 {
  color: var(--foreground--danger);
}
```

<details>
{/* textlint-disable ja-technical-writing/ja-no-mixed-period */}
<summary>答えと解説</summary>
{/* textlint-enable ja-technical-writing/ja-no-mixed-period */}

最後の `h2` の色（`--foreground--danger`）になります。`h2` のルールはどのレイヤーにも入っていないので、すべてのレイヤーより後ろの「暗黙の最後のレイヤー」として扱われます。`!important` のない宣言どうしでは、レイヤーの順番が詳細度より先に比べられます。そのため、詳細度0.0.1の `h2` が、0.2.0の `.card .title` にも、`utilities` の `.-text-muted` にも勝ちます（「[4-3 カスケードレイヤーで順位を決める](/cascade/layers/)」）。

`h2` のルールを `@layer base { … }` に入れると、答えは `--foreground--muted` に変わります。3つのレイヤーのうち最も後ろにある `utilities` が勝つからです。ユーティリティクラスが効かないときに、まずレイヤーの書き忘れを疑うのは、このためです。

</details>

## 次の章へ

この章で、詳細度を低く一定に保ち、優先順位をレイヤーとスコープで決める方針を立てました。セレクタのうち擬似クラスは、詳細度の数え方が種類ごとに違い、`:has()` と `:not()` のように入れ子の順序で意味が逆になるものもあります。次は、状態や位置、子の数を条件に要素を選ぶ擬似クラスと、要素の一部や生成した箱を選ぶ擬似要素を、第5章「[擬似クラスと擬似要素](/pseudo/)」で整理します。
