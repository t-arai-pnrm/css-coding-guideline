21-2から21-13で作った部品を使い、トップページを組み上げます。上から、固定ヘッダー、ヒーロー、「私たちの強み」、「お役立ちコラム」、「制作の流れ」、紺の誘導の帯、フッターの順に並べます。ヘッダーは、狭い画面ではドロワーを開くメニューのボタンに切り替わります（「[21-7 ドロワーメニューを作る](/exercise/drawer/)」）。

ヘッダーとフッターの間の各セクションは、帯で包みます。帯の上下には64pxの余白を取り、「私たちの強み」と「お役立ちコラム」の帯は白い面に、ほかの帯はページの背景と同じ淡いグレーにします。同じ色の帯が続く境目では、余白が64px＋64pxにならないよう、64pxにそろえます。帯の中身の幅は1080px相当までで、画面の端との間には20px以上を空けます。

手元で進めるときは、開始版（[index.html](/exercise-files/assemble/start/index.html)）から始め、中間版（[index.html](/exercise-files/assemble/middle/index.html)）と見比べます。後半の要件の変更は、中間版から始めて、完成版（[index.html](/exercise-files/assemble/finished/index.html)）と見比べます。サンプル一式のZIPでは、それぞれ `exercise/assemble/start/`、`exercise/assemble/middle/`、`exercise/assemble/finished/` にあります。開始版には、すべての部品のCSSが完成した状態で入っていて、ページのCSS（`page-top.css`）だけが空です。準備は「[21-1 題材と準備](/exercise/setup/#手元で進める準備)」で説明しています。

## 予想する

本文を読む前に、セクションとセクションの間の余白を、どこに書くかを考えてみてください。部品のCSSに `margin-block` を足すのか、ページのCSSで並べ方を決めるのか。白い帯の上下の余白を、ページの `gap` で空けると、何が見えるでしょうか。

中身の幅も予想します。ヒーロー、強みのカード、制作の流れの幅を1080px相当にそろえるとき、各部品へ `max-inline-size` を書くのか、帯の側で決めるのか。直すファイルを、部品のCSSとページのCSSに分けて数えてから読み進めます。

## 部品は直さず、ページの側で並べる

この節では、部品のCSSを1行も書き足しません。21-2から21-13で作った部品は、どれもルートに外側の余白と幅を持たせていないので、置かれた場所の幅に広がり、周りとの間隔を知りません（`no-external-layout-on-root`）。どの部品をどの順で、どれだけ離して、どの幅で置くかは、置く側のページが決めます（`parent-owns-child-placement`）。

ページのCSSは、ページのルートに `scoped page-top` を付け、`@scope (.scoped.page-top) to (.scoped)` の中に書きます（「[9-4 @scopeとネストの使い分け](/notation/scope-and-nesting/)」）。ページのCSSから部品のルートは選べないので、各部品を帯の要素で包み、ページのCSSは帯だけを選びます。

```html title="🙆‍♂ Recommended: 各セクションを帯で包み、帯に primary-layout を付ける"
<main class="scoped page-top">
  <div class="_band _hero-band | primary-layout">
    <section class="scoped hero | pile" aria-labelledby="hero-heading">…</section>
  </div>
  <section class="_band _strengths-band | primary-layout">
    <hgroup class="_heading">…</hgroup>
    <ul class="_strengths | switcher">…</ul>
  </section>
  <section class="_band _column-band | primary-layout">…</section>
  <section class="_band _flow-band | primary-layout">…</section>
  <div class="_band _cta-band | primary-layout">
    <section class="scoped cta-band">…</section>
  </div>
</main>
```

固定ヘッダーは、`<main>` の外の、`<body>` の直下のままにします。包む要素を足すと、ヘッダーの留まれる範囲がなくなるからです（「[21-6 固定ヘッダーを作る](/exercise/sticky-header/#帯とヘッダーを1つの要素で包まない)」）。

## 帯に上下の余白と背景を持たせる

帯は、ページの `gap` で離さず、間を空けずに積みます。白い帯の間を `gap` で空けると、背景は `gap` の部分に描かれないので、2つの白い帯の間にページの淡いグレーの筋が入ります。そこで、上下の余白は、帯自身の `padding-block` で作ります（`section-padding-block`）。`padding` の領域には背景が描かれるので、白い面は帯の端から端まで途切れません。

```css title="🙆‍♂ Recommended: 帯は間を空けずに積み、上下の余白と背景は帯が持つ"
@scope (.scoped.page-top) to (.scoped) {
  :scope {
    display: block grid;
  }

  ._band {
    --primary-layout--content-max-width: calc(1080 / 16 * 1rem);
    --primary-layout--row-gap: 24px;

    padding-block: 64px;
  }

  ._strengths-band,
  ._column-band {
    background-color: var(--background--surface);
  }

  ._strengths-band + ._column-band,
  ._flow-band + ._cta-band {
    padding-block-start: 0;
  }
}
```

同じ色の帯が続く境目では、前の帯の下の余白と、後ろの帯の上の余白が足し合わされます。`padding` は、`margin` と違って相殺しないからです。そこで、同じ色が続く2つの組を、次兄弟結合子で選び、後ろの帯の上の余白を0にします（「[11-2 余白を設計する](/layout-practice/spacing/#隣り合うセクションで変わる境目の余白)」）。どの帯の後ろにどの帯が来るかはページの構成で決まるので、この判定もページのCSSに書きます。

## 帯の中身の幅を primary-layout で決める

帯の中身の幅は、帯に付けた `primary-layout` で決めます。`primary-layout` は、左右にガターの列を持つグリッドで、直下の子を中央のコンテンツの列に置きます（「[12-10 primary-layout：コンテンツ幅とガターを決め、子に5段階の幅を選ばせる](/compositions/primary-layout/)」）。コンテンツの幅の1080px相当は、帯で `--primary-layout--content-max-width` に渡しています。

ヒーロー、強みのカード、制作の流れのどの部品にも、`max-inline-size` は書きません。部品は置かれた列の幅に広がるので、幅を変えるときに直すのは、帯に渡した1つの値だけです。帯の中の見出しと部品の間の24pxも、`--primary-layout--row-gap` で帯から渡しています。

## 要件が変わる

トップページをCMSで編集することになりました。編集者は、セクションを「ブロック」として並べ替えたり、足したりできます。各ブロックの背景は、編集者が「淡いグレー」か「白」から選び、CMSはその値を、ブロックを包む要素に `data-surface="base"` か `data-surface="muted"` として出力します。

試しに編集者が並べ替えたページでは、「お役立ちコラム」が「制作の流れ」の後ろへ移り、その後ろに、白い「お知らせ」のブロックが加わりました。本文を読む前に、前半で書いた2つの組の指定で、この並びの余白がどうなるかを考えてみてください。編集者が次にどう並べ替えても崩れない書き方を予想してから読み進めます。

## セクションの名前ではなく、面の役割で選ぶ

前半の `._strengths-band + ._column-band` は、決まった順番の2つの組を名前で選んでいました。編集者が並べ替えると、「お役立ちコラム」の後ろに「お知らせ」が来る組には当たらず、その境目の余白は128pxになります。並べ方のすべての組み合わせを名前で書き出すことはできません。

そこで、背景と余白を、セクションの名前ではなく、CMSが出力する面の役割で決めます（「[11-2 余白を設計する](/layout-practice/spacing/#隣り合うセクションで変わる境目の余白)」）。

```html title="🙆‍♂ Recommended: CMSに、ブロックの面の役割を data-surface として出力させる"
<main class="scoped page-top">
  <div class="_block | primary-layout" data-surface="base">…</div>
  <section class="_block | primary-layout" data-surface="muted">…</section>
  <!-- ... -->
</main>
```

```css title="🙆‍♂ Recommended: 面の役割で背景を決め、同じ面が続く境目の余白を詰める"
@scope (.scoped.page-top) to (.scoped) {
  :scope {
    display: block grid;

    & > [data-surface] {
      --primary-layout--content-max-width: calc(1080 / 16 * 1rem);
      --primary-layout--row-gap: 24px;

      padding-block: 64px;
    }

    & > [data-surface="muted"] {
      background-color: var(--background--surface);
    }

    & > [data-surface="base"] + [data-surface="base"],
    & > [data-surface="muted"] + [data-surface="muted"] {
      padding-block-start: 0;
    }
  }
}
```

同じ面が続く境目は、どのブロックが並んでも、面の値の組み合わせだけで決まります。値は `white` のような色の名前ではなく、`muted` のような面の役割の名前にしています。デザインで白い面を別の色に変えても、CMSの設定と出力する属性はそのままで、直すのはページのCSSの1行だけです。

## 振り返り

直したのは、ページのHTMLの帯の属性と、ページのCSSだけです。部品のCSSは、前半でも後半でも1行も直していません。前半では、部品が外側の余白と幅を持たず、余白、背景、幅を帯が受け持っていたので、部品を並べる作業はページのCSSの中で終わりました。後半では、背景と余白の条件を、名前の組から面の役割へ移しただけで、編集者が並べ替えても崩れなくなりました。

予想と見比べたら、自分の変更を次の3つの点で見直します。

- セクションの間の余白を、部品ではなく帯が受け持つと予想できたか。部品に `margin` を足していたなら、その部品をほかのページへ置いたとき打ち消すことになる指定を挙げられるか。
- 並べ替えたあとの境目の余白を、面の値の組み合わせから説明できるか。
- 中身の幅を変えるときに直す場所が、帯に渡した1つの値だけになっているか。

## 判断の問い

### 問い1

ヘッダーのすぐ下にヒーローを置きたいので、最初の帯の上の64pxを消してほしい、と言われました。どこに何を書きますか。

<details>
{/* textlint-disable ja-technical-writing/ja-no-mixed-period */}
<summary>答えと解説</summary>
{/* textlint-enable ja-technical-writing/ja-no-mixed-period */}

ページのCSSで、最初のブロックの上の余白を0にします（`& > :first-child { padding-block-start: 0; }`）。ヘッダーの直後かどうかはページの構成で決まることなので、ヒーローのCSSには書きません。ヒーローに負の `margin` や上の余白の打ち消しを書くと、ヒーローを下層ページや別の位置に置いたときにも効いてしまいます（`parent-owns-child-placement`）。

</details>

### 問い2

編集者が選べる背景に「紺」を足し、CMSが `data-surface="inverse"` を出力するようになりました。どこを直しますか。

<details>
{/* textlint-disable ja-technical-writing/ja-no-mixed-period */}
<summary>答えと解説</summary>
{/* textlint-enable ja-technical-writing/ja-no-mixed-period */}

ページのCSSに、`& > [data-surface="inverse"]` で `color-scheme: dark` を指定し、背景色と文字色をトークンで指定し直すルールを足します。同じ面が続く境目の組にも、`inverse` の組を足します。紺のブロックの中の見出し、ボタン、リンクの色は、21-2の紺の帯と同じく、トークンが配色に合わせて切り替えるので、部品は直しません（`redeclare-colors-with-color-scheme`）。

</details>

## この節で使ったルール

- [`no-external-layout-on-root`](/components/boundaries/#rule-no-external-layout-on-root)：コンポーネントのルートに、外側の余白や配置の指定を書きません。
- [`parent-owns-child-placement`](/components/boundaries/#rule-parent-owns-child-placement)：子のコンポーネントの配置と外側の余白は、親が決めます。
- [`page-scope-root`](/notation/scope-and-nesting/#rule-page-scope-root)：ページ固有のスタイルは、`scoped page-<スラッグ>` の `@scope` の中に書きます。
- [`section-padding-block`](/layout-practice/spacing/#rule-section-padding-block)：縦に並べるセクションの上下の余白は、各セクションの `padding-block` で作ります。
- [`gutter-columns-for-content-width`](/layout-practice/spacing/#rule-gutter-columns-for-content-width)：ページのコンテンツの最大幅と画面の端の余白は、グリッドの左右の余白の列で決めます。
- [`composition-configurable-via-props`](/components/compositions-and-utilities/#rule-composition-configurable-via-props)：コンポジションの値は、公開プロパティで渡します。
