## 完成したカードと一覧を確かめる

最初は内容です。最悪の内容を入れたテストページ（カンプの2倍の見出し、画像のない記事、5つのタグ、長い英単語 `Internationalization`）を、1280pxで見ます。画像のない記事は、関連記事とサイドバーのどちらに置いても画像の列がなくなり、文字だけの1列になります。タグが5つのカードではタグが複数行に折り返し、長い見出しのカードはほかより高くなります。どのカードの子もカードからはみ出さず、幅を320pxにしたときも横スクロールは出ません（「[21-5 内容の変化に耐える](/exercise/content-changes/)」）。

次は幅です。完成形の記事ページを1280pxで見ると2カラムになり、関連記事は3列（1枚307px）の特集の形、人気記事は240pxの小さな形（画像が左、抜粋なし）です。1024pxでも2カラムのままで、関連記事が2列になります。768px以下では1カラムになり、人気記事は約360pxの2列で、画像が上の形に切り替わります。320pxでは、どのカードも288pxの1列です。関連記事の欄も1列になりますが、カードは画像が上の形のままなので、特集の背景は付いたままです。

拡大では、1280pxの画面でズームを200%にすると、ページから見た幅は640pxで、768px以下と同じ1カラムの形になります（2026年10月、Chromeで幅640pxの表示として確認）。文字サイズの設定を200%に上げたときは、カードの閾値、列の最小幅、サイドバーの幅をどれもremで書いているので、切り替わる幅も文字と同じ割合で大きくなります。文字が大きくなった分だけ、狭い幅のときの形へ早く切り替わり、1280pxの画面でも1カラムの形になります（「[13-2 ブレイクポイントの決め方](/responsive/breakpoints/)」。2026年10月、Chromeでルートの文字サイズを32pxにして確認）。

キーボードでは、`Tab` キーで移動すると、各カードの中でタグのリンク、見出しのリンクの順にフォーカスが移ります。見出しのリンクにフォーカスすると、カードの外周に3pxの輪郭が出て、見出しに下線が付きます（「[21-6 カード全体を押せるようにする](/exercise/clickable-card/)」）。

表示の設定では、まず動きを減らす設定を見ます。記事カードには、ホバーとフォーカスの変化も含めて、トランジションやアニメーションがないので、この設定で変わるものはありません。ホバーとフォーカスの状態は、色ではなく下線と輪郭で示しているので、グレースケールでも見分けられます。

強制カラーモードでは、`background-color` がシステムカラーに置き換わるので（「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/)」）、特集の淡い背景もほかのカードと同じ背景になり、見分けが付かなくなります。それでも、失われる情報はありません。「[21-1 要件と完成形](/exercise/requirements/#3つの置き場所)」の要件に書いたとおり、特集は関連記事の欄に付ける装飾で、記事の重要度は表さないからです。カードの範囲も示したいなら、特集の `._layout` に透明な色の `border` を持たせる書き方があります（「[15-5 強制カラーモードとコントラスト](/color-media/forced-colors/#枠線は消さずに透明にする)」）。

この範囲では、記事カードと一覧のCSSに直す箇所はありませんでした。強制カラーモードで特集のカードの範囲を背景色以外でも示すかどうかは、判断として残ります。設定を再現した表示で確かめていない3つの設定は、公開前に、その設定を有効にしたブラウザで確かめる対象として残します。

## 自分でレビューする

次の見出しからの解説を読む前に、このプルリクエストを自分でレビューしてください。デモのHTMLとCSSのタブでコードを読み、幅のボタンで表示を、ポインターと `Tab` キーで操作を確かめます。読み進める順番は、19-2の段階（規約から始まり、コメントで終わる9つの段階）に従います（「[19-2 レビューの進め方](/operations/review/#確認する順番)」）。

見つけた問題ごとに、根拠、修正案、ラベルを書きます。根拠には、どのルールや仕様に反しているかと、どの表示や操作で問題が現れるかを書きます。ラベルは、直さなければならない指摘の `MUST`、好みが入りうる提案の `IMO`、質問の `Q` のどれかです（「[19-2 レビューの進め方](/operations/review/#指摘の深刻度ラベル)」）。

手元で試すときは、配布版の[index.html](/exercise-files/review/index.html)を開きます。同じディレクトリの `notice-card.css`、`notice-list.css`、`page-top.css`、`compositions.css` が、プルリクエストのCSSです。書き終えたら、次の見出しからの解説と見比べ、見落とした誤りと、ラベルの付け方の違いを確かめます。

## 表示と操作に現れる症状

幅のボタンで320pxを選ぶと、カードとカードの間が、一覧の `gap` の16pxにカードの `margin-block-end` の24pxが足されて、40px空きます。タグの色は、一覧から赤を渡しているはずなのに、デフォルトの青のままです。見出しは、ページのCSS（`page-top.css`）の `!important` で15pxに固定されています。画像が明るくなるのはマウスでホバーしたときだけで、キーボードでフォーカスしても変わりません。

3件目のカードの5つのタグは、折り返さずに縮み、「重/要」「Infrastruc/ture」のように単語の途中で改行されます。はみ出す代わりに縮んで現れるのは、デモの土台のCSSがすべての要素の `min-inline-size` を0にしているからです。

解説も、19-2の順番で進めます。5つの誤りは、規約、上書き、内容の変化、境界の段階で見つかります。残りの1つは、カードのCSSだけでは見つからず、値を渡すテンプレートとの照合か、画面を起点にした調査が要ります。

## コンテナとホバーの書き方

規約の段階では、2つの誤りが見つかります。1つ目（誤り2）は、カードのコンテナです。ルートに `container-type: inline-size` を単体で書き、`._body` で、名前のない `@container (width >= 300px)` を問い合わせています。名前のないクエリはいちばん近い祖先のコンテナを参照するので、コンテナが入れ子になると、参照先がコードから読み取れなくなります。条件は書字方向に依存しない `inline-size` で、閾値は文字サイズの設定に追従するremの式で書きます（「[13-3 コンテナサイズクエリ](/responsive/container-size-queries/)」）。

```css title="🙆‍♂ Recommended: ルートを名前付きのコンテナにし、フラグを宣言する要素だけがクエリを書く"
@scope (.scoped.notice-card) to (.scoped) {
  :scope {
    container: --scoped / inline-size;
    display: block grid;
    gap: 12px;
  }

  ._body {
    --_density: --compact;

    display: block grid;
    gap: 8px;

    @container --scoped (inline-size >= calc(300 / 16 * 1rem)) {
      --_density: --spacious;

      gap: 12px;
    }
  }
}
```

直した形では、`._body` がフラグ `--_density` を宣言し、コンテナサイズクエリはこのルールにだけ書きます（「[10-6 スタイルクエリで状態を伝える](/components/style-queries/)」）。300pxという値の根拠は、コードから読み取れないので、`Q` のラベルで尋ねます。列の最小幅などから決めた値なら、その条件を式に書いてもらいます（「[13-2 ブレイクポイントの決め方](/responsive/breakpoints/)」）。

2つ目（誤り3）は、ホバーです。カードのスコープの外に `.notice-card:hover img { filter: brightness(1.08); }` と書いています。カードのどこにポインターを置いても画像が明るくなりますが、押せるのは見出しのリンクだけです。ホバーを `@media (any-hover)` の中に書いておらず、キーボードでフォーカスしたときの変化もありません（「[17-1 ホバーとフォーカスを表す](/interaction/states-and-focus/)」）。スコープの外にあるので、カードの中に別のコンポーネントを入れると、その中の画像まで選びます。

```css title="🙆‍♂ Recommended: 見出しのリンクのホバーとフォーカスで --_has-hocus を立て、画像はフラグで切り替える"
@scope (.scoped.notice-card) to (.scoped) {
  :scope {
    --_has-hocus: --false;

    &:has(h3 a:any-link:hover) {
      @media (any-hover) {
        --_has-hocus: --true;
      }
    }

    &:has(h3 a:focus-visible) {
      --_has-hocus: --true;
    }
  }

  img {
    /* ... */

    @container style(--_has-hocus: --true) {
      filter: brightness(1.08);
    }
  }
}
```

状態の判定はルートの1か所にまとまり、画像はフラグを読むだけです。記事カードで、カード全体を押せるようにしたときと同じ形です（「[21-6 カード全体を押せるようにする](/exercise/clickable-card/)」）。

## ページのCSSからの上書き

不要な記述や副作用のある上書きの段階では、トップページのCSS（`page-top.css`）が目に留まります（誤り4）。`pages` のレイヤーに、`.page-top .notice-card h3` を選ぶルールがあります。ページがお知らせのカードの内部を選び、見出しの大きさを `font-size: calc(15 / 16 * 1rem) !important` で上書きしています。カードの見出しを直す人は、カードのファイルを読んでも、15pxになる理由を見つけられません（「[10-2 コンポーネントの境界を守る](/components/boundaries/)」）。

`!important` が要ったのは、本書のレイヤーの順番では `pages` が `components` より前にあり、ページの宣言は詳細度に関わらずカードの宣言に負けるからです。重要な宣言ではレイヤーの順位が逆になるので勝てますが、ページからカードの内部を変えているという問題はそのまま残ります（「[4-3 カスケードレイヤーで順位を決める](/cascade/layers/)」）。

見出しの大きさは、カードのCSSで決めます。狭い列でtitleの役割（20px）では大きすぎることが理由なら、カードが置かれた幅で文字の役割を切り替えます。誤り2を直したときに `._body` で宣言した `--_density` を、見出しが読みます。狭い列ではsubtitle（16px）、広い列ではtitleにします（「[14-5 文字の役割と色](/typography/text-roles/)」）。

```css title="🙆‍♂ Recommended: 見出しの大きさはカードが幅のフラグで決め、ページからは選ばない"
@scope (.scoped.notice-card) to (.scoped) {
  h3 {
    font-size: calc(var(--text--subtitle--font-size) / 16 * 1rem);
    line-height: var(--text--subtitle--leading);

    @container style(--_density: --spacious) {
      font-size: calc(var(--text--title--font-size) / 16 * 1rem);
      line-height: var(--text--title--leading);
    }
  }
}
```

ただし、15pxにした理由がほかにあるかは、コードからは分かりません。この指摘には、理由を尋ねる質問を添えます（後述の指摘の見本）。

## タグの並びと内容の変化

内容の変化の段階では、タグの並び（誤り6）を見ます。`._tags` は `display: block flex` と `gap` だけで、`flex-wrap` がありません。タグの数は記事ごとに変わるので、入りきらなくなったときに折り返す指定が要ります（「[11-3 サイズと内容の変化に耐える](/layout-practice/defensive/)」）。

直すときは、`flex-wrap: wrap` を足すより、記事カードと同じ `cluster` コンポジションを使います。タグの `ul` を `<ul class="_tags | cluster">` にし、カードは間隔だけを公開プロパティで渡します（「[12-2 cluster：子を横に並べ、入りきらなければ折り返す](/compositions/cluster/)」）。配布版の `review` の `compositions.css` には、記事カードで使っている `cluster` も入っています。`display: flex` の1値の構文はStylelintでも見つかるので、レビューの前にlintを通してもらいます。

```css title="🙆‍♂ Recommended: タグの並びは cluster に任せ、カードは間隔だけを渡す"
@scope (.scoped.notice-card) to (.scoped) {
  ._tags {
    --cluster--row-gap: 4px;
    --cluster--column-gap: 12px;

    font-size: calc(var(--text--caption--font-size) / 16 * 1rem);
    line-height: var(--text--caption--leading);
  }
}
```

この誤りは、表示が崩れているので `MUST` です。ただし、本書の規約を採用していないプロジェクトなら、`MUST` で求めるのは折り返すことまでで、`cluster` に替えるのは `IMO` の提案です。

## カードのルートの外側の余白

コンポーネントの境界の段階では、カードのルートの `margin-block-end: 24px`（誤り1）を見ます。カードとカードの間隔は一覧の `gap` が持っているので、ルートの余白がそこに足され、320pxでは40px空いています。カードを別の場所に置けば、置く側がこの余白を打ち消すことになります（「[10-2 コンポーネントの境界を守る](/components/boundaries/)」）。

ルートの余白は消します。24pxの間隔がデザインで必要なら、一覧のテンプレートで `ul` の `style` 属性の `--grid--gap` を24pxにします。記事カードでは、カードを作った最初の節から、ルートに幅も外側の余白も書いていません（「[21-2 カードを作る](/exercise/card/)」）。

## 色が変わらない原因をたどる

最後の誤り（誤り5）は、カードのCSS（`notice-card.css`）だけでは見つかりません。カードのCSSは `:scope` で `--notice-card--accent` を正しく受けていて、誤りは一覧のテンプレートの側にあるからです。見つけるには、値を渡すテンプレートとカードの名前を照らし合わせるか、表示を起点に原因をたどる必要があります。ここでは表示から始めます。画面で、赤を渡したはずのタグが青いことに気付いたら、「[19-4 表示の崩れを開発者ツールで調べる](/operations/devtools/#宣言が効かない)」の「宣言が効かない」の手順で原因をたどります。

開発者ツールでタグのリンクを選ぶと、`color: var(--_accent)` には取り消し線がなく、宣言は勝っています。宣言が勝っていても表示が思った色と違うので、参照しているカスタムプロパティの値を確かめます。タグの色はデフォルトの青なので、`--_accent` には、`var()` のフォールバックに書いたトークンの色が使われています。つまり、`--notice-card--accent` がカードまで届いていません。そこで、値を渡しているはずの祖先の `li` をElementsパネルで選び、`style` 属性を読むと、宣言されていたのは綴りの違う `--notice-card--acent` でした。

テンプレートの名前を `--notice-card--accent` に直します。あわせて、カードのファイルの先頭に、公開プロパティを `@prop` で並べた説明ブロックを足してもらいます。記事カードでも、公開プロパティを足したときに同じ一覧を書きました（「[21-7 特集の見た目を足す](/exercise/featured/)」）。

```css title="🙆‍♂ Recommended: 公開プロパティを説明ブロックの @prop に並べ、使う側が名前を照らし合わせられるようにする"
/**
 * お知らせのカード。
 *
 * @prop {color} --notice-card--accent [var(--foreground--accent)] - タグの色
 */
@scope (.scoped.notice-card) to (.scoped) {
  :scope {
    --_accent: var(--notice-card--accent, var(--foreground--accent));

    /* ... */
  }

  ._tags {
    /* ... */
  }

  ._tag-link {
    color: var(--_accent);
  }
}
```

説明ブロックに公開プロパティの名前が並んでいれば、レビュアーはテンプレートの差分をその名前と照らし合わせられます。そうすれば、綴りの誤りは、画面で確かめる前のコードレビューの段階でも見つかります。

## 指摘の見本

指摘には、ラベル、理由、解決策をセットで書き、当てはまるルールのIDを添えます（「[19-2 レビューの進め方](/operations/review/#レビューの指摘に書く内容)」）。誤り4と誤り5の指摘を、見本として示します。

```md title="🙆‍♂ Recommended: 境界を越えた上書きに、理由と解決策を書き、意図を尋ねる"
[MUST] トップページのCSSの `.page-top .notice-card h3 { font-size: … !important; }` は削除してください。ページがお知らせのカードの内部を選んでいるので、カードの見出しを直す人は、カードのファイルだけでは15pxになる理由を見つけられません（`no-other-component-internals`）。`!important` は、`pages` のレイヤーで負けていた宣言の順位を逆にしているだけです（`no-important-for-specificity`）。見出しの大きさはカードのCSSで決め、狭い列で大きすぎることが理由なら、`--_density` が `--spacious` のときだけtitleの役割（20px）にしてください（`density-via-style-query`）。

[Q] 15pxにしたのは、どの幅で見出しが大きすぎたからでしょうか。トップページに置いたときだけ小さくしたい事情があれば、カードの公開プロパティにするかを相談させてください。
```

```md title="🙆‍♂ Recommended: 画面で見つけた誤りに、たどった手順と解決策を書く"
[MUST] お知らせの一覧のテンプレートで `li` に渡している `--notice-card--acent` は、`--notice-card--accent` の綴りの誤りです。カードはこの名前を読まないので、タグの色が赤ではなく、デフォルトの青のままです。開発者ツールでタグのリンクを選ぶと、`--_accent` がフォールバックの `--foreground--accent` になっていました。テンプレートの名前を直してください。あわせて、カードのCSSの先頭に `@prop` の説明ブロックを足し、公開プロパティの名前を照らし合わせられるようにしてください（`prop-tag-for-public-properties`）。
```

1つ目は、`MUST` の指摘に `Q` を添えています。15pxにした理由によって、カードの中で幅から切り替えるか、公開プロパティにするかが変わるからです。2つ目は、原因をたどった手順を書いているので、レビュイーが同じ手順で確かめられます。

## 直した箇所と直さずに済んだ箇所

記事カードと一覧は、確かめた範囲では直さずに済みました。

プルリクエストで直すのは、お知らせのカードの `notice-card.css`、トップページの `page-top.css`（上書きの削除）、一覧のテンプレート（公開プロパティの名前と `cluster` のクラス）です。一覧の `notice-list.css` と `grid` コンポジションは直さずに済みます。6つの誤りは、記事カードが節ごとに守ってきた規約と1つずつ対応します。誤り1から3は、外側の余白を持たないこと、名前付きのコンテナとフラグ、`--_has-hocus` で伝えるホバーとフォーカスに当たります。誤り4から6は、置く側から内部を選ばないこと、`@prop` の一覧、`cluster` で並べるタグに当たります。

これで演習は終わりです。章の概要の「[この章で判断できるようになること](/exercise/#この章で判断できるようになること)」に戻り、要件の変更を受け持つのがカード、一覧、置く側のどれかを見分けられるようになったかを振り返ってください。この節のレビューで見た項目は、付録D「[レビューのチェックリスト](/appendix/checklist/)」に、19-2の順番で並んでいます。

## 判断の問い

### 問い1

誤り5の綴りの誤り（`--notice-card--acent`）は、Stylelintで見つけられますか。見つけられないなら、何で防ぎますか。

<details>
{/* textlint-disable ja-technical-writing/ja-no-mixed-period */}
<summary>答えと解説</summary>
{/* textlint-enable ja-technical-writing/ja-no-mixed-period */}

見つけられません。どのカスタムプロパティを宣言しても構文としては正しく、しかもこの宣言はCSSのファイルではなく、テンプレートの `style` 属性にあるからです。防ぐのは、レビューと、画面での確認です。カードのファイルの先頭に `@prop` で公開プロパティを並べておけば、レビュアーはテンプレートの名前と照らし合わせられます（「[9-9 コメントの書き方](/notation/comments/)」）。

</details>

### 問い2

誤り4の指摘に、トップページの担当者から「お知らせの見出しは、どこに置いても15pxにしたい」と返事が来ました。どこに書きますか。

<details>
{/* textlint-disable ja-technical-writing/ja-no-mixed-period */}
<summary>答えと解説</summary>
{/* textlint-enable ja-technical-writing/ja-no-mixed-period */}

カードのCSSの `h3` に書きます。どこに置いても同じ大きさなら、それはカード自身の文字の階層の決定で、置き場所の判断ではないからです。幅のフラグで切り替える必要もなくなります。ただし、15pxに当たる文字の役割はないので、役割を足すか、近いsubtitle（16px）で足りるかを担当者と決めます（「[14-5 文字の役割と色](/typography/text-roles/)」）。トップページに置いたときだけ15pxにしたいという返事だったなら、置き場所で決まる見た目なので、置く側からフラグか公開プロパティで渡します（「[10-7 置き場所と子の状態を伝える](/components/placement-and-child-states/)」）。

</details>

### 問い3

章の概要では、規約の良し悪しを、変更を受け持つ場所を予測できるか、影響範囲を確かめられるか、条件分岐が複雑になっていないかの3つで確かめると述べました。記事カードに重ねた21-2から21-7の変更を、この3つで振り返ってください。21-3から21-7の変更は、それぞれカード、一覧、置く側のどこが受け持ちましたか。21-7で特集の宣言を足したとき、新着とサイドバーのカードが変わらないことは、何を読めば確かめられますか。完成形のカードのCSSで、表示を切り替える条件はどこに集まっていますか。

<details>
{/* textlint-disable ja-technical-writing/ja-no-mixed-period */}
<summary>答えと解説</summary>
{/* textlint-enable ja-technical-writing/ja-no-mixed-period */}

受け持つ場所は、21-1で分けた線引きから予測できます。記事が7件に増えて列と端数が変わる21-3は、一覧と `grid` コンポジションが受け持ち、カードは直しませんでした。置かれた幅で形を変える21-4、内容が変わる21-5、押せる範囲を広げる21-6は、カードの中の配置と状態の話なので、カードが受け持ちます。21-7は、特集として置いたことと色の値を置く側が渡し、それを背景とタグの色にどう使うかをカードが決めました。

影響範囲は、特集のフラグの名前で確かめられます。カードは `--article-card--featured` を、渡されなければ `--false` になる内部プロパティで受け、特集の宣言はすべて `--_featured` が `--true` のときのスタイルクエリの中にあります。フラグを渡しているのは関連記事の一覧のHTMLだけなので、テンプレートで `--article-card--featured` を検索すれば、特集の見た目が出る場所を数えられます。新着やサイドバーの一覧を開いて目で確かめなくても、名前の検索で範囲が決まります。

切り替えの条件はフラグにまとまっていて、コンテナサイズクエリを書いたのは、`--_density` を宣言する `._layout` の1つのルールだけです。見出しの大きさや抜粋の表示はこのフラグをスタイルクエリで読み、ホバーとフォーカスは `--_has-hocus` に、特集は `--_featured` に集まっています。カテゴリーごとの色は値のまま公開プロパティで受けるので、カテゴリーが増えてもカードに分岐は増えません。置き場所ごとに `.related-list .article-card` のようなセレクタで書き分けていたら、置き場所と色の組み合わせの数だけルールが増えていたはずです（「[10-7 置き場所と子の状態を伝える](/components/placement-and-child-states/)」）。

</details>

## この節で使ったルール

- [`verify-worst-case-content`](/operations/verification/#rule-verify-worst-case-content)：実装後は、長い見出し、折り返せない文字列、読み込めない画像、0件・1件・多数の項目を入れたテストページで表示を確かめます。
- [`verify-text-resize-200`](/operations/verification/#rule-verify-text-resize-200)：ブラウザのズームと文字サイズの設定をそれぞれ200%にしても、内容が欠けず、操作できることを確かめます。
- [`verify-keyboard-and-display-settings`](/operations/verification/#rule-verify-keyboard-and-display-settings)：キーボードだけで操作し、強制カラーモード、動きを減らす設定、グレースケールの表示を再現して確かめます。
- [`review-check-order`](/operations/review/#rule-review-check-order)：レビューは、規約、トークン、ブラウザ対応、不要な記述、グローバルのCSS、内容の変化への耐性、コンポーネントの境界、レスポンシブ、コメントの順に確認します。
- [`review-reason-and-solution`](/operations/review/#rule-review-reason-and-solution)：レビューの指摘には、理由と解決策を必ずセットで書きます。
- [`review-severity-labels`](/operations/review/#rule-review-severity-labels)：レビューの指摘には `MUST`、`IMO`、`Q` のラベルを付けて、深刻度を区別します。
- [`devtools-find-winning-declaration`](/operations/devtools/#rule-devtools-find-winning-declaration)：宣言が効かないときは、詳細度を上げたり `!important` を付けたりする前に、開発者ツールで勝っている宣言と、差が付いた段階を確かめます。
- [`container-shorthand`](/responsive/container-size-queries/#rule-container-shorthand)：コンテナは `container` ショートハンドで、名前と種類をまとめて指定します。
- [`container-name-required`](/responsive/container-size-queries/#rule-container-name-required)：コンポーネントのルートをコンテナにするときは `container: --scoped / inline-size` と書き、`@container --scoped (…)` で問い合わせます。
- [`container-query-inline-size`](/responsive/container-size-queries/#rule-container-query-inline-size)：コンテナサイズクエリの条件では、`width` ではなく `inline-size` を使います。
- [`breakpoint-in-rem`](/responsive/breakpoints/#rule-breakpoint-in-rem)：ブレイクポイントはremで指定し、ピクセル値からの変換を式で書きます。
- [`threshold-as-formula`](/responsive/breakpoints/#rule-threshold-as-formula)：クエリの閾値は、レイアウトが成り立つ条件を `calc()` の式で書きます。
- [`density-via-style-query`](/components/style-queries/#rule-density-via-style-query)：コンテナサイズクエリは、フラグを宣言する1つの要素のルールだけに書き、ほかの子孫はスタイルクエリで切り替えます。
- [`hover-operable-in-any-hover`](/interaction/states-and-focus/#rule-hover-operable-in-any-hover)：ホバーのスタイルは操作できる状態に限定し、`@media (any-hover)` の中に書きます。
- [`hover-with-focus-visible`](/interaction/states-and-focus/#rule-hover-with-focus-visible)：ホバーで変える見た目は、`:focus-visible` にも同じように指定します。
- [`hocus-via-style-query`](/components/style-queries/#rule-hocus-via-style-query)：ホバーとフォーカスで子要素の見た目を変えるときは、フラグを立てて `@container style()` で切り替えます。子孫の状態をほかの子孫に伝えるときは、`&:has()` で `--_has-hocus` を立てます。
- [`no-other-component-internals`](/components/boundaries/#rule-no-other-component-internals)：ほかのコンポーネントのルートや内部の要素を、セレクタで選んで見た目を上書きしません。
- [`no-important-for-specificity`](/cascade/cascade-basics/#rule-no-important-for-specificity)：詳細度や読み込み順の競争に勝つ目的で `!important` を使いません。
- [`flex-wrap-for-variable-items`](/layout-practice/defensive/#rule-flex-wrap-for-variable-items)：要素の数が変わる可能性のあるFlexboxには、`flex-wrap: wrap` を指定します。
- [`compositions-for-layout-patterns`](/components/compositions-and-utilities/#rule-compositions-for-layout-patterns)：並べて折り返すといった、コンポーネントに依存しない配置は、コンポジションで書きます。
- [`no-external-layout-on-root`](/components/boundaries/#rule-no-external-layout-on-root)：コンポーネントのルートに、外側の余白や配置の指定を書きません。
- [`prop-tag-for-public-properties`](/notation/comments/#rule-prop-tag-for-public-properties)：公開プロパティを持つファイルでは、説明ブロックの `@prop` に、型、デフォルト値、説明を書きます。
