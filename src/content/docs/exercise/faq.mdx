よくある質問のページに、質問と回答の一覧を作ります。質問は、ごく淡い1pxの枠線で囲んだ白い面に、紺の丸い「Q」の印と質問の文を並べ、右端に「+」を置きます。質問を押すと、その下に回答が開き、「+」が「−」に変わります。回答の前には、淡いティールの丸い「A」の印を付けます。

開けるのは1つだけで、別の質問を開くと、開いていた質問は閉じます。開閉には高さが伸び縮みする動きを付け、動きを減らす設定では付けません。

一覧の上には、「すべて」と3つのカテゴリーの絞り込みのボタンを中央にそろえて置き、押したカテゴリーの質問だけを表示します。絞り込みは、ページを移動せず、同じページの中で切り替えます。ボタンの見た目は、21-4のカテゴリーの絞り込みと同じです（「[21-4 記事リストを作る](/exercise/article-list/)」）。

手元で進めるときは、開始版（[index.html](/exercise-files/faq/start/index.html)）から始め、中間版（[index.html](/exercise-files/faq/middle/index.html)）と見比べます。後半の要件の変更は、中間版から始めて、完成版（[index.html](/exercise-files/faq/finished/index.html)）と見比べます。サンプル一式のZIPでは、それぞれ `exercise/faq/start/`、`exercise/faq/middle/`、`exercise/faq/finished/` にあります。絞り込みを動かす `script.js`（開始版の [script.js](/exercise-files/faq/start/script.js)）も、同じディレクトリにあります。準備は「[21-1 題材と準備](/exercise/setup/#手元で進める準備)」で説明しています。

## 予想する

本文を読む前に、開閉を何で作るかを考えてみてください。`div` とクラスの付け外しで作るのか、HTMLの開閉の機能を使うのか。1つだけを開く動作を、JavaScriptを書かずに作れるかも予想します。

絞り込みのボタンについても考えます。21-4の絞り込みと見た目は同じですが、21-4はほかのページへのリンクで、こちらは同じページの中で表示を切り替えるボタンです。同じコンポーネントにするか、別にするかを決めてから読み進めます。

## 質問と回答を details で開閉する

質問と回答は、`<details>` と `<summary>` で作ります。開閉はブラウザが受け持つので、キーボードでの操作や、開閉の状態の読み上げも、スクリプトなしで動きます。複数の `<details>` に同じ `name` 属性を付けると、1つを開いたときにほかが閉じます（「[17-6 開閉するUI](/interaction/disclosure/)」）。

```html title="🙆‍♂ Recommended: 同じ name 属性の details で、1つだけを開くアコーディオンにする" from="exercise/faq-1"
<details name="faq" data-category="price" open>
  <summary>費用はどれくらいかかりますか？</summary>
  <div class="_answer">
    <p>ページ数や機能によって変わりますが、コーポレートサイトは100万円からが目安です。…</p>
  </div>
</details>
```

「Q」と「A」の印、「+」と「−」の印は、`::before` と `::after` の生成コンテンツで入れ、代替テキストを空にします。質問であることは `<summary>` が、開閉の状態はブラウザが伝えるので、印を読み上げても情報は増えません（「[5-8 生成コンテンツと装飾の擬似要素](/pseudo/generated-content/)」）。

```css title="🙆‍♂ Recommended: 印は生成コンテンツで入れ、開いた状態は [open] で選ぶ" from="exercise/faq-1"
@scope (.scoped.faq-accordion) to (.scoped) {
  summary {
    display: block grid;
    grid-template-columns: auto 1fr auto;
    gap: 16px;
    align-items: center;

    &::before {
      content: "Q" / "";
    }

    &::after {
      content: "+" / "";
    }

    &:is(details[open] > *)::after {
      content: "−" / "";
    }
  }

  ._answer {
    &::before {
      content: "A" / "";
    }
  }
}
```

開いた状態は、`[open]` 属性で選びます。`:open` 擬似クラスは、対応していないブラウザでセレクタリストごと無効になるからです（「[5-7 開閉と表示の状態を表す擬似クラス](/pseudo/open-states/)」）。`<summary>` を `display: block grid` にすると、ブラウザが付ける開閉の三角の印も消えます。開閉の動きは、`::details-content` の高さと不透明度を動かします。書き方は「[18-7 出現と退場](/motion/entry-and-exit/#details-の開閉を動かす)」と同じです。

## 絞り込みのボタンは状態を属性で表す

絞り込みは、同じページの中で表示を切り替える操作なので、`<a>` ではなく `<button>` で作ります。押されている状態は `aria-pressed` で表し、CSSはその属性を見て見た目を変えます。スクリプトが受け持つのは、`aria-pressed` と、各質問の `hidden` 属性を切り替えることだけです（「[17-3 状態を属性で表す](/interaction/state-attributes/)」）。

```html title="🙆‍♂ Recommended: 絞り込みのボタンは hidden にしておき、スクリプトの初期化が終わってから表示する" from="exercise/faq-1"
<div class="_filter | cluster" role="group" aria-label="カテゴリーで絞り込む" hidden>
  <button type="button" aria-pressed="true" data-category="all">すべて</button>
  <button type="button" aria-pressed="false" data-category="price">料金・お見積り</button>
  <!-- ... -->
</div>
```

ボタンの並びは、HTMLで `hidden` にしておき、スクリプトの初期化が終わってから表示します。スクリプトが動かない環境では、押しても何も起きないボタンが並ぶ代わりに、すべての質問がそのまま並びます。質問の側は最初から表示しておき、スクリプトが絞り込むときにだけ隠します。

見た目は21-4の `category-filter` と同じですが、同じコンポーネントにはしません。21-4はほかのページへ移るリンクの並びで、今いるページを `aria-current` で示します。こちらは、同じページの中の表示を切り替えるボタンで、押した状態を `aria-pressed` で示します。1つのコンポーネントにすると、要素の種類と状態の属性ごとに条件が分かれます。そこで、ボタンの並びは `faq-accordion` の中の要素として書き、見た目は同じトークンを参照してそろえます（`share-look-with-tokens`）。ボタンを隙間なく並べ、ピルの形を擬似要素に描いて内側に寄せる書き方と、状態ごとに内部プロパティの値を変える書き方も、21-4と同じです。強制カラーモードのときだけ押した項目に下線を引くことも、21-4にそろえています。

## 要件が変わる

回答をCMSで編集することになりました。回答には、段落のほかに、表、箇条書き、ほかのページへのリンクが入ります。表は1pxの枠線で囲み、リンクはティールの文字に下線を引き、箇条書きには黒丸を付けます。段落、表、箇条書きの間は12px空けます。

本文を読む前に、表、箇条書き、リンクの見た目を、どこに書くかを考えてみてください。回答は、編集者がCMSで入力するので、要素にクラスを付けられません。`faq-accordion` のCSSに `._answer table` のように書くのか、ほかの場所に書くのか、その書き方を、ほかのページのCMSの本文でも使えるかを予想してから読み進めます。

## 回答の中を rich-text に任せる

回答の中の要素を、`faq-accordion` のCSSから選んで見た目を付けると、`faq-accordion` がCMSの本文のすべての要素を知ることになります。

```css title="🙅‍♂ Not Recommended: アコーディオンのCSSから、回答の中の要素を選ぶ" issue="convention"
/* 🙅‍♂ Not Recommended */
@scope (.scoped.faq-accordion) to (.scoped) {
  ._answer {
    table {
      border-collapse: collapse;
    }

    ul {
      list-style-type: disc;
    }
  }
}
```

子要素のクラスの下にある要素を、タイプセレクタで選んでいます（`no-type-under-child-class`）。編集者が見出しや引用を入れれば、そのたびに `faq-accordion` へ書き足すことになります。同じCMSの本文をお知らせの記事にも置くなら、同じ指定を別のコンポーネントにも書きます。

本書では、編集者が自由にHTMLを入れる領域を、別のコンポーネントにします。名前は、見出し、段落、リストを含む編集領域を表す `rich-text` です（「[9-3 名前に使う語](/notation/terminology/)」）。回答の `._answer` の中に `rich-text` を置き、要素の見た目と要素の間の間隔は、`rich-text` が受け持ちます。

```html title="🙆‍♂ Recommended: 回答の中に、CMSの本文を受け持つ rich-text を置く" use="diff" from="exercise/faq-2"
<div class="_answer">
  <div class="scoped rich-text">
    <p>ページ数や機能によって変わります。サイトの種類ごとの目安は、次のとおりです。</p>
    <div role="region" aria-labelledby="faq-price-caption" tabindex="0">
      <table>
        <caption id="faq-price-caption">サイトの種類ごとの費用の目安</caption>
        …
      </table>
    </div>
    <p>詳しくは<a href="#pricing">料金プランのページ</a>をご覧ください。…</p>
  </div>
</div>
```

```css title="🙆‍♂ Recommended: 編集領域の中は、要素の種類で選び、間隔も自分で作る" use="diff" from="exercise/faq-2"
@scope (.scoped.rich-text) to (.scoped) {
  :scope {
    & > * + * {
      margin-block-start: 12px;
    }
  }

  ul,
  ol {
    padding-inline-start: revert;
    list-style-type: revert;
  }

  a {
    color: var(--foreground--accent);
    text-decoration-line: underline;
  }

  [role="region"] {
    overflow-x: auto;
  }

  table {
    border-collapse: collapse;
    font-variant-numeric: tabular-nums;
    overflow-wrap: normal;
  }
}
```

`rich-text` の中は、編集者が要素にクラスを付けられないので、要素の種類で選びます。要素の間の12pxも、`rich-text` 自身の `& > * + *` で作ります。`prose` のコンポジションは付けません。`prose` は子ごとに `style` 属性で間隔を渡す前提で、編集者はそれを書けないからです（`prose-not-on-cms-body`）。リストのマーカーと字下げは、kiso.cssが消したものを、値を書き直さずに `revert` でブラウザのデフォルトに戻します（「[8-1 壊さないリセット](/reset/kiso/)」）。

記事の本文のように、CMSのWYSIWYGが出力する長い本文には、「[19-5 CMSのWYSIWYG本文にスタイルを当てる](/operations/wysiwyg/)」の書き方を使います。`wysiwyg` クラスを起点とする `@scope` を使う形です。CMSの独自ブロックは `cms-` で始まるクラスを目印にして切り離し、ブロックの間の余白は `rlh` で決めます。よくある質問の回答は、段落、表、リストだけの短い文章で、独自ブロックを入れません。要素の間もカンプが12pxに決めているので、演習のほかの部品と同じ `scoped` のコンポーネントにしています。回答に独自ブロックを入れるようになったら、19-5の形に切り替えます。{/* 要確認: 著者の判断。FAQの回答を、19-5の wysiwyg ではなく scoped の rich-text で書く理由として、この説明でよいか */}

表は、`caption` で名前を付け、`role="region"` と `tabindex="0"` を付けた枠で包みます（「[11-15 表を組む](/layout-practice/tables/)」）。枠の名前は `aria-labelledby` で `caption` から借ります。この枠と `caption` は、CMSの表のブロックが出力する前提です。11-15の表は、列の幅を足した式で最小の幅を `min-inline-size` に決めていました。編集者が入れる表は、列の数と中身が決まっていないので、式を書けません。そこで、表の中だけ `overflow-wrap` を `normal` に戻し、kiso.cssの `anywhere` で `100万円から` の `100` が途中で折り返されないようにします。数字や英単語の幅が表の最小の幅になり、収まらない分は枠の中でスクロールします。{/* 要確認: 著者の判断。CMSの表で、式の min-inline-size の代わりに overflow-wrap: normal で最小の幅を決めてよいか */}

金額の列は、末尾ではなく先頭で揃えています。どの列が数値かを `rich-text` からは決められず、この列は `から` の付いた文として読ませるからです。数字の幅は `tabular-nums` でそろえます。

`faq-accordion` の `@scope` の範囲は、`to (.scoped)` で `rich-text` のルートの手前までです。`faq-accordion` のCSSが回答の中の要素に届かないので、編集者が回答に `<details>` やボタンを入れても、アコーディオンの見た目は混ざりません（「[9-4 @scopeとネストの使い分け](/notation/scope-and-nesting/)」）。

スクリプトにも、同じ境界を引いておきます。`root.querySelectorAll('details')` のように子孫をすべて選ぶと、編集者が回答に入れた `<details>` まで絞り込みの対象になり、カテゴリーの属性がないので、質問を残したまま回答の一部が隠れます。デモのスクリプトは、`:scope > ._items > details` のように `faq-accordion` の直下の要素だけを選ぶので、回答の中身が変わっても直さずに済みます。

## 振り返り

直したのは、回答のHTMLと、新しく作った `rich-text.css` です。`faq-accordion` のCSSとスクリプトは直していません。回答の中身が段落から表と箇条書きに変わっても、アコーディオンが受け持つのは、質問と回答の枠と印、開閉、絞り込みだけだからです。

予想と見比べたら、自分の変更を次の3つの点で見直します。

- 回答の中の見た目を、`faq-accordion` ではなく別のコンポーネントが受け持つと予想できたか。`._answer table` のように書いていたなら、編集者が別の要素を入れたときに直す場所を挙げられるか。
- `faq-accordion` のCSSが、回答の中に届かないことを、`@scope` の範囲から説明できるか。
- 絞り込みのボタンと21-4のリンクを、条件で分ける1つのコンポーネントにしていないか。

## 判断の問い

### 問い1

質問の文を、見出しで移動できるように `<summary><h3>…</h3></summary>` にしたい、と言われました。どう答えますか。

<details>
{/* textlint-disable ja-technical-writing/ja-no-mixed-period */}
<summary>答えと解説</summary>
{/* textlint-enable ja-technical-writing/ja-no-mixed-period */}

`<summary>` の中に見出しを入れません。`<summary>` の中では見出しの役割が失われ、見出しで移動する人は、結局その項目にたどり着けません（`no-heading-in-summary`）。見出しの構造が必要なら、`<details>` をやめ、見出しとボタンで開閉し、閉じたパネルを `hidden="until-found"` で隠すアコーディオンにします（「[17-6 開閉するUI](/interaction/disclosure/)」）。

</details>

### 問い2

絞り込みのスクリプトが読み込めなかった環境で、ページはどう表示されますか。

<details>
{/* textlint-disable ja-technical-writing/ja-no-mixed-period */}
<summary>答えと解説</summary>
{/* textlint-enable ja-technical-writing/ja-no-mixed-period */}

絞り込みのボタンは、HTMLの `hidden` のまま表示されず、すべての質問が並びます。アコーディオンの開閉は `<details>` が受け持つので、スクリプトがなくても動きます。初期のHTMLで質問を隠し、スクリプトで表示する作りにしていたら、スクリプトが動かない環境では、質問が1つも表示されなくなります（`hide-panels-after-init`）。

</details>

## この節で使ったルール

- [`native-disclosure-elements`](/interaction/disclosure/#rule-native-disclosure-elements)：開閉するUIは、`<details>` のようなHTMLの機能で作ります。
- [`details-name-for-exclusive`](/interaction/disclosure/#rule-details-name-for-exclusive)：1つだけを開くアコーディオンは、同じ `name` 属性を付けた `<details>` で作ります。
- [`details-content-for-panel`](/interaction/disclosure/#rule-details-content-for-panel)：`<details>` の開閉する部分の開閉の動きは、`::details-content` に指定します。
- [`open-attribute-for-details-dialog`](/pseudo/open-states/#rule-open-attribute-for-details-dialog)：`<details>` の開いた状態は、`[open]` 属性セレクタで選びます。
- [`empty-alt-for-decorative-content`](/pseudo/generated-content/#rule-empty-alt-for-decorative-content)：装飾の文字を生成コンテンツで入れるときは、代替テキストを空にします。
- [`state-by-pseudo-class-or-aria`](/interaction/state-attributes/#rule-state-by-pseudo-class-or-aria)：状態のスタイルは、状態クラスではなく、ARIA属性などで選びます。
- [`hide-panels-after-init`](/interaction/disclosure/#rule-hide-panels-after-init)：開閉するパネルは初期のHTMLでは隠さず、初期化が成功してからJavaScriptで隠します。
- [`share-look-with-tokens`](/components/what-is-a-component/#rule-share-look-with-tokens)：別のコンポーネントの間で見た目をそろえたいときは、同じトークンを参照します。
- [`no-type-under-child-class`](/components/boundaries/#rule-no-type-under-child-class)：子要素のクラスの下にある要素を、タイプセレクタで選びません。
- [`prose-not-on-cms-body`](/compositions/prose/#rule-prose-not-on-cms-body)：CMSで編集者が入力する本文エリアには、`prose` を付けません。
- [`table-caption-and-scope`](/layout-practice/tables/#rule-table-caption-and-scope)：表には `caption` で名前を付け、見出しのセルは `th` にして `scope` を付けます。
- [`table-min-size-with-scroller`](/layout-practice/tables/#rule-table-min-size-with-scroller)：表は置かれた場所の幅に合わせて縮めず、それより狭い場所では、表を包む要素の中で横にスクロールさせます。
- [`scope-with-donut`](/cascade/scope/#rule-scope-with-donut)：コンポーネントのスタイルは、`@scope (.scoped.<名前>) to (.scoped)` の中に書きます。
